# 099 工作台与日历不显示内部排序时刻和误导的剩余小时

## 背景

数据层和汇总文字已经修好，摊平出来的事件现在带一个有没有明确时刻的布尔标记，
还有一句具体时刻未说明的说明文字，没有时刻时事件的时间字段是空串。
但工作台的事项卡还是直接照着时间戳拼出时分，日历点开某一天也直接把事件的时间字段摆出来，
更麻烦的是剩余时间标签会算出剩多少小时这种精确到小时的话，可通知根本没写几点。

## 本机已核验事实

routeEvents.js 现在返回的每个事件多了两个字段。
hasExplicitTime 是布尔，true 表示原文给了明确时刻，false 表示只有日期。
timeNote 在 false 时是具体时刻未说明，true 时是空串。
time 字段在 false 时是空串，true 时还是原来的时分写法。
date 和 ts 两个字段一律不变，排序与日历格子照旧靠它们。

工作台事项卡在 ItemCard.js。
第20到32行 formatWhen 收一个时间戳，直接取小时和分钟拼成 月日 空格 时分。
第42到57行 remainingLabel 收时间戳和当前时间，小于一小时给不到一小时，
小于一天给剩 N 小时，其余给剩 N 天。
第87行 const remaining = safeTs !== null ? remainingLabel(safeTs, safeNow) : null;
第170到184行是何时那一行，safeTs 不为空就调 formatWhen 并把 remaining 做成小标签。
组件参数里 event 解构出 name ts location materials progress timeType noticeTitle。

日历页在 CalendarPage.js，第371行是选中某天后的详情里 <span className="truncate">{ev.time}</span>。
第173行用 formatRemaining(ev.ts, now).level 只取颜色等级给格子上的小圆点上色，不显示文字。
第18到21行有时间类型标签 deadline 是办理截止 start 是活动开始，这个是对的不要动。

待办与旧日历组件在 TodoList.js 和 CalendarView.js，都调用了 formatRemaining，
其中 TodoList 第41行 const remaining = formatRemaining(item.ts, now); 后面把文字显示出来，
CalendarView 第185行直接显示 ev.time。
这两个组件当前页面没有渲染，但为了各页一致也一起改。

剩余时间的纯函数在 app/lib/todo.js，第24行 export function formatRemaining(deadlineTs, nowTs)，
被 scripts/test-calendar.mjs 和 scripts/test-sample-notices.mjs 直接逐条断言文字与等级。
这些调用都只传两个参数，不许让它们的行为变掉。

app/lib/deadline.js 已导出 getRemainingDays 和 NO_TIME_NOTE 可以引用。

## 验收要点

第一，没有明确时刻的事项，工作台事项卡只显示日期和具体时刻未说明，
不显示任何时分，也不显示剩 N 小时或不到一小时这类话。
剩余时间要退到按自然日算的剩 N 天，或者干脆不显示，总之不许精确到小时。

第二，日历点开某天，没有明确时刻的事项要显示具体时刻未说明，不要留一个空行或者空白图标。
这两个死组件里也一样。

第三，formatRemaining 请加一个可选参数表示有没有明确时刻，
只有明确传 false 时才改口径，不传的时候必须跟现在一模一样，
测试脚本里那些两参数调用一个都不许坏，期望文字一个都不许改。

第四，有明确时刻的事项，工作台与日历里的时分显示和剩余小时标签跟现在完全一致，这是回归红线。

第五，时间类型标签办理截止和活动开始不要动，本轮不改它。

第六，只输出成对改动片段，逐文件分开写，不重写整个文件。
