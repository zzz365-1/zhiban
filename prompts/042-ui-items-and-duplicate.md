# 042 界面接上事项与去重，改了原文不许还能保存旧结果

## 背景

事项层和去重模块已经写好，界面还没接。同时同学试用抓到几个界面状态上的毛病：改了原文还能保存旧结果、新通知残留上一条的已保存、点已存通知不清批量残留、重复通知出现两条一模一样的。

## 几条硬约束

第一，改了原文就必须重新解析，保存按钮要禁用并说清原因。

第二，重复导入不能静默覆盖，标题相同正文不同要让用户自己选。

第三，状态文案不许一律显示未识别，要用事项模块里定义好的那几种中文。

第四，已保存的事项可以手动切换办理状态。

## Prompt

```
上一轮解析链路那个待确认的口径改好了，四十条用例全过，十分感谢。这一轮是界面上的活，我先把同学试用时抓到的毛病一条一条说给你听，这几条都挺丢人的。

第一条最危险。我把原文改了，界面上还显示着上一次的解析结果，保存按钮照样能点，一点就存进去了，存的是旧结果。我想改成这样，只要原文动过，就在结果区上面挂一条提示说内容已修改待重新解析，保存按钮变成不能点，鼠标放上去告诉人家请先重新解析。重新解析之后这条提示自己消失，保存按钮恢复。

第二条。我解析完一条新通知，界面上还挂着上一条的已保存三个字，我差点以为已经存好了。新通知就是新通知，不该有上一条的痕迹。

第三条。我点列表里一条已经存过的通知想看详情，可下面还堆着上次批量导入留下来的那一堆结果，看着特别乱。点已存通知的时候要把这些清干净，顺便那个模式切换的提示也一起清掉。

第四条。同一条通知我不小心粘了两次，界面上就出现两条一模一样的。上一轮你已经帮我把去重的模块写好了，这一轮请把它接到界面上。我的想法是点解析的时候先查一下。如果正文完全一样，就告诉人家这条已经存在了，给跳过和查看两个选择。如果标题一样但正文不一样，要说清楚这可能是改过的通知，给仍然导入和查看和取消三个选择，选了仍然导入就照常导入，绝不许闷声把旧的那条覆盖掉。

第五条。事项这一层上一轮也写好了，可界面上还看不到。请在结果区里把事项清单显示出来，每个事项要显示名称，时间类型是办理截止还是开始时间，日期，时间，地点，材料，面向对象，还有状态。状态那几个中文就用我们定好的那几种，原文未提及不适用待确认解析存疑，有值的时候不显示任何标签，不许一律显示未识别。每个事项还要能手动切换办理状态，待办理已办理无需办理，点一下就换。点依据要能跳到原文里选中那几个字。

还有几件小事想请你一起做。分类那一栏如果为空就显示未分类两个字，不要显示横杠。模型给出来的字段请加一个推断的小标签，让人知道这是猜的不是原文写的。日期如果是待确认的，请在旁边提示用户去补发布日期。摘要那一栏不要一律写未识别，那是以前的老毛病。

麻烦你只给改动片段，告诉我改哪几处改成什么，需要新建的两个组件请把完整内容给我。正则继续用字符类写法，另外界面里请不要动样式以外的老功能。
```

## 验证

真实浏览器里跑了十三项，全过。事项清单渲染出两个事项，名称和状态都对，改原文之后提示出现并且保存按钮变灰，重新解析提示消失，保存成功，再粘一次同样的原文弹出了重复提示。编译通过，二十三个离线命令里二十二个全绿，导出日历那条是本来就要带参数的命令，不是回归。

这一轮往返三回。第一回给的内容到一半断了。另外它有三处引用写错，迁移函数和查重函数的路径写错，生成事项时把解析结果当成原文传了进去，这三处我在落位时按事实表里写明的契约改掉了，并在下一轮回复里告诉了它，让后面的代码别再犯。
