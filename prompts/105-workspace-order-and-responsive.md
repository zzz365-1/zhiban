# 105 工作台信息顺序与宽窄屏整理

## 背景

演示时一进工作台，最上面先是一整块需要关注，然后才看到三个统计数字，
再往下依次是待确认事项，即将截止，待办理事项。
老师最想先看的还剩多少事要办，哪几件快到期了，主要待办是什么，全被挤到下面。

缺结束时间的提醒本轮另有一条链会合成一条，所以提醒区不会再占掉半屏。
本条只负责把顺序理顺，并顺手收拾宽屏留白和窄屏拥挤。

## 本机已核验事实

组件参数，常量，三组栅格类名，现场提醒条数，改动后的目标顺序，
都写在随附的事实材料里，请照着写片段。

空态判断，统计数字来源，事项卡点击打开，完成，勾材料，
这四类行为一律不许改，也不许去动别的模块。

## 验收要点

第一，页头之后先是统计卡，再是需要关注，再是即将截止，再是待办理事项，最后是待确认事项。

第二，统计卡三张徽标本身的先后顺序保持不变，三个数字的算法不动。

第三，空态页面与原来一致，ItemCard 的参数一个都不变。

第四，深蓝导航，浅色背景，白色卡片，主要按钮，大日历风格全部保留，
不换配色，不加动画，不加装饰，反馈文字保持简短。

第五，宽屏下不要出现大片空白，窄屏下卡片和按钮不挤成一团，
内容多时能滚动，文字不被截断。

第六，只输出成对改动片段，不重写整个文件，正则一律用字符类。

## Prompt

```
工作台现在一进来最上面先摆一整块需要关注，接着才是三个统计数字，再往下依次是待确认事项，即将截止，待办理事项。老师看演示的时候说最想先看的是还剩多少事要办，哪几件快到期了，主要待办是什么，结果这些全被挤到下面去了，得往下翻好久。我想把三个统计数字放到最上面，紧跟着放需要关注，然后放即将截止，再放主要待办，最后才是待确认事项。统计卡三张自己的先后顺序别动，数字怎么算也别动。空着的时候那个还没有通知的页面保持原样，事项卡点开看原文，标记完成，勾材料这些行为一个都不许改。深蓝导航，浅色背景，白色卡片，主要按钮和大日历的样子全部照旧，别换配色，别加动画和装饰，反馈文字也别写长。另外宽屏下页面两边空得有点多，窄屏下卡片和按钮容易挤在一起，内容多了要能滚着看，字别被截断。请按事实材料里写的顺序和类名来改，只把要改的地方写成改前改后成对片段发我，别把整个文件重贴一遍。
```
