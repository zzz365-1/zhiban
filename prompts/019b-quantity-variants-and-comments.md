# 019b 数量型变体补全 + 恢复被删注释

## 背景

019 交付后本机验收：断网通过（移走密钥仍可跑）、金丝雀按预期报红、脚本 import 生产模块且零网络依赖。
**但 66 条业务用例有 1 条失败**，且穷举注入暴露出比它自报的更严重的遗漏。

### 一、它自报的那条

它自报的那条是：`[29/66] FAIL - 过三天（2026-11-01）= 11月4日`，期望 2026年11月4日，实际 null。

根因：正则里虽然加了 `(过)?` 前缀，但结尾仍要求 `之内|以内|内|之后|以后|后` 后缀。
中文口语「过三天」本身就等于「三天后」，不带后缀，所以整串匹配失败。
**典型的半个修复——改了前缀忘了后缀。**

### 二、穷举注入发现的（它没报，也没覆盖）

本机用生产模块跑 30 种说法：

| 说法 | 结果 | 判断 |
|---|---|---|
| 三天后 / 三天内 / 三日之内 / 三日以后 / 三天之后 / 三日后 | 11月4日 | 正确 |
| 一周后 / 一周内 / 两周后 / 两个星期后 / 十周后 | 正确 | 正确 |
| 五十天后 / 九十九天后 | 12月21日 / 次年2月8日 | 大数正确 |
| 半月后 / 半个月后 / 三个工作日 / 隔天 | null | 宁缺勿滥，正确 |
| **过三天 / 过五天 / 过一周** | **null** | **遗漏** |
| **一个月后 / 两个月内 / 三个月后** | **null** | **遗漏，且比「过X天」更常见** |

「请于一个月内提交材料」「三个月后再来办理」在校园通知里非常常见。
如果这一轮只修它自报的「过X天」，下轮必然冒出「一个月后」——
正是 Dec-034 说的打地鼠。

## 验收要点

**零、先查注释有没有恢复（本轮第一条，不可省）**
跑 `git diff --numstat app/lib/aiExtract.js app/lib/extractNotice.js`，
累计删除行数应当明显回落。再逐条确认这几处注释回来了：
`mergeAIResult` 上方的同源策略说明、`cleanMaterialItem` 的六步编号、
`stripLeadingHints` 与两个 RE 常量的说明。
**只涨了字段相关的行、注释没回来，就打回。**

**一、断网可跑**
把 `.env.local` 改名后跑 `npm run test:relative`，必须照常出结果。

**二、本轮两类说法逐条必须有值**
- 口语无后缀：过三天、过五天、过一周、过两周
- 月级数量：一个月后、两个月内、三个月后、半年后

「半年后」要不要支持可以让它判断，但一旦支持就必须有对应用例。

**三、防误杀（双向验）**
原来已经对的不能变坏：三天后、三日之内、三日以后、一周后、两周后、
五十天后、跨年跨月闰年那批，必须仍然全对。

**四、宁缺勿滥不能被破**
半月后、半个月后、三个工作日、隔天、三月之后、下周之前，必须返回 null。
尤其「三月之后」有歧义（是三月这个月份还是三个月），宁可空着不许猜。

**五、金丝雀必须咬人**
保留现有坏实现注入，期待 FAIL 且不计入业务失败数。

**六、全量回归不可省**
`test:relative` `test:sample` `test:calendar` `test:manual` `test:extract`
外加材质类两条，全部要绿。

**七、本机先验**
交付后本助手会亲自跑穷举注入脚本，不只信它自带脚本的结果。
