# 012 批量粘贴多条通知

**立项**：2026-10-31 20:25
**定位**：最后一个功能。做完冻结代码，转技术文档与演示。

## 为什么做这个

批量粘贴是「从知到办」闭环的最后一块拼图：真实场景里辅导员一次发好几条通知，
一条一条贴太慢。也是演示时最有冲击力的一帧——一大段文字一次进去，全部入库。

## Prompt 正文

```
现在我想做最后一个功能。我们辅导员经常在群里一次发好几条通知，我一条一条粘贴太麻烦了，要贴好几遍。我想能一次把一大段文字贴进去，里面可能夹着三四条通知，程序自己把它们分开，一条一条解析，然后全部存下来。
但是有个地方我不太确定。这些通知到底应该怎么分开呢。有的时候两条通知中间空了一行，有的时候是连在一起的，就靠开头那句关于什么什么的通知来判断。我也不清楚哪种办法靠谱，你看着办，只要能分开就行。如果实在分不开，你就告诉我分不开，不要硬拆，拆错了比不分更麻烦。
还有三个地方我在意。
一个是解析的时候要让我看到进度，比如正在解析第二条，一共四条。不然我不知道它到底有没有在干活，看着没反应我还以为卡死了。
另一个是如果里面有一条没解析出来，你要明确告诉我是哪一条没成功，不能因为一条失败就把其他的都扔了，更不能假装全部成功了。我宁可少一条，也不要看到假的。
还有一个是如果我重复贴了同一条通知，最好能认出来，不要再存一遍，不然列表里会出现两条一模一样的，看着很乱。
粘贴进去以后，原来一次解析一条的那些都不要动，只是多一个能一次贴多条的地方就行。
老规矩。给我一个能在终端直接跑的自检脚本，要验证一大段文字确实被分成了正确条数，验证分不开的时候会报错而不是硬拆，还要验证重复的那条不会被存进去第二次。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
不要为了这些装新的库。
这一步就只做批量粘贴这一件事，相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 一次粘贴含多条通知的大段文字，全部拆分并逐条入库。
2. 解析过程有进度提示（第几条 / 共几条）。
3. 单条失败时明确指出是哪一条，其余不受影响，不静默假装全成。
4. 重复粘贴同一条能识别，不产生重复条目。
5. 无法拆分时报错，不硬拆。
6. 自检脚本 import 生产模块，含故意错的用例且被判定失败。
7. 没有新增依赖，原有的单条解析链路不受影响。
