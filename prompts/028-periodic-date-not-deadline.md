# 028 周期时间不得被当成具体日期（P0-2）

## 背景

审计查出：`每周三下午三点在行政楼会议室召开例会` 被抽成「周三」，
再经本地换算变成 2026年11月4日，界面显示一个确定日期。
但原文说的是每周都要开，不是那一天。静默错误，用户会照着去办事。

同类未建模：每两周、每逢单周、每月第一个周一、第12周。

## Prompt

```
我又发现一个问题想请你帮忙。

我拿一条通知去试，通知里写的是每周三下午三点在行政楼会议室召开例会，请全体成员准时参加。可是程序给我的截止日期是2026年11月4日。这个日期是我试的那天往后算出来的，可是原文根本没说11月4日要干什么，它说的是每个星期三都要开会。

我想想这个挺吓人的。因为界面上那个日期看起来跟别的日期一模一样，用户看到就会以为那是哪天要办事，实际上那个日子是凭空算出来的。而且每周这两个字和下午三点这个时间也都丢掉了。

我想请你改一下，凡是日期前面带着每这个字的，都不要当成截止日期，让它是空的就好。比如每周三，每两周，每个月，每逢周一，每隔一周，这些都不要给出日期。另外像第12周这种按教学周算的说法，也请不要当成日期。宁可空着让用户自己看，也不要给一个看起来像答案的假日期，这条是我们一开始就定下来的规矩。

有一点请特别注意，不要把正常的情况也弄没了。不带每字的那些说法还是要照旧能算，比如写周三开会，或者写下周三之前交表，或者写本周三下午，这些该算出日期的还是要算出来。也就是说只挡住前面带每字的，别的都不动。

还有几件事。第一个是测试要直接引用真正的那个模块，不要自己另外抄一份相似的来判断。第二个是要在正式那个测试文件里给这些带每字的说法补上用例，期望值都写成空，不少于八条，同时要有两条对照用例，写周三和下周三这种，期望值要能算出日期，用来证明没有误杀。第三个是正则一律用字符类写法，不要反斜杠加数字。第四个是那个存各种命令的文件里原有的命令一条都不能删，特别是那条查密钥的，改完请把所有命令都跑一遍把结果一起给我。

还有一件事想请你判断一下。改完之后，如果把新加的这个判断整个去掉，那八条期望为空的用例会不会报错。我要的是会报错，这样才说明这个判断是真的在起作用，而不是那些用例本来就是空的。这个你不用真的去跑，告诉我你的判断就行，我自己会在本机试。

回复的时候不要把这个文件整个重新输出一遍，只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。如果改动分散在好几处，就一处一处分开说清楚，每处都标明大概在第几行。

我不太懂这里面的写法，如果哪里说得不对，你按你的判断来就好。
```

## 验收要点（本机侧）

1. 每周三、每两周、每月、每逢周一、每隔一周、第12周 一律返回空
2. 防误杀：周三、下周三、本周三 仍能换算（test:relative 220 条不得变红）
3. 注入验证：去掉新增的周期判断，八条期望为空的用例必须报红
4. 全量 18 条离线命令 exit=0
5. 时间字段行为不变（下午三点该抽还是抽）
