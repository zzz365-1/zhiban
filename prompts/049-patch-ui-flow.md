# 049 补充通知要在界面上走完选通知看对比再确认

## 背景

抽取和落盘两个模块都跑通了，二十一条用例全过。可是现在还只是命令行里能跑，同学根本用不上。他要的是把补充通知粘进来之后，界面上直接告诉他这是不是补充通知，让他挑一条原通知，把改了什么列成对比给他看，他点确认才真的改，点取消就当没发生。

## 几条硬约束

第一，不许自动关联，这一版就让同学手动挑原通知。

第二，匹配不到具体事项时也必须让同学自己挑，不许程序替他决定。

第三，补充通知自己说不清的地方要先摆出来让同学确认，不许直接覆盖。

第四，点取消一律当作没发生，原记录一个字都不许变。

## Prompt

```
上一轮那三个函数我跑通了，二十一条用例全过，谢谢。可是现在还只是命令行里能跑，同学根本用不上。

同学的原话是，我把补充通知粘进来，界面上什么都没发生，原来的评审会还是八号，我根本不知道该拿它怎么办。

所以这一轮我想请你把这条流程接到界面上。先说一下同学要的完整走法。他把补充通知粘进输入框，点解析。界面先认出这是一条补充通知，弹出来让他挑一条原通知。挑完之后把改了什么列成对比给他看，一条一条写清改之前是什么，改之后是什么，依据是哪句话。他看清楚了点确认，才真的写回去。点取消就当什么都没发生。

有两条规矩请一定守住。第一，不许自动关联原通知，这一版就让同学自己挑，猜错了比不猜更糟。第二，补充通知自己说不清的地方，比如只写了另行通知没给新时间，要先在界面上摆出来让同学确认，不许直接覆盖。

请帮我做三件事。

第一件事，请新写一个组件，放在组件目录里，文件名叫 PatchLinkDialog 点 js。它负责让同学挑原通知。输入的属性我要这几个。已有通知的数组，抽出来的补充通知结果，还有三个回调分别是点了取消，点了下一步，还有当前需要同学自己挑事项的标记。

这个组件要显示这些。第一行写明这是一条补充通知。下面把已有通知一条一条列出来，每条显示标题和有几个事项，点一下就选中，选中的那条要有明显的高亮。最下面两个按钮，一个叫取消，一个叫下一步。

请特别注意这一处。当传进来的补充通知结果里的歧义不是空的时候，要在最上面单独用一块醒目的底色把每一条歧义写出来，并且写明请先确认这些再决定。这种情况下一步按钮不要禁用，因为同学看完歧义可以自己决定继续，但是歧义必须显眼。

还有一处。当那条原通知里的事项匹配不到具体某一个的时候，组件要允许同学自己在事项里挑，就是把那条通知下面的事项列成可勾选的一排，至少要选一个才能点下一步，一个都没选时下一步按钮请置灰并且不响应。

第二件事，请再新写一个组件，文件名叫 PatchReviewDialog 点 js。它负责展示对比并让同学确认。输入的属性我要这几个。对比结果，也就是上一轮那个 buildPatchReview 的返回值。补充通知的原文整段。提醒数组，也就是落盘那个函数返出来的 alerts。还有两个回调，点了确认更新和点了取消。

这个组件要显示这些。最上面写明这次要改的是哪条通知。中间是对比表，一行一个字段，每行四栏。第一栏是改的是哪一项，写日期或者时间或者地点或者材料。第二栏是变化前，写原通知里现在的值。第三栏是变化后，写补充通知给的新值。第四栏是补充通知里的依据原句，这栏要能点，点了要回调出去让界面去高亮原文里那句话。

行的类型请分三种显示。类型是变化的行用醒目的颜色，并且在行首写一个小牌子叫变化。类型是不变的行用浅色，行首写一个小牌子叫不变，这一栏很重要，同学要知道哪一项其实没动。类型是取消的行用另一种醒目的颜色，行首写小牌子叫取消。

下面再放两块。一块叫这些保持原样，把这次完全没动的事项名字列出来，因为同学最怕的是改了一条结果别的全没了。另一块叫需要你注意，把提醒数组里每一句列出来，一句一行。

最下面两个按钮，一个叫取消，一个叫确认更新。如果对比结果里一行变化都没有，确认更新这个按钮请置灰并且不响应，因为没什么可改的。

第三件事，请改主页面那个文件，把这条流程接起来。我先把现在的代码结构抄给你，免得你去翻。

主页面里现在有一个状态叫 notices，是已经保存的通知数组。有一个状态叫 analysis，是当前解析出来的结果。有一个状态叫 duplicate，装着重复导入的弹窗信息。有一个异步函数叫 handleParse，点解析按钮时走它，它现在做的事是对原文跑一遍解析，把结果塞进 analysis，同时补上事项。有一个函数叫 handleSave，负责把当前结果存成一条新通知。

我要你这样改。

在 handleParse 里，解析完之后请对原文跑一遍你上一轮写的抽取函数。如果结果里的 isPatch 是真，并且已有的通知数组不是空的，就不要走原来那套，请把抽出来的结果存进一个新的状态叫 patchDraft，同时把另一个新状态叫 patchStep 置成选通知，然后直接返回，不要再往 analysis 里塞，也不要去查重。如果 isPatch 是假，就照原来的走，一点都不要变。

然后加两个新状态。第一个叫 patchDraft，装抽出来的补充通知结果。第二个叫 patchStep，是一个字符串，值只能是选通知，看对比，还有关掉这三种，初始值是关掉。另外再加两个状态，一个叫 patchNoticeId，装同学挑中的原通知编号，一个叫 patchIndexes，装同学挑中的事项下标数组。

再写三个处理函数。

第一个叫 handlePatchPickNotice，参数是原通知编号和事项下标数组，把这两个存进状态，然后调用你上一轮写的 buildPatchReview 算出对比结果存进一个新状态叫 patchReview，再把 patchStep 置成看对比。

第二个叫 handlePatchConfirm，点确认更新时走它。它要做的是调用你上一轮写的 applyPatch，传进去那条原通知的事项数组，patchDraft，事项下标数组，还有当前时间。拿到返回之后，请把新的事项数组写回那条原通知，注意事项存了两处，最外层有一处，分析结果里面有一处，两处都要写成同一份，只写一处日历那边不动。然后把返回的 record 追加到这条原通知的历史数组里，键名请叫 history，如果原来没有就新建一个空数组再追加。最后把 patchStep 置成关掉，patchDraft 清空，并把这条通知选中，让同学在详情里直接看到改完的样子。

第三个叫 handlePatchCancel，点取消时走它。它只做一件事，把 patchStep 置成关掉，patchDraft 清空，别的什么都不许动，原通知一个字都不许改。

最后在渲染区把两个弹窗挂上去。patchStep 是选通知的时候显示 PatchLinkDialog，是看对比的时候显示 PatchReviewDialog。

还有一件事请一并做掉。点对比表某一行的依据原句时，请复用主页面里已经有的那个高亮原文的函数，不要自己另写一个高亮的办法。

下面这些是我一条一条算出来的期望，请你照着核对。

第一条，同学粘进来的就是助学金那条补充通知，库里已经存了助学金那条原通知。点解析之后，应该弹出选通知的窗口，不应该走普通解析，也不应该弹重复导入的窗口。

第二条，同学挑中助学金那条之后，应该进入看对比。对比表里应该有三行，第一行日期从十一月八日到十一月九日牌子是变化，第二行时间从十九点整到十九点整牌子是不变，第三行地点从行政楼A302会议室到行政楼B201会议室牌子是变化。这些保持原样那一块里应该有提交纸质申请表。确认更新按钮不是灰的。

第三条，同学点取消之后，那条原通知里评审会的日期必须还是十一月八日，地点必须还是行政楼A302会议室，一个字都不许变，也不许多出一条历史。

第四条，同学点确认更新之后，那条原通知里评审会的日期变成十一月九日，地点变成行政楼B201会议室，交表那件事的日期还是十一月五日时间还是十七点整，历史数组里多出一条。

第五条，同学粘进来的是评审会时间另行通知这种说不清的补充通知。选通知那个窗口里应该有一块醒目的底写着歧义，写明请先确认。

第六条，同学粘进来的是报名截止时间调整至十一月二十日，库里那条助学金通知里没有任何事项名字含报名这两个字。这时候匹配不到事项，选通知那个窗口里应该把两个事项列出来让他自己勾，一个都没勾的时候下一步按钮是灰的。

第七条，同学粘进来的是一句普通通知，里面没有任何变更词。这时候不应该弹任何补充通知的窗口，应该照原来的方式解析和保存。

请你只输出新增的两个组件的完整代码，因为都是新文件，还有主页面里改动的那几段。不要整个文件重抄一遍。改完我自己跑，跑不过我再回来找你。
```

## 本机验证结果

返修一轮，三处接口没接上。一是选通知那个组件在不需要手选时把事项下标传成空数组，
  我这边拿到空的就没法算对比。二是看对比那个组件去补充通知结果上取 alerts，
  可是提醒其实是落盘函数算出来的，取出来永远是空。三是点依据原句用的是行上的 start 和 end，
  而对比函数返回的行里只有 quote，取出来是空的。
  返修后改成组件内部对每条通知自己算一次匹配，主页面干跑一次落盘函数取提醒，
  依据原句用 quote 在原文里找子串定位。
