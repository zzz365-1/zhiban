# 007b 相对日期换算

归档时间：2026-10-31
状态：已执行并通过（补齐归档，原文在此前对话中发出，当时未落盘）

## 目标

让「明天」「本周五」「本月25日」「下周三」「大后天」这类口语写法能被换算成可用于倒计时的具体日期。

## 实施结果

四项改动全部落地：

1. `app/api/parse/route.js` — `buildSystemPrompt()` 动态注入当天日期，并要求模型以此为基准换算
2. `app/lib/aiExtract.js` — 新增 `isFuzzyDate`，相对表述一律视为未抽到，强制触发模型兜底
3. `app/components/AnalysisPanel.js` — 摘要不再写入日历，避免模型 hallucinate 的事实进交付物
4. `app/lib/deadline.js` — 只有日期没有钟点时默认填 17:00，不再落在当天零点

这一步想解决一类我一直很头疼的通知，就是不明说日期的那种。

比如写「明天中午12点前交」「本周五前到值班室登记」「本月25日前完成缴费」这种。现在日期那一格会把「明天」「本周五」这几个字原样显示出来，剩余天数算不出来，导出日历那个按钮也是灰的，等于这条通知白解析了。

我后来想明白了原因，模型不知道今天到底是几号，它当然不敢替我算。这个我理解，它不瞎猜反而是对的。所以我想的办法是，能不能在问它的时候顺手把今天的日期告诉它，比如明确说今天是2026年10月31日，请以此为基准换算。同时跟它讲清楚，如果连它也算不出来就老老实实留空，别硬编一个日期给我。

还有一件事我觉得是更大的问题。我发现本地规则现在会把「本月底」当成已经成功抽到了，那整条就判定为本地搞定，模型压根没被叫上来。可这个词根本没法用来算还剩几天。我的想法是，凡是「明天」「下周」「本月底」「大后天」这类含糊的说法，都应该算没抽到，老老实实交给模型去处理。你觉得这么改合适吗，还是有更好的办法。

第三个是上次跟你提过的那个隐患。有一条通知原文写的是下周三下午3点，模型给的摘要里写成了下周二。它敢这么写，我就不敢信它。现在这类通知导出按钮还是灰的所以看不出危害，等这次改完日期能算了，按钮就能点了，那句写错的摘要会一路进到日历文件里，人家打开日历看到的就是错的。能不能帮我想个稳妥的处理，比如在摘要前面加一句说明这是自动生成的仅供参考，或者干脆别把摘要写进日历文件。这个我拿不准，你给个建议。

每个文件的完整代码给我，我在 VS Code 里粘。
