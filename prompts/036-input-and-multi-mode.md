# 036 输入框太小、多通知提示和结果位置重做

日期：2026-11-02
模块：`app/components/NoticeInput.js`、`app/page.js`、
新增 `app/components/MultiSplitDialog.js`、`app/components/MultiResultPanel.js`、
删除 `app/components/MultiNoticePanel.js`

## 背景

我拿给同学试用，同学一口气提了四个问题。一是输入框太小，上面那块地方
明明还有很多空着，输入框却只有一点点高。二是多通知模式下，什么提示都贴在
输入框下面，把输入框挤得更扁。三是多通知之间如果没有空行分开，程序闷声不响，
什么都不告诉你。四是多通知模式和单条模式长得完全不一样，按钮不一样，
结果还堆在输入框下面那一小块里，三条通知挤在一起根本看不见。

## Prompt

```
我拿这个项目给同学试用，同学一口气提了四个问题，我一个一个说给你听，麻烦你帮我一起改。

第一个，输入框太小了。我们页面右边这块上面是通知原文的输入框，下面是解析结果，上面这块占了百分之三十五的高度，可是里面的输入框只占了一小截，下面空出一大片空白。同学说旁边明明还有很多地方，为什么输入框这么小。我希望输入框能把上面这块剩下的空间都撑满，不用留那片空白。上下比例先不动，还是三十五和六十五。

第二个，多通知模式的提示不要占输入框的地方。现在多通知模式下，输入框下面会直接渲染一块面板，里面写着已分割三条，还有重新开始和开始解析的按钮，这块面板把输入框挤得更扁了。我希望这类提示改成弹窗，弹出来显示，不要压输入框。

第三个，多通知如果没有用空行分开，现在一点反应都没有。同学把两条通知连在一起粘进去，点解析，界面上什么都不出现，他以为程序坏了。我希望这种情况也能弹个提示出来，告诉用户要用空行分开，或者每条都以关于什么的通知这种标题开头。而且最好给用户一个退路，可以选择就当作一条通知来解析。

第四个，多通知模式要和单条模式长得基本一样，只是功能不同。现在多通知的按钮只有一个开始解析，单条是解析和保存到我的通知两个按钮，我希望两个模式的按钮一样。还有解析结果，现在多通知的结果就堆在输入框下面那一小块，三条通知挤在一起，往下就看不见了。我希望结果和单条通知放在同一个位置，就是右下那块结果面板，一条通知一块，块多了能上下滑动。

我有几个要求想请你一起考虑。

第一，切分要先弹窗确认再解析。点解析之后先弹出一个框，告诉用户识别到几条，每一条的标题和开头一句是什么，如果哪一条切错了，可以点去掉把它排除掉。确认之后才开始真正解析。不要点一下就直接跑。

第二，保存的方式是一次保存全部。弹窗里去掉的那几条不保存，其余的一次性存进左边的我的通知列表。不要在每一块上都放一个保存按钮，那样太碎了。

第三，换模式的时候要把上一个模式的结果清掉。不然上面写着单条通知，下面还挂着三条多通知的结果，对不上，看着像出错。

第四，原文改了之后上一次的多通知结果也要清掉。改了原文还显示上一次的结果，那是旧数据，会误导人。

第五，弹窗要能关。点遮罩能关，按 Esc 也能关，不然弹窗挡着没法回去改原文。

第六，输入框改成撑满之后，单条模式原来那个占位的空白块要删掉，不然撑不满。多通知模式那块内联面板也要整个去掉，因为它已经变成弹窗了。

改完告诉我要跑哪几条命令验证，还有哪里是你在浏览器里需要我自己看的。
```

## 采纳情况

DeepSeek 给的方案和我想要的一致，四处都覆盖到了，实现上我改了两处。
一是它把去掉某一块的状态放在了页面层，我挪进了弹窗组件里，
弹窗关掉就跟着销毁，不用在外面手动清理。
二是它把切不出来的情况只给了一种提示文案，我拆成了两种：
确实像多条但分不开的，直接把切分模块给的原因显示出来；
只认出一条的，单独说一句要空行分开，免得用户看着莫名其妙。

## 本机验证

- 编译通过，二十一条离线命令全绿，一百条素材自检没问题
- 切分链路本机跑过：三条空行分隔的通知切出三条，逐条解析结果正确
- 无空行的场景本机跑过：切分模块给的是失败原因，弹窗会显示出来
- 界面渲染这一层本机没有浏览器，改完请用户在浏览器里过一遍
