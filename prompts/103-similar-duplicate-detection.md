# 103 补上疑似重复通知这一级判定

## 背景

同一个活动稍微改几个字再导一次，现在还是会产生重复事项。
当前查重只有两档，正文完全一样算重复，标题一样算标题重复需确认，其余都放行。
问题是标题相同但正文完全不同的一条通知，也会被当成标题重复弹出来，
而真正只是改了几个字的同一条通知，提示又和它长得一样，同学分不清。

## 本机已核验事实

app/lib/dedupe.js 当前导出四个函数。
normalizeForCompare 去掉空白和标点，返回纯字符串。
noticeTitle 取正文第一行非空文本。
checkDuplicate 收两个参数 text 和 notices，先比归一化正文全等返回 exact，
再比归一化标题全等返回 title_same，其余返回 none，
返回对象形如 { type, notice }。
itemCalendarKey 和 dedupeItems 是事项去重用的，不要动。

本机实跑了四种说法与同一条基准通知的正文相似度，
算法是归一化之后取相邻两字组成集合算 Dice 系数，
也就是交集数量乘二除以两个集合大小之和。结果如下。

正文完全一样 1.000
少量措辞变化 0.918，把报送至改成交至，请各班改成请各班于，届时到场改成准时到场
只改一句 0.977，只把届时到场改成准时到场
标题相同但正文完全不同 0.359，正文改成公示评选条件和异议反映渠道，日期地点材料全不一样

这四种当前 checkDuplicate 分别返回 exact、title_same、title_same、title_same。
也就是说标题相同内容不同那条现在会被误当成需确认的重复。

阈值定 0.75 就能干净分开，0.918 和 0.977 都在上面，0.359 在下面，余量足够。
请把这个算法做成导出函数，checkDuplicate 在 exact 之后加一档 similar，
返回 { type: "similar", notice, score }，
similar 之后再保留原来的 title_same 分支，
这样标题相同但实际内容不同的那条仍然提示标题相同但正文不同，不会被误判成疑似重复。

另外请新增一个批量查重函数，收一批正文和一个已有通知数组，
逐条返回它与已有通知、以及同批次里排在它前面的正文之间的重复判定，
让批量保存那边能一次拿到每条的状态。
判定时同一批里前面已经出现过的正文也要算进来，不能只比已有通知。

## 验收要点

第一，完全一样返回 exact，少量措辞变化和只改一句返回 similar，
标题相同但正文不同返回 title_same 而不是 similar，这三档必须分得开。

第二，不能只凭标题相同就返回 similar，正文相似度不够的一律不许判成疑似重复。

第三，不许自动删除或覆盖已有通知，函数只做判定，返回已有那一条的引用供界面查看。

第四，批量查重要同时覆盖与已有通知重复和同批次内部重复两种情况。

第五，正则一律用字符类，只用现有的归一化函数，不要新建名字差不多的模块，
只输出成对改动片段，不重写整个文件。

## Prompt

