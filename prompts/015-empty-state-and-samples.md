# 015 空态引导与载入示例通知

## 背景

当前打开页面，localStorage 为空时三栏全空白，用户不知道该往哪粘贴、能干什么。
赛事要求「README 含 10 分钟极速复现指南」，评委 clone 下来跑起来第一眼看到空白，
第一印象就砸了。本轮是投入产出比最高的一项。

## 硬要求：示例日期必须按打开当天动态计算

若写死成某月某日，过几天打开就全过期、一片灰，看着像坏了。
评委何时打开不可控，必须有几条永远处于不同紧急度：
明天截止、三天后、一周后、已过期、活动类无截止日期。

## Prompt

```
我发现一个问题。我现在打开页面，左边右边中间全是空的，第一次用的人根本不知道该干什么，不知道该往哪里粘贴，也不知道这个东西能做什么。我们比赛要求别人拿到代码以后十分钟就能跑起来看到东西，要是打开一片空白，第一眼印象就不好了。
我想加一个东西。中间那块空着的时候，显示一段话告诉人家这是干什么的，要怎么用，然后放一个按钮，写着载入示例通知，点一下就自动放几条通知进去，这样打开就能看到效果了。
这个按钮只在一条通知都没有的时候显示，有通知了就别再出来了，不然每次都看见很烦。
还有个地方我特别在意。那几条示例通知的截止日期不能写死。我试过，要是把日期写成11月2号，过几天再打开就全过期了，一片灰，看着像坏了。评委拿到我们的代码也是一样，他什么时候打开我们不知道，写死的日期肯定会有几条是过期的。所以日期得按打开那天的日期算出来，比如一条是明天截止，一条是三天后，一条是一个星期后，再来一条是已经过期的，这样不管哪天打开效果都是对的。
内容上我想覆盖几种不同的情况。一条要有明确的时间地点和要带的东西，最好里面出现两个日期，一个靠前一个靠后，看看它会不会取错。一条没有材料只有地点。一条写的是下周三这种不写具体日期的说法，因为我发现这种有时候会算错，正好可以演示我手动改一下。还有一条是活动通知，没有截止日期，就是某天在哪儿办活动。最后再来一条已经过期的，让人看到过期了会变灰。
老规矩。给我一个能在终端直接跑的自检脚本，要验证那几条示例通知的日期确实是按当天算出来的，不是写死的。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
另外提醒一下，你每次改 package.json 的时候，里面原来就有的命令要都留着。
不要为了这些装新的库。
这一步就只做空状态提示和载入示例这两件事，其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 示例数据里**不许出现任何写死的年月日**，只能用相对偏移在运行时计算
2. 空态提示与按钮只在列表为空时出现，有数据后必须消失
3. 载入后五条应覆盖：紧急标红、黄色分级、相对日期、活动类无截止、已过期置灰
4. 全量回归十条命令均需通过，原有 npm 命令全部保留

## 备注

示例内容的设计意图：第一条故意埋「文首靠前日期 + 文末截止日期」的陷阱，
验证不会取错；第三条用相对日期，便于演示手动修正功能。
