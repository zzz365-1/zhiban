# 014 粘贴入口统一为模式切换，并校验内容与模式是否一致

决策时间：2026-11-01，由用户在讨论中拍板。

现状问题：单条解析在中间主区域，批量解析在顶部导航条上一个不显眼的「批量粘贴」按钮。
用户视角只有"一段通知文字"，是几条由内容决定，不该由用户去找对应的按钮。

用户拍板的方案（比"常驻开关"和"自动判断"都更完整）：
1. 中间输入框上方常驻「单条通知」与「多通知」两个选项，默认停在单条。
2. 粘贴后系统自动检测内容与当前模式是否一致，不一致就提醒。
3. 提醒只是建议，用户可以选择忽略，系统不得擅自替用户改模式。
4. 系统自己拿不准时不提醒，避免每次粘贴都弹窗。

这样既保留了显式声明的确定性（用户随时知道自己在什么模式），
又用系统校验堵住了"忘了切模式"这条静默失败通道——
否则多条内容按单条解析会拼出每格都有值、实际不存在的"缝合怪"（Dec-019、Dec-021 同类）。

现成能力：`splitNotices` 返回 `{ ok, items, method, reason }`，
items.length 即条数，ok 为 false 即拿不准，纯本地规则，不调模型，即时返回且零成本。

## 实施 Prompt

```text
我想把粘贴通知这个入口合并一下，现在是分开的，我觉得用起来别扭。
现在的情况是，中间那一大块只能一条一条解析，要一次弄好几条的话，得去顶上找一个「批量粘贴」的按钮，那个按钮还挺不显眼的，我一开始都没找到。我觉得没必要分两个地方，粘贴通知就应该是同一个地方，不管我这一次贴的是一条还是好几条，都在中间那一块弄。
我的想法是在中间输入框上面加一个选择，两个选项，一个是「单条通知」，一个是「多通知」，我自己先选一下我这次要贴几条。默认就停在「单条通知」上，因为多数时候就是一条。
不过光有这个选择我怕不够。万一我忘了切呢。比如我从班群里复制了辅导员连着发的三条，粘贴进去，可是我忘了我还停在「单条通知」上，那程序就会把三条当成一条来解析，截止日期可能是第一条的，地点是第二条的，材料是第三条的。这样拼出来的东西每一格都有值，看着挺正常，其实是一条根本不存在的通知，我要是没注意就存下来了，日历上就多了一个错的。这种错最麻烦，因为它不报错，界面上也看不出来。
所以我想加一个提醒。我粘贴完以后，程序自己看看这段内容跟我现在选的模式对不对得上。要是我在「单条通知」模式下，它看出来这段像是好几条，就提醒我一句，说这段看起来像是三条通知，你现在选的是单条，要不要切过去。反过来也一样，我要是选了「多通知」，结果只认出来一条，也提醒我一下。
但是提醒归提醒，决定权给我。它提醒完，我要是觉得它看错了，我选继续按原来的模式走，它就得照我说的办，不能自己替我改。
还有一件事很重要。它要是自己也拿不准这段到底是几条，那就别提醒，直接按我选的模式走就行。我最怕那种每次粘贴都弹个窗问我要不要切换，明明就是一条普通通知也要问一遍，那样太烦了。
还有一点，这个看看是几条这件事，我希望不要用那个模型来做。我粘贴完马上就要知道结果，等模型转两秒太慢了，而且一次粘贴本来也不该花那个钱。你之前做批量粘贴的时候不是写过一个能判断一段文字里有几条的法子吗，用那个就行。
顶上那个「批量粘贴」的按钮，既然功能合并进来了，就可以去掉了。但是原来那些能耐都不能丢，一次贴好几条的时候要一条一条解析，要让我看到正在解析第几条一共几条，有一条没解析出来要告诉我是哪条，不能因为一条失败就把剩下几条都扔了，也不能假装全部成功。重复贴同一条的时候要认出来，不要再存第二遍。
老规矩。给我一个能在终端直接跑的自检脚本，要验证选了单条但内容是三条的时候会提醒，选了多条但内容是一条的时候也会提醒，还要验证它拿不准的时候不提醒。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
另外提醒一下，你每次改 package.json 的时候，里面原来就有的命令要都留着，之前已经删过我两次了。
不要为了这些装新的库。
这一步就只做模式切换和提醒这一件事，其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 模式切换存在于中间输入区，默认停在「单条通知」。
2. 三态都要验：单条模式遇多条内容要提醒、多条模式遇单条内容要提醒、拿不准时不提醒。
   第三条最容易漏，它是"宁缺勿滥"的一部分——没把握就不要制造噪音。
3. 提醒后用户选择忽略时，必须严格按用户选的模式执行，系统不得擅自切换。
4. 检测必须是本地规则，不得调用模型。验收方法：grep 该流程是否有网络请求，
   并确认检测是同步返回的，粘贴后应立刻出现提醒而非等两秒。
5. 原有批量能力一个都不能丢：拆分、进度提示、逐条解析、单条失败不丢弃其余、
   失败要指明是哪一条、重复内容不入库。
6. 顶部「批量粘贴」按钮已移除，且移除后批量能力仍可从模式切换进入。
7. 自检脚本要有通过失败统计，故意错的用例必须报红。
8. package.json 原有命令全部保留（Dec-029）。
9. 回归：test:batch、test:share、test:title、test:manual、test:calendar、test:relative 全跑一遍。
