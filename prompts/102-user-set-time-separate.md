# 102 用户自行补充的时间与通知规定时间分开

## 背景

同学在提醒卡片里可以自己补一个活动结束时间，用来判断时间冲突。
这个时间是用户自己填的，不是通知写的。现在补完以后它和通知里写的时间混在一起，
看不出哪个是通知要求的，哪个是自己估的，容易被当成通知原文的时间。

## 本机已核验事实

补充结束时间的入口在 app/page.js 的 handleFillEndTime，第792行开始。
它校验输入是合法时分，且必须晚于开始时间，然后在这条通知的这个事项上写
endTime 为填的值，同时把 status 里的 endTime 改成 ok。
事项存在两处，最外层 items 和 analysis 里的 items，函数用同一份新数组同时写回。
路由事件模块会把 item.endTime 带上给冲突计算用，这个不能断。

事项卡时间行在 app/components/ItemsPanel.js 的 TimeHeadline 里，
现在 parts 依次放 timeTypeLabel、date、time，没有 time 但有 date 时会放 NO_TIME_NOTE，
最后用空格拼成一行显示。当前没有显示 endTime 的地方。
组件顶部已经从 ../lib/deadline.js 导入 NO_TIME_NOTE。

界面上通知要求和系统建议不是通知里的要求两个区块已经分开，那层不要动。

## 验收要点

第一，用户补的结束时间要在事项上留下一个明确来源标记，
表明这是用户自行补充的，不是通知规定的时间。

第二，事项卡时间行要能看出这个区别，
用自行补充这样的字样把用户填的结束时间和通知规定的开始时间分开显示，
不要让两者看起来都是通知原文的要求。

第三，补完以后冲突判断照常能用到这个结束时间，
路由事件和冲突计算那条链路一个字都不许断。

第四，通知本身写了结束时间的事项，不显示自行补充字样，行为跟现在一样。

第五，只输出成对改动片段，逐文件分开写，不重写整个文件，不新增独立设置界面。

## Prompt
