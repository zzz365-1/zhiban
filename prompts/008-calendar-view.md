# 008 视图框架：导航条 + 日历 + 待办清单

**立项**：2026-10-31 14:35
**v3**：用户决定把导出改成命令行工具，并勾选四项后续功能，因此本轮先搭视图架子。

## 为什么把日历与待办合并进同一轮

用户要求页面划分清楚，不能杂乱。若先做日历、下次再加待办，第二轮的导航条必然推翻第一轮布局，
等于返工且有回归风险。因此一次做完「看」的三件事：导航条、日历视图、待办清单。

## 相关决策

- **导出改为命令行**：界面不再有任何下载按钮。`generateICS.js` 与 `validate:ics` 保留，
  另补 `npm run export:ics`。既有标准格式能力留档，又不会在演示时翻车。
- **提醒不做弹窗**：改为待办清单，只显示三天内到期，不足一天改显示剩余小时数，超过五条折叠。
- **后续轮次**：009 手动修正、010 复制摘要、011 批量粘贴、012 搜索筛选。
- **冻结线 11 月 12 日**：其后六天全部给文档与演示素材。

## Prompt 正文

```
最近我需要往里加好几个功能，日历啊待办啊后面还要加搜索和修改什么的。我有点担心，如果这些东西一个一个往上堆，按钮越来越多，最后页面会很杂很乱，看着不像一个正经产品。所以在动手之前我想先把整个页面的格局定下来，以后新东西都往这个格局里放，不再到处加按钮。
我想的格局是这样的。最上面加一条很窄的横条，左边写我们产品的名字，中间放三个小标签，分别叫「待办」「日历」「全部通知」，点了就切换。最右边放一个搜索框和一个分类的选择，方便以后通知多了能找。
下面还是三栏，这个不要动。左边那一栏的内容跟着上面的标签变。点「待办」就显示最近三天内要截止的事，点「日历」就显示一个月的格子，点「全部通知」就是现在这个列表。中间那一栏还是贴通知原文，右面那一栏还是解析结果，这两个位置都不要变。
这一次具体做日历和待办这两块。
先说待办。我之前想过一打开就弹个窗出来提醒，后来觉得不好，弹窗占地方还烦人，而且一次只能看见一件事。我想改成一条待办清单，就在切换过去之后显示出来，三天内要到期的都列出来，越急的排越前面。超过一天的写还剩几天，不到一天的改成写还剩几个小时，我觉得快到的时候按钟头算才有用。要是三天内没什么事，就显示一句让人安心的话，别空着一大块。这个清单里最多显示五条，再多的话下面就写一句还有几件，点开再展开。
再说日历。一个月的格子，那天有事的话格子上露出来，可以是个小圆点或者几个字的标题。点那个格子，能看到那天所有的事，什么事、几点、在哪、要带什么东西。没事的日子空着就行。上个月和下个月的尾巴那个位置也要有格子，但是颜色淡一点，让人知道那是别的月。日历这一页和列表这一页要保持一致的紧急程度，三天以内还是红的，一周以内还是黄的，别两套标准。
还有一件事。以前那个下载日历文件的按钮，我后来想明白了，打算不要了。界面上不要出现任何导出到日历的按钮，这个功能我改成一条命令放在终端里跑，界面上就当没这回事。
老规矩。算一个月的格子会碰到跨月、闰年、每个月天数不一样、上个月尾巴占着本月第一格这些，很容易差一天，而且肉眼看不出来。给我一个能在终端直接跑的自检脚本，验证二月、跨年的十二月、一号正好是星期天这几种特殊情况。还要验证待办清单那个三天和小时的换算。脚本要有期望值和通过失败统计，外加一条故意算错的用例，证明断言真的能抓到错，上次我们已经用这招验证过是管用的。正则里数字写成零到九这种字符类的样子，不要用反斜杠，我们在这个地方连续栽过跟头。
不要为了这些装新的库，能用基础办法算出来就用基础的。
这一步就只做导航那个横条、日历、待办清单这三样，手动修改、搜索、批量粘贴那些我们后面再一轮一轮加，这次千万不要顺手给我加上去。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 顶部导航条存在，三个标签可切换，左栏内容随之变化。
2. 待办清单只显示三天内到期，不足一天显示剩余小时数，超过五条折叠。
3. 月历格子按天落位，跨月灰显，紧急度阈值与列表一致，三天红、一周黄。
4. 界面上不再出现任何下载日历文件的按钮。
5. 终端自检脚本：二月、跨年十二月、一号为周日等用例全部通过，另有一条故意算错必须报错。
6. 未安装任何新依赖库。
7. 改动完成后运行 `npm run test:location` 与 `npm run test:dates`，两组都应保持全绿。
