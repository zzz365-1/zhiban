# 011b 修标题在解析结果面板显示未识别

**立项**：2026-10-31 19:20
**定位**：011 里让分享文字做了标题兜底，但**右栏面板没接上同一个函数**，同一个标题三处三个来源，其中一处掉链子。

## 缺陷成因（本机实测确认）

- `app/lib/shareText.js` 的 `getNoticeTitle` 有三级兜底：analysis.title > notice.title > 原文首行。
- 但 `app/components/AnalysisPanel.js` 的字段渲染走 `renderValue(analysis[field.key])`，
  第 21 行 `return value || "未识别"`，**只认 analysis.title**，为空即显示未识别。
- `NoticeList` 读 `notice.title`，所以列表正常；分享文字走三级兜底，所以也正常。
- 规律：**凡没经过模型的条目（手动加入、本地识别），右栏标题一律未识别**；
  走过模型的那条（AI 辅助）显示正常。

本机探针已排除另一处嫌疑：`formatShareDateTime` 对 11月2日 17:00 输出正确，
分享文字的日期没有问题，本轮只修标题。

## Prompt 正文

```
复制到剪贴板这个做好了，我用下来发现一个地方不对。
我在左边点一条通知，右边解析结果里标题那一格显示的是未识别。可是同一条通知，左边列表里明明显示着完整的标题，你那个整理成文字的弹窗里也显示着完整的标题。同一个标题，三个地方，就右边这一格是空的。
我试了几条，发现有一个规律。凡是标签写着手动加入或者本地识别的那些，也就是没有经过模型解析的，右边标题那一格都是未识别。反过来，标签写着 AI 辅助的那条，标题就正常显示出来了。所以我觉得是不是因为标题存在了两个地方，经过模型的那些存在一个地方，没经过的存在另一个地方，而右边这一格只认其中一个。
能不能让它们统一起来，不管这条通知有没有经过模型，右边标题那一格都要显示出标题来。通知原文的第一行本来就是标题，实在不行从那里拿也行。
不过有一点我要说清楚。摘要和分类那两格显示未识别，我觉得这个是正常的，因为确实没经过模型，没有摘要很合理，这两格你不用管。我要修的只有标题这一格，因为标题是原文里本来就有的东西，不该空着。
还有一件事。你上次做的时候，好像特意为整理成文字那个功能写了一个专门取标题的办法，能一级一级往下找。这次能不能让右边那一格也用同一个办法，不要另外再写一套差不多的。我们之前为这个吃过亏，两边各写一套，结果结论对不上，比没有还麻烦。
老规矩。给我一个能在终端直接跑的自检脚本，要验证不管有没有经过模型，取出来的标题都是对的，还要验证人工改过标题的时候以人工改的为准。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
不要为了这些装新的库。
这一步就只修标题这一个格子，摘要分类和其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 点一条「手动加入」或「本地识别」的通知，右栏标题格显示完整标题，不再显示未识别。
2. 点一条「AI 辅助」的通知，标题仍正常。
3. 人工改过标题后，以人工改的为准。
4. 摘要、分类两格保持不变，仍是未识别（本轮不修）。
5. 自检脚本 import 生产模块，含故意错的用例且被判定失败。
6. 没有新增依赖。
