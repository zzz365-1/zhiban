# 061 第六轮之一 评测脚本

## 背景

第六轮要交一份能给别人看的测试记录。之前那些测试脚本都是开发时用的断言脚本，
跑完只说通过多少失败多少，看不出每条通知抽成了什么样。
现在需要一个评测脚本，把一批通知逐条跑一遍，把预期和实际并排列出来，
并且统计时间类型、时间值、事项和地点对不对、材料有没有漏抽或者误抽。

语料文件我已经写好了，是一个 json 文件，放在文档目录下，名字叫 eval 短横线 cases 点 json。
你不要改语料，只写跑它的脚本。

## 几条硬约束

第一，必须 import 真实生产模块，不许在脚本里另抄一份差不多的实现。
事项是调事项模块里那个导出的构建函数，日期基准用它的第二个参数传进去。

第二，基准日期要写死。所有预期日期都是按二零二六年十一月二号这个基准算出来的，
不许用当前时间，不然过几天跑出来的日期全变了。

第三，语料解析出零条必须报错退出，不许把零覆盖渲染成通过。

第四，评测是量东西不是卡门禁。有失败很正常，脚本要把失败写进报告并且如实统计，
退出码还是零。只有语料为零条、或者某条跑的时候抛异常，才给非零退出码。

第五，报告里必须写明测试条件，包括条数、基准日期、走的是哪条路径、要不要密钥。

## 本机已核验事实

事项模块导出的构建函数叫 buildItems，接收两个参数，第一个是通知原文字符串，
第二个是选项对象，选项上有一个键叫 publishedAt，传日期对象或者能转成日期的值。
它返回一串事项对象，每个事项上有 name，timeType，date，dateText，time，
location，materials，status 这些键。
timeType 只有两个取值，deadline 表示办理截止，start 表示活动开始。
date 是字符串，格式是四位的年短横线两位的月短横线两位的日。
time 是字符串，小时两位数字英文冒号两位分钟，没有就是空。
location 是字符串，没有就是空。
materials 是数组，每个元素是一个对象，上面有个 name 键是材料名。

相对日期模块导出的 resolveRelativeDate 接收原文词和基准日期，返回 null 或者一个对象，
对象上有个 normalized 键是那个四位的年短横线月短横线日的字符串。
