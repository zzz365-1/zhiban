# 004 - ICS 日历导出（行动产出层第一步）

> **状态**：待发出。004 号的第一个交付，对应「产品生死线」。
> **写作原则**：参赛学生第一人称，逗号句号断句，不用括号星号破折号，不用 markdown 强调符号。

## 产品定位（架构师注）

003 让「知办」能**看清**通知，但看清不等于执行。004 的目标是把结构化字段变成**可被手机日历消费的实体行动**——这是区分「又一个 AI 摘要」和「真正有用的工具」的分界线，直接对应评分表 25% 的「解题有效性与实用价值」。

选 ICS 而非自研提醒系统，理由：零后端、零账号、零成本，双击即入系统日历，演示时效果最直观，且评委一定能复现。

## 技术要点（架构师内部掌握，不进 Prompt 正文）

ICS 标准格式对本项目的三个硬约束：

1. **换行必须是 CRLF（`\r\n`）**，仅用 `\n` 会导致部分日历客户端解析错乱或静默失败。这是该格式最经典的坑，且 AI 极易写错。
2. **行宽不得超过 75 字节**，超长需折行（RFC 5545）。
3. **时区需显式声明**，建议用 `Asia/Shanghai` 的 VTIMEZONE 或 UTC 时间 + `Z` 后缀，避免出现「导出后时间偏移 8 小时」。

本轮 Prompt 刻意让 AI 自行解决这三点，但**要求它提供不依赖手机导入的本地校验手段**——这是吸取 003 三轮转义教训后的流程升级。

## Prompt 正文

```
昨天那个抽取引擎跑通了，五个样例里日期、时间、地点都抽得很准，太感谢了。今天想往前推一步。

我发现现在有个问题：字段是抽出来了，可是同学看完截止日期之后，还是得自己打开手机日历去手动添加这一步，很多人懒得做，通知照样会忘掉。所以我想做成这样，右边解析结果那块下面加一个按钮，点一下就能下载一个日历文件，双击可以直接导进手机或者电脑的日历里，提醒也自动设好。

这个东西我听人提过，好像叫 ics 文件，具体怎么做我没概念，你按通用的标准来就行。有几个要求我想说一下：

一是时区。我们都在国内，导进去的时间必须是中国这边的时间，不要出现导入之后变成别的时区时间这种情况，这种错误特别难发现。

二是如果这条通知压根没抽出截止日期，这个按钮点了也没意义。能不能让它变灰不能点，或者点的时候提示一下先得有截止日期？这块你看着办，怎么合理怎么来。

三是提醒时间。别等到截止当天才响，最好能提前一天提醒一次，比如15号截止，14号就来个提醒。你觉得这样合适吗，不合适的话你按常见做法来。

还有一件事比较重要。我听说这种日历文件对格式要求挺严的，尤其换行那里，写错了的话导入会失败或者时间整个乱掉，而且很难查出来是哪一行出的问题。我们昨天在那个反斜杠的事情上折腾了三轮，我有点怕再来一次。能不能麻烦你顺便给我一个检查的办法，不用真的导到手机里，在电脑上就能先看一眼这个文件是不是符合标准？有的话告诉我怎么用。

这一步先只做日历导出，别的功能暂时不用动。老规矩，每个文件的完整代码给我，我在VS Code里粘。
```

## 这条 Prompt 的五个设计点

1. **开门见山给产品动机**：不是「我要加个按钮」，而是「同学看完还是要手动添加，很多人懒得做，通知照样会忘」。**这是 25% 解题有效性的核心论述**——评委要看到你理解真实场景，而非堆功能。
2. **时区要求**：真实用户一定会遇到的问题，且 AI 极易忽略。提出它体现产品完整度。
3. **空值时的按钮行为**：主动考虑边界状态，这是产品设计意识的体现。把实现方式交还给它（怎么合理怎么来）。
4. **主动预警格式陷阱**：措辞是「我听说……我有点怕再来一次」——把昨天的教训转化成今日的风险预判。**这条是整条 Prompt 最值钱的部分**，它证明提问者在积累方法论，而不是每次都从头踩坑。
5. **索要本地校验手段**：流程层面的升级。从「跑起来看浏览器」升级为「命令先验」。这个习惯若贯穿全程，最终结果可信度会有量级差异。

## 验收标准

- 右侧面板出现导出按钮，且无截止日期时处于禁用/提示状态
- 点击后下载 `.ics` 文件，双击能被系统日历识别
- ICS 内换行符为 CRLF（可用十六进制/文本工具验证）
- 事件时间在中国时区正确，且含提前一天的提醒（VALARM）
- AI 提供了本地校验方法
