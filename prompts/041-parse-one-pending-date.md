# 041 没有通知发布日期就不许按今天换算相对日期

## 背景

通知里写明天或下周三，程序直接按今天算出一个日期。可是这条通知是哪天发的并不知道，按今天算出来的日期可能比通知发布日还早。同学试用时抓到这个矛盾。

上一轮事项层已经按这个口径做了，没有发布日期时保留原文并标待确认。这一轮要把整条解析链路改成同一个口径，否则事项层和扁平字段会互相打架。

## 几条硬约束

第一，没有发布日期时保留原文那个词，不许换算。

第二，换算与否要在结果上留一个标记，界面才能提示用户补发布日期。

第三，模型路径和本地路径口径必须一致。

第四，原来的单参数调用方式不能坏。

## Prompt

```
上一轮那个事项层我按你说的改好了，四条原文都对上了，十分感谢。这一轮我发现了一个更要命的问题，还是日期的事。

我们程序遇到明天或者下周三这种说法，是直接按今天这个日子去算的。可是我根本不知道这条通知是哪天发的呀，凭什么按今天算。同学试用的时候抓到一个特别难受的例子，一条通知明明是上周发的，里面写着明天交表，我们按今天算出来的日期比通知发布的日子还早，这显然不对。

所以我想请你把整条解析的链路改成这样。解析的入口多加一个参数，可以传进来这条通知的发布日期。传了发布日期的，相对日期就按发布日期去算。没传发布日期的，遇到明天这类说法就原样留着不许算，同时在一个字段上做个标记，让界面知道这个值是待确认的，好提示用户去补发布日期。

有几点请特别注意。

第一，标记字段的名字我写在另外那张事实表里了，请照着用，放在解析结果里。没有基准的时候它是真，有基准并且算出来了它是假。

第二，模型那条路径也要一起改，不能只改本地规则那条，不然两条路走出来的结果不一样，界面上会一会儿对一会儿错。

第三，上一轮你帮我把事项层也改成这个口径了，这一轮改完请保证两边的口径是一致的，事项里显示的和上面那个扁平字段显示的不能互相打架。

第四，原来只传一个参数的调用方式不能坏，我们别的地方还在这么调。第二个参数不传的时候就当作没有发布日期。

下面这两条是我跑出来的，请你照着核对，不要自己另算。

跑体温表那条通知，不传发布日期，结果里的标记是真，截止日期还是明天两个字，没有变成某月某日。

还是这条通知，传发布日期二零二六年十一月二日，结果里的标记是假，截止日期是二零二六年十一月三日。

麻烦你只给改动片段，告诉我改哪几处改成什么，不要给整个文件的完整实现。正则继续用字符类写法。
```
