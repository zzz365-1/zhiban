# 019d 补「这个星期X」「下个星期X」等带个字的星期说法

## 背景

019c 收尾后，日期换算模块自己写的支持清单里列了两类带个字的星期说法，
但穷举注入实测这一类全部返回 null，属文档与实现不一致。
同时该类说法是学校通知里最常见的口语写法之一，漏掉会持续造成静默失效。

## Prompt

```
上次那版改完我又试了试，你说加的那些基本上都好了，说过一周说过两周的能算了，说三个月以后这种意思含糊的也知道空着不瞎猜了，那条对不上的测试用例你也改对了基准日子，没有直接把答案改掉，这几处我都看出来了，谢谢你。

不过我翻最开头那段说明的时候，看到里头写着支持下个星期几和这个星期几，我就顺手去试了试，结果试一句空一句。试了这几种说法，右边都是空的。

这个星期三，这个周三，这个星期日，这个周日，下个星期三，下一个星期三。

我一开始以为是我打错了，就换着花样又试了几遍，发现写成下面这样反而是能算出来的。

下周三是能算出来的，本周三也能算出来，这周三也能算出来，下一周周三也能算出来。

也就是说凡是带个字的那几种写法，都不行。可是平常说话大家确实会说这个星期三和下个星期三，学校通知里这么写的也不少，写成这个星期三的比写成周三的还多，漏了这一块感觉挺可惜的。

还有，既然说明里写着支持这两句，结果又算不出来，我怕后面再看的时候搞不清到底支持什么不支持什么，能不能顺便把说明那段也跟着对一下，支持的才写进去。

除了这几句，你要是还想到了别的带个字的或者别的常见说法，一并加上吧，我是真不想再一遍一遍粘着试了。前面已经试了三轮了，每轮都是试完觉得好了，下一轮又冒出来一句新的。

老规矩。给我一个能在终端直接跑的自检脚本，上面说的每一种说法都要有一条用例，还要试跨月，跨年，月底那几天。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。脚本要引用页面真正在用的模块，不要另抄一份。

另外提醒一下，你每次改那个存各种命令的文件的时候，里面原来就有的命令要都留着，尤其是那条查密钥的，之前已经删过我两次了。

不要为了这些装新的库。

这一步就只动日期这一块，其他功能都不要改。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 穷举注入，以下必须全部有值：这个星期三，这个周三，这个星期日，这个周日，
   下个星期三，下个周三，下一个星期三，下一个周日
2. 已有的不能回归：下周三，本周三，这周三，下一周周三，下星期天，下周天
3. 文件头支持清单与实际能力必须一致，不许写着支持实则不支持
4. 注释不许再删，aiExtract 的注释条数不得低于 24 条
5. 断网可跑：移走 .env.local 后仍出结果
6. 全量回归至少跑 test:relative，test:sample，test:calendar，test:manual，test:extract
