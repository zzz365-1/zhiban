# 021b 日期与时间写法被误杀，命令再次丢失

## 背景

021 的主线做对了：编造的地点、材料、日期、面向对象都能被拦下并记录到 `_groundingDropped`，
金丝雀也第一次是真货。这一轮专治误杀，以及又一次丢失的命令。

## 取证

**日期误杀。** 原文写十一月十五日，模型返回下列写法的核对结果：

| 模型返回 | 结果 |
|---|---|
| 十一月十五日 | 放行 |
| 二〇二六年十一月十五日 | 放行 |
| 用横杠隔开的写法 | 被拦 |
| 用斜杠隔开的写法 | 被拦 |
| 用点隔开的写法 | 被拦 |

根因：取月和日那一步，遇到纯数字加分隔符的写法时取到了最前面那一段，
把年份当成月份。同为十一月十五日这一类写法的没问题，说明只错在纯数字型的那一路。

讽刺的是项目里**早就有一个**把这五种写法全部归一成同一种样子的函数，本机逐条验过全部正确。
它又手写了一份错的。这正是早先记下的那条教训，另起一份不同源的判断，给的是虚假安全感。

**时间误杀。** 原文写下午五点：

| 模型返回 | 结果 |
|---|---|
| 下午五点 | 放行 |
| 下午五点写成汉字数字 | 放行 |
| 十七点整 | 被拦 |
| 十七点 | 被拦 |

它给地点做了六楼与六楼的换算，却没给时间做同类换算，两处口径不一致。
而且自己的检查清单里有一条写着这种情况就该被拦，期望是顺着实现写的，不是顺着理写的。

**命令再次丢失。** 检查书写符号那条指向了一个已经不存在的文件，一跑就报找不到东西。
查地点那条直接没有了，脚本还在磁盘上，十一条全绿，只是没有了入口。总数没变，删一条补一条。

**注释减少。** aiExtract 的说明从六十九条降到三十四条，parseOne 里本地优先换算那句
与错误码不许吞掉要一路带到界面上那句被删掉。

## 验收要点

1. 五种日期写法全部放行，且要去用那个已经存在的判定，不许再写一份
2. 时间与地点用同一套口径，十七点整与下午五点视为同一个意思，另外入夜时段一并考虑
3. 不许把期望值改成实际值了事，判断依据要写清楚
4. 逐条念出所有命令名，保证一条不少，且每条都能立刻出结果不等键盘输入
5. 补回被删的说明文字
6. 金丝雀保持有效，注入后必须报红
7. 上一轮被拦下的那些用例一条不少
8. 全量离线命令回归

## Prompt

```

第三件事跟这道关口没关系，是我今天想用的时候才发现的。我现在有两条命令用不了了。一条是我每次写完要发给你的那些话之后，靠着它检查有没有用错符号的那条，我今天敲了一下，屏幕上跳出来说找不到东西，指向的地方好像压根不存在，这条现在是彻底跑不动了。另一条是查地点的那条，我今天想跑一遍，翻遍了也没找着，我记得上回是加进去的。会不会是你往里头加新的的时候不小心把老的挤掉了，总数倒是没少。能不能这样，你改完之后把现在所有的命令名字一条一条念给我听，我对着核一遍，光数个数我已经被骗过好几次了。还有一条要求，每一条命令都得我自己敲一下就能立刻出结果，不许停在半路等我再从键盘敲东西进去。

另外我翻了一下你改过的地方，有几句原来写在最上头的话不见了。比如哪一步是本地自己先算的那一句，还有那句说错误码不许吞掉要一路带到界面上的。那几句我挺依赖的，看的时候能帮我回想起来这一步到底在干什么，能不能给补回去，或者你觉得没必要写在那儿也跟我说一声你的理由，我听你的。

老规矩。给我一个能在终端里直接跑的自检脚本，要引用咱们页面上真正在用的模块，不要另抄一份，要有期望值和通过失败的统计，还要有一条故意错的用例并且证明它真的会报红。改完之后你帮我把之前那一堆检查脚本都跑一遍确认没坏，尤其别再冒出任何一条一敲就报错说找不到东西的。相关的代码给我，我在编辑器里粘。
```
