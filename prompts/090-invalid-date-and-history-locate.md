# 090 非法发布日期与依据原句误选

## 背景

通知发布日期输入框填了非法内容后，下面已经出现红字，开始解析按钮却还能点，
而且解析会沿用上一次填的合法基准。修改历史里点依据原句，光标会跑到原文最开头。

## 本机已核验事实

日期不合法时输入处理函数直接返回，既不清空上层值也不覆盖它，上层保留着上一次的合法日期。
解析按钮的禁用条件只判原文为空和正在解析，没有判日期错误。
修改历史把依据原句这个字符串原样传给高亮回调，而回调直接把参数当成含起止下标的对象用，
字符串的起止都是空值，浏览器把它当成零，于是选中了原文开头。
对比弹窗传的才是含起止下标的对象，但下标是相对补充通知原文算的，不是当前通知原文。

## 验收要点

第一，日期没认出来时解析按钮禁用，输入草稿保留，上层基准回传空串。
第二，恢复成合法日期后照常回传，留空行为完全不变。
第三，高亮回调遇到字符串或越界下标时安静不选中，不再误选开头。
第四，原有的选中后滚动逻辑保留，不改按钮文字与补充通知对比逻辑。

## Prompt

```
我遇到两个不显眼但挺别扭的事。新增通知弹窗里有个选填的通知发布日期，我先填了一个正常的日期，后来故意改成几个英文字母想试试报错，输入框下面确实红了，写着日期没认出来，可是开始解析按钮还是能点，我点下去发现它还在按之前那个正常日期换算，好像红色提示只是摆着看的。另一个是通知有修改记录以后，我点历史里那句依据原句，本来想看看它对应原文哪一段，结果要么没反应，要么光标一下子跑到原文最开头，选中的根本不是那句话。我不太确定是值没传对还是位置算错了，能不能帮我看看这两处，让按钮在日期没认出来的时候真的不能点，也让依据原句找不到的时候别乱选，只给我要改的那几段代码。
```
