# 029 模型返回的周期日期没被拦，半个月后这种说法没被换算

## 背景

031 大批量测试（六十条真实通知）查出四个日期问题：

1. `每周三下午三点在行政楼会议室召开例会` → 界面显示截止日期「每周三」。028 修的是本地规则，
   但这条走了模型兜底，模型返回的值在合并时没有再拦一次周期。**同类还有「第12周前」。**
2. `半个月后截止` → 界面原样显示「半个月后」。本地 `resolveRelativeDate` 单独调用能算出
   2026年11月17日，但 `isFuzzyDate` 用的正则表没有「半」字，判它非模糊，压根没去调换算。
   **半年后、一季度后同病。这是两处不同源的典型：能力有，开关没开。**
3. 中文数字日期 `二〇二六年十一月十五日` 模型能抽出来，但转不成具体日期，日历加不进去。

## Prompt

```
我又跑了一批测试，六十条学校里常见的通知，大部分是对的，但是日期上有三个问题我实在解决不了，你能帮我看看吗。

第一个，通知里写学生会各部门每周三下午三点在行政楼会议室召开例会，最后界面上截止日期那一栏显示的是每周三。之前我们明明已经让本地规则不认周期时间了，可是这次显示出来的是模型返回的值，本地那条规则好像管不到模型给的东西。我听人说本地规则是在抽取那一步拦的，模型的结果合并进来的时候没有再拦一次。这样界面上就会出现一个根本没法加进日历的截止日期，学生看了会觉得很怪。第12周前也是同一类问题，界面上原样显示第12周前。

第二个，半个月后这种说法，本地那个换算函数其实是能算的，我单独试过，给我返回的是二零二六年十一月十七日。可是整条通知跑下来它就是不换算，界面上原样显示半个月后。我查了一下，好像是有个判断函数说它不是模糊日期，所以根本没去调换算。那个判断用的是一份正则表，表里只写了几天几周几个月这种写法，没有半个月，也没有半年和一季度。我觉得这两处应该同源，换算函数能算出来就该算模糊日期，不应该再另写一份正则表，你说对吗。

第三个，通知里写请于二零二六年十一月十五日前将材料报送至行政楼A301，日期是中文数字写的，模型能抽出来，但是后面转不成具体日期，日历加不进去，界面上就一直显示中文数字那一串。

我想请你改这三处。第一，模型返回的日期也要和本地一样做周期和教学周的检查，最好是在本地结果和模型结果合并之后统一查一次，这样不管这个值是从哪一步来的都拦得住。第二，判断是不是模糊日期那里，改成以换算函数能不能算为准，不要再另写一份正则表，免得两边永远对不齐。第三，中文数字的日期在转成具体日期之前先换成阿拉伯数字。

改完请帮我一起验证这几条。每周三和第12周前和半个月后和半年后和一季度后，跑完应该要么为空要么变成具体日期，不能再原样显示。反过来，请于11月5日前提交和三天后截止和本周五前交和明天交表这些正常说法必须照旧，不能被误伤。二零二六年十一月十五日要能变成2026年11月15日。

你不用把整个文件发给我，只告诉我改哪几处和改成什么就行。我们这个项目之前有一次你给了完整实现，结果覆盖掉了很多已经做好的功能，所以这次麻烦你一定只给改动片段。另外正则请全部用字符类写法，不要用反斜杠加数字那种，之前在这个项目上出过好几次问题。
```
