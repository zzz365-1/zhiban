# 026b 分类字段在无密钥时的显示

## 背景

本机取证：`extractNotice` 的返回里**没有 category 字段**（只有 deadline、time、location、
materials、audience）。所以无密钥走本地规则时，分类永远为空，界面显示「未识别」。

「未识别」这个说法在这里是错的：分类不是从原文里抄出来的值，没有分类是正常的，
不是识别失败。混用同一个词会让用户以为程序抽错了。

另外顶部还有一张「当前通知」卡片，内容和下面标题字段一字不差，白占一截高度。

## Prompt

```
还有一个小地方想请你帮忙看一下。

我发现结果面板最下面那个分类字段，在没有配密钥的时候一直显示未识别这三个字。我去查了一下，本地那个抽取模块返回的东西里确实没有分类这一项，所以它是空的。可是显示未识别感觉不太对，因为分类本来就不是从通知原文里抄出来的，它是模型自己归的类，没有分类是正常的，不像截止日期或者地点那样属于没抽出来。未识别这三个字用在截止日期和地点上是合适的，用在分类上容易让人以为程序抽错了。

我想请你把分类这一格的空值显示改成未分类这三个字，别的字段还是照旧显示未识别，不要一起改。

另外还有一件事想请你顺手看一下。结果面板最上面有一块写着当前通知的卡片，里面显示的是通知标题，可是下面字段里的标题那一格显示的也是同一个标题，等于同一个东西在上下显示了两次，白白占了一截高度。能不能把上面那块去掉，或者换成别的有用的信息。这个你判断，如果觉得去掉有风险就不动，告诉我一声就行。

老规矩，只改显示，不要动抽取相关的文件，不要新增依赖，那个存各种命令的文件里原有的命令一条都不能删。回复的时候不要把这个文件整个重新输出一遍，只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来。
```

## 验收要点（本机侧）

1. 分类为空时显示「未分类」，其余字段空值仍为「未识别」
2. 改动只落在结果面板组件
3. 全量 18 条离线命令 exit=0
