# 107 明确另存放行与变更对比原句定位

## 背景

最后一轮完整流程浏览器实测里抓到两处真实缺陷，都会直接影响演示。
第一处是单条疑似重复通知点明确另存后弹窗反复出现，通知存不进去。
第二处是变更对比弹窗里点依据原句没有反应，控制台报变量没定义。

## 本机已核验事实

见 tmp/107-facts.md，里面有真实函数签名，行号，源码片段，触发顺序和约束。
特别留意 handleParse 同时被当事件回调使用，事件对象不能被误当成放行标记。
补充通知的判断在查重之前，顺序不能动。

## 验收要点

第一，明确另存只放行这一次解析，弹窗不再回来，解析结果能正常保存成新的一条，
原来那条不被覆盖，也不自动删除。

第二，完全重复和标题相同两支的行为一字不改，跳过和取消都不增加通知。

第三，变更对比弹窗的回调参数补齐，点依据原句能选中原文那句话，找不到时安静返回，不抛异常。

第四，只输出成对改动片段，逐文件分开，不重写整个文件，package.json 一条命令都不动。

## Prompt

```
我录演示的时候又撞到两个地方不对，想请你帮我修一下，改动越小越好。第一个是明确另存。我把一条和已有通知只差几个字的通知粘进去，弹窗说疑似重复，我点明确另存，结果弹窗又原样弹回来了，再点还是弹回来，那条通知始终存不进去。完全重复点跳过是正常的，标题相同点取消也正常，只有明确另存这一条走不通。我希望点完就真的往下解析，解析结果能正常保存，而且确实是新的一条，不要覆盖原来那条。还有个地方要当心，同一个解析函数也被当成按钮的回调在用，浏览器可能把事件对象传进来，别把这个当成我要放行。第二个是补充通知的变更对比弹窗。我点表格里依据原句那一列的蓝色文字，想跳回原文看看，页面没反应，控制台里报一个变量没定义。其他按钮都正常，确认更新也能用。请把这个入口修好，点了要能在原文里选中那句话，原文里找不到的时候也别报错。补充通知先弹关联原通知那一步的顺序千万别动，别让它被查重挡住。只发成对改动片段，按文件分开，别重写整个文件，别的流程一个字都别动。
```
