# 006 - 接入大模型做语义解析（产品核心）

> **状态**：Key 已就位并通过本机实测，尚未发出。
> **写作原则**：参赛学生第一人称，逗号句号断句，不用括号星号破折号，不用 markdown 强调符号。

## 产品定位（架构师注）

001 到 005 解决的是「看得清、存得住、导得出」，但字段抽取仍依赖 003 的规则引擎。规则引擎的真实上限在验收时就暴露了：**只要通知写得随意一点就抓瞎**。这一侧的失败会向下游传导——没有正确的截止日期，004 的日历导出就是废的。

006 是整个产品的能力分水岭，也是「 AI 原生」而非「挂了个 AI 招牌」的唯一证明。

## 本机先验证过的事实（架构师实测，2026-10-31）

在写这条 Prompt 之前，已用真实 Key 跑通全链路，以下数据可直接进技术文档：

| 项目 | 实测结果 |
|---|---|
| 账户余额 | 9.99 元，充值部分 9.99，赠送 0 |
| 单次解析输入 | 约 210 tokens |
| 单次解析输出 | 约 308 tokens，**其中思考占用 252** |
| 单次耗时 | 2.0 到 2.4 秒 |
| 单次成本 | 约 0.04 分，9.99 元可解析约两万条 |
| JSON 可靠性 | `response_format: json_object` 下可直接解析 |
| 抽取质量 | 正确识别出「11月10日23:59 交初稿」为截止日期，而非文中更靠前的「11月15日答辩」 |

**最关键的一条发现**：`deepseek-flash` 是带思考过程的模型，输出 token 里约八成被思考占掉。
把上限设小会拿到**完全空白的正文**，且不会报错，极难察觉。这一点已写进 Prompt 让学生向 AI 描述现象而非给出结论。

自检脚本已落 `scripts/check-api-key.mjs`，注册为 `npm run check:key`，只打印掩码后的 Key 与消耗量，不打印明文。

## Prompt 正文

```
日历导出那个已经好了，谢谢。今天想把这个工具最核心的一块补上。
现在有个问题我一直绕不开。我们之前那个用规则匹配来识别的办法，碰到格式规整的通知还行，
但只要通知写得随意一点就抓瞎。比如有的通知写"下周三下午之前交"，有的直接写"十五号"，
还有的一句里塞好几个日期，正常人一眼就知道哪个才是真正要赶的那个时间点，程序就是分不出来。
我又试了好几条真实的通知，有相当一部分抽不全，或者直接抽错。这个问题不解决，
后面日历做得再漂亮也没意义，因为导进去的时间本身就是错的。
所以我申请了一个大模型的接口，听说理解这种自然语言比较在行，我想让它来干这件事。
我的账号里已经有额度了，配置文件也放好了，放在项目根目录一个叫 .env.local 的文件里，
里面就一行，变量名是 DEEPSEEK_API_KEY。模型我在控制台看到叫什么 flash 的，具体该用哪个你帮我定。
对了，我自己写了个小脚本放在 scripts 目录下面叫 check-api-key.mjs，
在终端跑一句就能看到余额还有多少，接口通不通，你写的时候如果要验证可以直接用它，不合适你就按你的来。
有几件事我想提前说一下。
第一是安全。我听说这个密钥绝对不能直接写在网页打开就能看到的代码里，人家按一下查看源代码就偷走了，
然后刷我的钱。这一块我完全不懂怎么处理，你帮我设计一个安全的办法，让密钥只在服务器那一边用到。
第二是万一出问题怎么办。网络有可能不好，也有可能别人拿到我这个项目压根没去配密钥。
这种时候能不能不用大模型，自动退回到我们之前那个规则识别的办法，结果差一点没关系，
但别整个页面报错崩掉，同学看着满屏红字会很慌。
第三是我先用脚本单独试了几次，发现一个挺奇怪的现象。有时候它明明应该返回东西，我拿到的却是空的，
多试几次又正常了。我隐约听人提过，好像是它得先在内部想一大堆东西才肯写答案，我也不确定是不是这么回事。
你写的时候帮我避开这个坑，如果需要我手动改哪个运行参数你直接说。
第四是费用。我不想每解析一条都要花钱，能用本地办法解决的就别去调它。
这块我拿不准怎么安排，是本地识别不出来的时候才去找它，还是加一个按钮让我自己决定什么时候用。
你给个建议，你觉得哪种更像一个正经产品。
第五是返回结果的处理。我要的还是现在这几个字段，标题截止日期地点摘要分类，
最好直接给我一个方便程序读取的格式，别返回一大段话让我还得自己再去里面抠字。
这一步先只做把大模型接进来这一件事，别的不用动。老规矩，每个文件的完整代码给我，我在 VS Code 里粘。
```

## 设计点

1. **用具体失败场景开场，而不是抽象需求**：「下周三下午之前交」「十五号」「一句里塞好几个日期」。
   这是规则引擎真实的失效案例，说出来才有说服力，也直接论证为什么必须上模型。
2. **安全问题由学生主动提出**：这是评分表「无严重安全漏洞」的加分项，而且必须是**参赛者自己先意识到**，
   不能事后补救。措辞保留了不懂的位置，由 AI 决定实现手段。
3. **降级兜底**：进阶的产品意识，同时也是演示时的保险。真实答辩环境断网也不会当场翻车。
4. **把现象说给 AI，把结论留给 AI**：描述「有时候返回是空的，多试几次又正常」，而不直接断言原因。
   万一判断有误，本机还有 `check:key` 能验出来。
5. **主动谈成本**：对自己的钱有概念，同时引出「本地优先，模型兜底」的混合架构，这是本项目架构叙事的核心。

## 验收标准

- 存在服务端接口承接解析请求，浏览器端任何位置都搜不到明文 Key
- 未配置 Key 或请求失败时，自动回落到本地规则引擎，页面不报错
- 对同一条通知，模型结果的字段结构与本地引擎保持一致，可无缝喂给日历导出
- 输出上限设置足以容纳思考开销，不出现静默返回空字符串
- 提供本地验证命令，不依赖页面点选
