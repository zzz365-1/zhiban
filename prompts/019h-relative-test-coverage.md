# 019h 相对日期新说法补进正式测试套件

## 背景

019g 已应用并通过验收，改动落在 `app/lib/relativeDate.js`：

1. 函数开头加截止后缀预处理，摘掉结尾的之前、以前、前，再摘掉时段词
2. 新增 `isQuantityRelativePhrase`，摘后缀后若是纯数量型短语返回 null
3. 补半个月（15 天）、半年（6 个自然月）、一季度（3 个自然月）三档

但 019g 交付的 30 条用例是一次性验证脚本，**跑完即弃，没有沉淀进正式套件**。
当前 `scripts/test-relative-dates.mjs` 里与本轮相关的只有「半个月后」一条
（且该条是本次验收中从"期望 null"改成正向断言的）。

**缺口**：半年后、一季度后、以及全部带「之前/前/以前」的说法，
目前功能可用但**没有任何正式用例守住**。以后误改不会被发现。

## 本轮目标

把三类说法补进 `scripts/test-relative-dates.mjs`，并覆盖多个基准日。

| 类别 | 说法 | 期望 |
|---|---|---|
| 后缀型（日期型带前） | 下周三之前、下周三前、本周五前、本周五中午前、本月底前、大后天之前 | 算出具体日期 |
| 数量型带前 | 三天前、三天之前、三天以前、两周前、一个月前 | **必须返回 null** |
| 新增单位 | 半个月后、半年后、一季度后、半年内、半个月之内、一季度内 | 算出具体日期 |

## 已知事实（本机实跑，供写期望值时参考）

基准 2026-11-02（周一）实测：

- 下周三 → 2026年11月11日
- 本周五 → 2026年11月6日
- 本月底 → 2026年11月30日
- 大后天 → 2026年11月5日
- 半个月后 → 2026年11月17日（15 天）
- 半年后 → 2027年5月2日（6 个自然月）
- 一季度后 → 2027年2月2日（3 个自然月）
- 三天前、三天之前、三天以前 → null

## 必须守住的两条

**一、数量型带「前」必须返回 null，绝不能算成未来日期。**
「三天前」说的是过去。若误当成加三天，界面会给出一个错误的截止日，
而用户完全无感——这是本项目判定为最危险的一类错误（Dec-021）。

**二、`isQuantityRelativePhrase` 目前是行为等价的冗余防御。**
本机注入实验证明：让它永远返回 false，所有测试**依然全绿**。
原因是摘掉后缀后剩下的「三天」本来就解析不了，提前 return null 与否结果相同。
本轮**不要求**删除它，但补充用例时不要误以为它已被验证有效。
若新用例能让它真正被覆盖，那很好；若不能，保持现状即可，不要为了凑覆盖而改语义。

## 验收要点

1. 三类说法全部进入正式套件，且多基准日覆盖（至少两个基准日）
2. 数量型带前的用例期望值严格为 null
3. 新增用例不得破坏现有 140 条（`test:relative` 必须仍为全绿且总数相应增加）
4. 金丝雀必须注入坏实现验证真会报红（Dec-024）
5. 测试脚本 import 生产模块，不得另抄一份（Dec-022）
6. 断言前不许归一化（Dec-023）
7. 正则一律用字符类，禁止反斜杠加数字（Dec-013）
8. package.json 原有命令一条不能删，改完跑全量回归（Dec-027）
9. 发现期望值本身写错不要直接改成实际值，要说一声（Dec-031 / Dec-039）
