# 013 面向对象与需提交材料两格补齐模型兜底

发现时间：2026-10-31，由用户在界面实测中发现。
现象：通知原文含「所有同学，都要参加」与「@所有人」，右栏「面向对象」仍显示「未识别」；
同一条通知的模型摘要里却写着「全体同学于10月31日上午八点在图书馆报告厅集合参加选举」，
说明模型理解到了对象，字段却是空的。

根因（本机 grep 与实跑确认，三处叠加）：
1. parsePrompt.js 里给模型的 json 字段只有 title、deadline、time、location、summary、category，
   从头到尾没有要求模型输出 audience 与 materials。
2. aiExtract.js 合并逻辑写的是 audience: base.audience || null，materials: base.materials || []，
   只取本地规则结果，模型结果一律丢弃。
3. extractNotice.js 的 extractAudience 词表只覆盖「全体X」「全校X」「各X」「本科生」等，
   不覆盖「所有同学」「所有人」「@所有人」，本机实测返回 null。

## 修复 Prompt

```text
我今天拿一条真实的通知试，发现有个字段一直认不出来，你帮我看看。
那条通知里写着「所有同学，都要参加」，最后还有一句艾特所有人。可是右边面向对象那一格显示的是「未识别」。我又试了几条，发现一个规律，写着「全体同学」或者「全校学生」的那些都能认出来，只有写着「所有同学」的认不出来。我猜是不是认的词表里面只有全体和全校这两种说法，没有把所有的算进去。
不过还有一件事我觉得更奇怪。同一条通知，摘要那一格它自己写的是全体同学于10月31日上午八点在图书馆报告厅集合参加选举。它明明知道是全体同学，可是面向对象那一格还是空的。所以我又怀疑，是不是这个字段根本就没有让它去填，或者它填了但是没有被用上。你帮我查一下是哪种情况。
还有材料那一格也有类似的问题。那条通知里写了要带身份证和选民证，还要带一支黑色笔，结果只认出来一个身份证，另外两样没认出来。
我希望这两个格子都能准一点。面向对象那边，像「所有同学」「所有人」还有艾特所有人这种说法，最好也认得出来。材料那边也是，原文写了几样就认出几样。
有个地方我拿不准。这两个格子可能既有本地认出来的结果，也有模型认出来的结果，到底该用哪个。地点那个格子好像是模型优先，这两个是不是也一样，你来判断。不过材料是个清单，可能不止一样东西，我的想法是，要么整套用模型认出来的，要么整套用本地认出来的，别把两边凑在一起，凑出来的清单原文里可能根本没那么写。
老规矩。给我一个能在终端直接跑的自检脚本，要验证「所有同学」「所有人」还有艾特所有人这些说法都能认出面向对象，还要验证原文写三样材料的时候三样都能认出来。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
另外提醒一下，你每次改 package.json 的时候，里面原来就有的命令要都留着，之前已经删过我两次了。
不要为了这些装新的库。
这一步就只修面向对象和需提交材料这两个格子，其他字段和其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 跑它给的自检脚本，要有通过失败统计，且故意错的用例必须报红。
2. 本机用截图那条原文实跑 extractNotice，确认 audience 不再是 null。
3. 检查 parsePrompt.js 的 json 字段列表里新增了 audience 与 materials。
4. 检查 aiExtract.js 合并逻辑是否改为模型优先。
5. 检查 max_tokens 是否仍给足 1200，新增字段后输出变长，防止静默截断（Dec-017）。
6. 检查 package.json 原有命令是否都还在（Dec-029）。
