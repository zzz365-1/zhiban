# 024 盲测缺陷修复（落款日期与地点截断）

## 背景

023 盲测用 20 条全新通知实测，发现两处静默错误。完整比对见 `docs/blind-report-023.md`。

两处都不报错，界面上看不出来，属于最危险的一类。

## Prompt

```
我又发现两个问题想请你帮我看看，这两个都是我拿二十条全新通知做测试的时候发现的。

第一个问题是通知末尾的落款日期被当成了截止日期。有一条通知写的是期末考试安排，全文没有任何报名或者交材料的截止时间，只是结尾写了某某大学教务处然后换行写了二零二五年六月三日，那个明显是发文日期不是要办事的日子。可是程序把这个日期填进了截止日期那一栏。我觉得这样挺危险的，因为日期那一栏一旦不是空的，程序就觉得本地已经抽好了，不会再让模型去改正，界面上就显示一个错的日期而且没有任何提示。我猜可能是因为匹配日期的时候只看格式像不像，没有看它出现在通知的什么位置，但我不太确定，你帮我查一下真正的原因是什么。

我想让落款那种发文日期不要被当成截止日期。不过有个地方我拿不准。如果一条通知真的只有一个日期，比如写的是请于六月二十日前把表交上去，那这个日期虽然只出现一次也应该要，它是真的截止时间。所以我的想法是不能简单地说只出现一次的日期就不要，而是要看它是不是出现在结尾落款那个位置。我不知道这样分对不对，如果你有更好的办法告诉我一声。

还有一个情况你一并考虑一下。有的通知落款是写在开头的，比如某某大学教务处写在第一行，日期写在第二行，也有的是日期和单位写在同一行。这几种情况你都帮我看看。

第二个问题是地点抽出来不完整。有一条通知写的是交至学院教学办公室然后圆括号里面写文科楼二零八，程序抽出来的是学院教学办公室圆括号文科楼，后面的门牌号和右边的括号都不见了。类似的还有好几条，都是在圆括号那里断掉。还有一条通知的标题是关于图书馆闭馆整理及借阅调整的通知，正文写的是图书馆将于七月八日至七月十二日闭馆，结果地点那一栏抽出来的是图书馆闭馆，多带了闭馆两个字，那两个字是动作不是地方。

想请你帮我改一下这两个地方。

有几点麻烦你注意一下。测试脚本要直接引用真正的那个模块，不要自己另外抄一份相似的来判断。要有故意写错的用例，而且它必须真的会报错，不能永远显示通过。写正则的时候一律用字符类，不要出现反斜杠加数字。不要加新的依赖包。那个存各种命令的文件里原有的命令一条都不能删，特别是那条查密钥的。改完请把所有命令都跑一遍，把结果一起给我。用例要把这一类说法尽可能列全，同时也要确认原来能抽的那些没有被弄坏。如果你发现某个用例的期望值本身写错了，不要直接把期望值改成实际值了事，要跟我说一声。

还有一件很重要的事，请你回复的时候不要把文件整个重新输出一遍，那个文件很长，你全部打出来我会看不过来，而且容易把本来没问题的地方也改坏。你只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。如果改动分散在好几处，就一处一处分开说清楚，每处都标明大概在第几行。

另外说明一下，我是新开的一个对话，之前聊过什么你这边看不到了，所以你只能根据我这次发给你的内容来判断，不要假设你还记得之前我们说过什么。如果我给的信息不够你判断，你直接问我，我去补。

我不太懂正则，如果哪里说得不对，你按你的判断来就好。
```

## 验收要点（本机侧）

1. 改动只落在 `app/lib/extractNotice.js`，删行数不得异常大于新增行数
2. 第 1 条盲测通知的截止日期必须为空，不得再出现落款日期
3. 第 10 条地点必须包含门牌号 208 且括号闭合
4. 第 17 条地点不得包含「闭馆」
5. 原有 20 条盲测中已正确的那 17 条日期不得被改坏
6. 注入验证：把落款日期恢复成可被抽中，相应用例必须报红
