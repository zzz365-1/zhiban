# 020e 让提示词检查器回到真正的轨道

## 背景

020d 交付后本机验收。挂住键盘输入这件事确实修好了，
但它换了一个更隐蔽的失败方式。

**挂住已解决。** `npm run check:prompt` 不传参数也能立刻出结果。

**但它实际上一个文件都没扫。** 输出第一行是：

```
扫描：0 个文件，干净：0 个，违规文件：0 个，违规：0 处
? 未发现违反正则规矩的提示词
```

prompts 目录下躺着 46 份归档，它一份都没读进去，却在最后报通过。
**这比当场报错更危险**，因为它把用户的注意力从"工具坏了"引到"我写对了"。
原版 `check-prompt-style.mjs` 同条件对照，照样能报出每一份的违规数量，一比就露馅。

**根因是文件名过滤那一行写了反斜杠转义。** 原文是：

```js
files = readdirSync(PROMPTS_DIR).filter((f) => /\\\\.(md|txt)$/i.test(f));
```

四个反斜杠在正则里表示两个字面反斜杠，再接一个任意字符，永远配不上任何文件名。
这恰好踩了本项目自己定下的规矩：不许写反斜杠转义，要用字符类。
工具自己犯了它要查的那个错。

**并且它查的根本不是该查的东西。** 新脚本只检查反斜杠类写法，
而 `check:prompt` 原本的职责是执行书写约束：正文只许出现汉字，ASCII 字母数字，
空格，换行与中文逗号句号问号，其余一律报出文件名行号与总数。
现在这套规则彻底没人执行了，等于把关卡悄悄撤了。

**磁盘上现在有两份干这件事的代码**，一份是原始实现但已无任何命令调用，
一份是新写的占着命令名。同名不同物，每次跑都不知道跑的是哪个。

**附带**：它自带的自检脚本是红的，一条用例期望同一行出现两处同类违规应计两处，
实际只计一处。

## 验收要点

1. 该命令必须自行遍历提示词归档目录，先把扫到的份数打出来，与目录里的实际数量一致
2. 扫到零份必须当场报错退出，绝不允许报"未发现"
3. 执行的必须是书写约束那一套：汉字，ASCII 字母数字，空格，换行，逗号句号问号，其余全部报出
4. 不再掺和反斜杠检查，那是另一条命令的职责
5. 历史归档只报告不计入退出码，019b 之后的新文档必须卡住
6. 两份同名用途的脚本只允许留一个，多余的删掉
7. 自检脚本自带那条红必须弄绿，不得靠改期望值凑绿
8. 全量十七个命令全绿，且任何一个都不许停在半路等键盘输入

## Prompt

```
这一轮还是接着上一轮没收拾干净的那件事，我自己试了一下，发现现在反倒更危险了，我说给你听。

我今天又敲了那条检查我写的话合不合规矩的命令。好消息是它不再卡住不动了，这一点谢谢你。可是它打出来的第一行把我吓了一跳，写的是扫描零个文件，干净零个，最后还来一句没发现问题，退出的时候也是报通过。我那一堆以前写好的提示词明明就在那个目录里躺着，四十六份一份不少，它一个都没看进去，却告诉我一切正常。这比当场报错还坑人，因为我看它报通过就真以为自己写对了。我也拿最早那份旧的检查器对着跑了一遍，人家老老实实告诉我哪几份里各有多少处问题，一对比就看出来这条新的其实什么也没查，我猜就是它挑文件名的那句话写得不对，一个也没配上。

所以我想让它做到这么几件事。一是这条命令必须自己把那个目录下所有存下来的提示词都读一遍，屏幕上要先明明白白打出这一共扫了多少份，这个数得跟我在文件夹里能数出来的数对得上。二是万一一个都没扫到，必须当场报错，说清楚一个文件都没读到，绝对不许再说没发现问题。三是它查的规矩必须是咱们当初定的那套，整段话里面除了汉字，英文字母，数字，空格和换行，就只许出现逗号句号问号这三个，多出任何一个别的符号都要报出来，说清楚是在哪一份的第几行，最后给一个总数。至于反斜杠那件事是旁边另一条命令的活，这条不要插手。

还有一点我得提醒你。里面有些是很早以前写的，那时候规矩还没定这么严，而且已经实实在在发给你用过了，没法回头改。这些老的要照旧报出来让我看见数量，但别因为它就不让这一轮过去。最近这批新写的就得卡住，一处都不许放过。

另外现在磁盘上有两份都是干这件事的，一个是我最早用的那个，一个是你后来新加的，它们不是同一个东西却占着同一个命令名，我每次都分不清自己跑的到底是哪一份。能不能只留一个，把没用的那份删掉，别留着两个互相打架。

最后，你上一轮给我的那个自检脚本到今天还是红的，有一条说一行里出现两处同样的错应该算两处，可它只报了一处。麻烦弄一弄，办法我听你的，但别直接把期望的数字改成实际跑出来的数字，那样等于把错题的答案改对了，下次真错就查不出来了。

以后凡是能在终端敲一条就出结果的命令，都不许停在半路等我键盘输入，这一点请你务必记住。

老规矩。给我一个能在终端直接跑的自检脚本，要引用页面真正在用的模块，不要另抄一份，要有期望值和通过失败的统计，还要有一条故意错的用例并且证明它真的会报红。不要为了这些装新的库。改完之后你帮我把之前那一堆检查脚本都跑一遍确认没坏，尤其是别再冒出任何一个一敲就卡住不动的，也别再冒出任何一个明明什么都没查却报通过的。相关的代码给我，我在 VS Code 里粘。
```
