# 096 多通知结果页补保存入口

## 背景

浏览器实测发现，批量解析结果出来后，右侧整块被多通知结果面板替换，
顶部状态栏连同保存按钮一起不渲染，面板头部却提示去点上面的保存到我的通知。
结果是两条都已解析，界面上却没有任何可以保存的入口。

## 本机已核验事实

页面在多通知且有批量结果时走结果面板分支，否则才走详情组件，
保存按钮只在详情组件的顶部状态栏里。结果面板目前只接受 items 一个参数，
头部右侧是一句静态提示文字。页面里 canSave 与 saveLabel 已经算好，
保存函数 handleSave 也已经能处理多通知分支。

## 验收要点

第一，结果面板头部有可点的保存按钮，文案与可保存条数一致。
第二，不能保存时按钮置灰，点击走原来的保存函数。
第三，单条模式的详情顶部按钮一行不改，解析流程不改。
第四，给第六轮脚本补一条钉住这条接线的静态断言。
第五，只输出成对改动片段，别重写整个文件。

## Prompt

```
多通知这条路我又试了一遍，结果面板出来了，两条都显示已解析，可我找遍整个页面也没找到保存到我的通知那个按钮。面板右上角还写着确认没问题就点上面的保存到我的通知，可上面只有搜索框和几个筛选按钮，压根没有保存。我切回单条模式，保存按钮就好好地在顶部。能不能帮我在多通知结果这一屏也放一个能点的保存按钮，条数要和结果里能存的对上，不能存的时候要置灰，点下去走原来那条保存逻辑。另外给这一轮的检查脚本补一条断言，钉住结果面板确实接上了这个按钮。别把单条那边的按钮弄坏，也别改解析流程。
```
