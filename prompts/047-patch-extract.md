# 047 补充通知要能抽出改了什么

## 背景

同学遇到一个真实场景。助学金那条通知已经存好了，里面有两件事，一件事是十一月五日下午五点前交纸质申请表，另一件事是十一月八日晚七点在行政楼A302会议室开评审会。后来学院又发了一条补充通知，说原定十一月八日的助学金评审会调整至十一月九日十九点，地点改为行政楼B201会议室，其余安排不变。

同学现在只能把这条补充通知当成一条全新的通知存进来，结果列表里多了一条，日历里多了一个点，可是原来那条评审会还是八号，一点没变。他想要的是，粘进来之后能看出来哪件事变了，原来是什么样，变成什么样，然后自己点一下确认才真的改，没提到的那些不动。

## 几条硬约束

第一，补充通知要先抽出来它说了哪些变更，这是这一轮的地基。

第二，抽不到新值的变更不许硬造，宁可什么都不改。

第三，原文说不清的地方要单独记下来，改之前必须先问同学，不能直接覆盖。

第四，依据原句要原样抄，不许自己拼。

## Prompt

```
这一轮我想做补充通知。同学遇到一个真实场景，我把经过和原话抄给你。

同学已经存好了一条助学金的通知，里面有两件事，一件事是十一月五日下午五点前把纸质申请表交到学生工作处A302办公室，另一件事是十一月八日晚七点在行政楼A302会议室开评审会。后来学院又发来一条补充通知，原话是这样的。关于助学金评审会的补充通知。换行。原定十一月八日的助学金评审会调整至十一月九日十九点，地点改为行政楼B201会议室，其余安排不变。

所以这一轮我想请你先帮我写一个新模块，放在抽取模块同一个目录下，文件名叫 noticePatch 点 js。里面主要一个函数，输入一条通知的原文，输出这条通知里说了哪些变更。

我先把我们这边的数据结构抄给你，免得你去猜。每条通知下面有一串事项，每个事项有这些字段。名称叫 name，是要做的那件事的名字，比如提交纸质申请表或者参加评审会。时间类型那个字段叫 time type 两个单词中间一个下划线，值是 deadline 或者 start。日期叫 date，是显示用的文字，比如十一月五日。时间叫 time，存成二十四小时制，比如十九点整那一项实际存的是十九比零零这种两位小时两位分钟的写法。地点叫 location。材料叫 materials，是一个数组，每一项是一个对象，对象里名字叫 name，准备好了没有叫 ready。办理状态叫 progress，值是待办理或者已办理或者无需办理。每个字段的状态放在一个叫 status 的对象里，日期那个键也叫 date，值有五种，分别表示没问题，原文没提，不适用，待确认，解析失败，这五种的英文拼写我放在下面单独给你的事实清单里，请你照抄不要自己拼。

changes 里每一项我要这些字段。field 表示改的是哪一项，值只能是 date 或者 time 或者 location 或者 materials 或者 cancel 这几种。op 表示是替换还是新增还是取消，值只能是 set 或者 add 或者 cancel 这几种。from 表示原文里提到的原来的值，没有就空。to 表示改完之后的值。quote 表示这句话在补充通知原文里的原句，要原样一个字不改地抄下来。start 和 end 表示这句话在补充通知原文里从第几个字到第几个字，从零开始数，end 那个位置不含。

下面说怎么认变更，这些是我一条一条试出来的，请你照着做。

第一，认变更句。这一句里出现调整，改为，改成，变更，推迟，延后，延期，顺延，提前，改到，改至，调整到，调整至，取消，不再，撤销，新增，增加，补充，另行通知这些说法里的任意一个，这一句就是变更句。

第二，日期变更。变更句里如果出现了原定两个字，原定后面跟着的那个日期是原来的值，放进 from，变更词后面紧跟的那个日期是新的值，放进 to。如果原文没写原定，那 from 就空着，to 取变更词后面那个日期。日期要保留原文的写法，比如十一月九日就原样存十一月九日，不要自己转成别的格式。

第三，时间变更。变更句里出现二十四小时制或者中文的时间说法，都作为新的时间放进 to，from 空着。中文说法要转成二十四小时制，晚上七点转成十九点整，下午五点转成十七点整，晚上六点半转成十八点三十分。项目里已经有一个把中文时间说法转成二十四小时制的现成函数，在依据那个模块里，请你直接复用它，不要自己另写一个算法，另写容易跟别处对不上。

第四，地点变更。这一句里出现地点两个字加上改为改成调整到调整至这一类词，后面那个地点是新的值。要注意把改为改成这一类动词前缀去掉，只要地点本身，比如原文写的是改为行政楼B201会议室，抽出来应该是行政楼B201会议室，不要把改为两个字带进去。

第五，材料变更。出现新增，增加，补充，需提交，还要交这一类说法，后面那个材料是新增加的材料，op 用 add，to 是一个数组。

第六，取消。出现取消，不再举行，不再举办，撤销这一类说法，op 用 cancel，field 用 cancel，to 空着。

第七，其余不变。出现其余安排不变，其他不变，其余不变，其他事项不变这一类说法，keepOthers 就置真。

第八，歧义。下面这三种情况要记进 ambiguities，因为改之前必须先问同学。一是有变更词但是新的值抽不出来。二是一句里出现两个或者更多日期，确定不了哪个才是新的。三是出现另行通知，待定，暂定，择期这一类说法，而且这一句里再没有别的具体值。

下面这些是我一条一条跑出来的结果，请你照着核对，不要自己另算。

第一条补充通知原文是，关于助学金评审会的补充通知。换行。原定十一月八日的助学金评审会调整至十一月九日十九点，地点改为行政楼B201会议室，其余安排不变。

这一条跑出来应该是这样。isPatch 是真。changes 有三项，第一项 field 是 date，op 是 set，from 是十一月八日，to 是十一月九日。第二项 field 是 time，op 是 set，from 空，to 是十九点整。第三项 field 是 location，op 是 set，from 空，to 是行政楼B201会议室。keepOthers 是真。targetHint 里应该有评审会这三个字。ambiguities 是空数组。

第二条原文是，请各班于十一月五日下午五点前将纸质申请表报送至学生工作处A302办公室。这一句里没有任何变更词，跑出来 isPatch 应该是假，changes 是空数组。

第三条原文是，评审会时间另行通知。这一句有变更的意思但是给不出新值，跑出来 isPatch 是真，changes 是空数组，ambiguities 里要有一条说明。

第四条原文是，原定十一月八日的评审会推迟至十一月十日举行。跑出来 changes 里应该有一项 field 是 date，from 是十一月八日，to 是十一月十日。

第五条原文是，评审会取消。跑出来 changes 里应该有一项 op 是 cancel，field 是 cancel。

还有两条请特别注意。第一，同一句里既有日期又有时间的时候，比如调整至十一月九日十九点，要拆成两项，一项日期一项时间，不要合成一项。第二，抽不到新值的变更不许硬造，宁可什么都不改，也不要拿今天或者随便一个日期凑数，凑出来的数字同学会当真。

请你只输出这个新模块的完整代码，因为是个新文件。改完我自己跑，跑不过我再回来找你。
```

## 本机验证结果

返修一轮。第一版把地点抽成了十一月九日十九点，因为它是从整句里找最早出现的改动词，
  而原句里最早的是调整至。另外把补充通知里的补充当成了材料变更，抽出一个叫通知的材料。
  落位前跑出来两处都不对，把现象抄回去，它改成以地点二字为锚点、退化时排除纯日期纯时间，
  并排除补充通知这类固定说法。
  新增 tmp/probe 五条用例全过，正则检查干净。
