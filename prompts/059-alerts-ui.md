# 059 第五轮之四 提醒的展示组件与三处接线

## 背景

冲突和截止集中已经能算出来了，现在要放到界面上。
要求是日历和事项卡片显示一致的提醒，不能一个地方一个样，也不能重复堆叠警告。

## 几条硬约束

第一，同一条提醒在事项卡片上只显示一行小标签，完整内容只在专门的区域展开，不许同一个警告在页面上叠好几遍。

第二，状态必须图标加文字一起表达，不能只靠颜色。

第三，提醒只是提醒，不许改任何时间数据。

第四，提醒要能点回原文，也就是点开对应事项的详情。

## Prompt

```
冲突和截止集中已经算出来了，现在把它放到界面上。你只做加东西，不要重做，也不要把已有文件整个重抄一遍，请只输出改动的那几段和新文件。

先交代算出来的提醒长什么样。逻辑目录下有一个新模块，导出的函数接收摊平后的事件，返回一串提醒。每条提醒是一个对象，上有 key 是唯一标识字符串，type 只有三种取值，overlap 表示确定的时间重叠，cluster 表示截止事项集中，needEndTime 表示缺结束时间，level 只有 warn 和 info 两种，title 是短标题，detail 是详细说明，items 是牵涉到的事件的精简信息数组，每个元素上有 noticeId，itemIndex，name，time，endTime，noticeTitle 这几个键。这个模块还导出一个把分钟数变成中文的辅助函数，六十分钟出来是一小时，九十分钟是一小时三十分。

请你新建一个组件文件放在组件目录下，名字叫 ScheduleAlerts 点 js，它是一个默认导出的函数组件，接收四个属性，alerts 是提醒数组，onOpenItem 是点击某条提醒上某个事项时的回调，onFillEndTime 是补充结束时间的回调，可能为空，className 是可选的附加类名。

这个组件的渲染规则请照下面做。整体是一个纵向列表，每条提醒渲染成一张卡片，卡片左侧有一个图标，图标请用图标库里现有的，overlap 用那个叹号三角的警告图标，cluster 用那个列表图标，needEndTime 用那个时钟图标。图标旁边是标题文字，标题右边放一个类型标签，overlap 写时间冲突，cluster 写截止事项集中，needEndTime 写结束时间待补充。注意这里有个硬要求，状态不能只靠颜色区分，所以每种类型除了颜色和图标，必须同时有上面这几个不同的文字，让人不看颜色也能分清。颜色方面 overlap 用琥珀色系，边框和背景都偏浅琥珀，文字深琥珀，另外两种用蓝色系，同样是浅背景加深蓝文字。

卡片第二行是详情文字，请用辅助文字那个灰色，字号小一号，不要截断，允许换行显示完整。

卡片第三行是牵涉到的事项，请横向排列一组小按钮，每个按钮上写事项的名字，点一下就调用 onOpenItem，把这条事项的 noticeId 和 itemIndex 一起传回去，这样用户就能跳到这条事项的详情看原文。这组按钮就是原文入口，必须要有，不然用户只知道撞车了不知道去哪条通知里看。按钮请用次要样式，描边加浅背景，不要抢主按钮的视觉。

只有 needEndTime 这种类型才在卡片底部显示补充结束时间的入口。做法是这样，默认显示一个次要样式的按钮，写补充结束时间四个字。点一下就在原地展开一个输入框和一个确定按钮。输入框请用原生的时间选择框，也就是类型为 time 的那种输入。用户输入完之后点确定，调用 onFillEndTime，三个参数依次是这条事项的 noticeId，itemIndex，还有用户输入的时间值。如果 onFillEndTime 是空的，整个这个入口就不要显示，避免出现点了没反应的按钮。展开和收起请用组件内部状态实现，每条提醒自己记自己的，不要互相影响。这里还有一句要说清，这个入口只是让用户自己补，不许在输入框里预填一个猜出来的时间，默认为空。

如果 alerts 是空数组或者根本没传，这个组件请直接返回空，不要渲染任何东西，也不要显示没有提醒这类提示，没有提醒就是没有，不要占地方。

接下来是三处接线。

第一处，事项卡片那个组件。它现在接收 event，now，selected，onOpen，onComplete，onToggleMaterial 这些属性。请你再加一个 alerts 属性，是提醒数组，可能为空。规则是，从这个数组里挑出和这个事项有关的那几条，判断办法是看提醒的 items 里有没有 noticeId 和 itemIndex 都和当前事项相同的元素。挑出来之后取最严重的那一条，严重程度的顺序是 overlap 最严重，cluster 次之，needEndTime 最后。然后在卡片上只显示一行很小的标签，标签左边是对应类型的图标，右边是这条提醒的标题文字加类型标签，颜色也按上面那套来。这里是最容易出错的地方，请你务必只显示一行，不管挑出来几条都只显示一行，不要把整张提醒卡片的内容在事项卡片里再渲染一遍，那样页面上一个警告会叠出好几遍，很难看。这一行标签也不要做成可点的，点了也没地方去，完整内容在下面两处看。如果挑不出来就不显示这一行。

第二处，日历页那个组件。它现在接收 notices，now，onOpenItem 三个属性，中间是月历，右边是一个侧栏显示选中那天的全部事项。请给它加两个属性，alerts 是提醒数组，onFillEndTime 是补充结束时间的回调。规则是在侧栏里，选中那天的事项列表上方，显示这一天的提醒。过滤办法是，只保留和当天事项有关的提醒，同样看提醒的 items 里有没有元素能和当天列表里某个事项的 noticeId 和 itemIndex 都对上。过滤出来之后就渲染上面那个新组件，把 onOpenItem 和 onFillEndTime 原样传下去。如果没有选中任何一天，或者过滤出来是空的，就不要渲染。请放在事项列表的上方，标题写这一天的提醒。

第三处，工作台首页那个组件。它现在接收 now，groups，stats，focus，selectedKey，onOpenItem，onComplete，onToggleMaterial，onFocusStat，onCreate 这些属性。请给它加 alerts 和 onFillEndTime 两个属性。规则是在页头下面，三张统计卡上面，显示一个提醒区。请用通用组件库里那个分区标题组件写一句需要关注，然后把上面那个新组件渲染出来，onOpenItem 和 onFillEndTime 原样传下去。如果 alerts 是空的，这一整块都不要渲染，包括那个分区标题，不要留一个空标题在那。

还有一条总的要求，这三处用到的提醒必须是同一份算出来的数据，由外层页面统一算一次再传进来，不要在三个组件里各算一遍，各算一遍迟早会不一致。所以这三个组件都只接收算好的结果，不要在自己内部去调那个计算函数。

最后一条，动效请沿用样式文件里已有的入场动画类名，时长和过渡都用已有的，并且尊重系统减少动态效果的偏好，也就是该加的地方加上那个 motion 开头的工具类。请不要新增关键帧。

请输出新组件的完整内容，以及三处接线的改动片段标明位置。改完我本机跑，跑不过再回来找你。
```
