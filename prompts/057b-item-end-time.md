# 057b 第五轮之三 事项层与模型提示词同步结束时间

## 背景

抽取那一层已经能拿到结束时间了，但事项对象上还没有这个字段，
界面和冲突计算都读不到。这一步把它接到事项上，并且让模型路径也返回同一个字段。

## 几条硬约束

第一，只有活动类事项才抽结束时间，截止类一律留空。

第二，抽不到就留空并标原因，不许猜时长。

第三，模型提示词里必须写明不许推测活动时长。

第四，只新增字段，不许动已有字段的含义。

## Prompt

```
抽取那一层已经改好了，现在把它接到事项上。你只改很小的地方，不要重写文件，也不要把已有文件整个重抄一遍，请只输出改动的那几段，标明落在哪几行附近。

先交代现在的代码长什么样。切事项那个文件里有一个主循环，它把通知按句切开，逐句判断这句话是手续类还是活动类，然后给这一句单独调一次抽取，拿到这一句自己的抽取结果，存在一个局部变量里。接着它选日期和时间，手续类优先取截止日期和截止时间，活动类优先取活动日期和活动时间，互相兜底。再往下它构造一个事项对象，上面有 name，timeType，timeTypeLabel，date，dateText，time，location，materials，suggestions，audience，progress，dateStatus，evidence，status，还有两个下划线开头的内部键。其中 status 是一个对象，里面有 date，time，location，materials，audience 这几个键。timeType 只有两个取值，一个是 deadline 表示办理截止，一个是 start 表示活动开始。

抽取那个文件里的总入口函数，返回对象上现在已经多了两个键，一个叫 endTime 是截止那条线上的结束时间，一个叫 eventEndTime 是活动那条线上的结束时间，都是小时两位数字英文冒号两位分钟的字符串，没有就是空。局部抽取结果里同样有这两个键。

请你改两处。

第一处，在选时间那几行的后面，再加一行选结束时间。规则是这样，先判断这一句是活动类还是手续类，只有活动类才要，手续类一律给空。活动类的取值顺序是优先取局部抽取结果上的 eventEndTime，取不到再退回局部抽取结果上的 endTime，都没有就是空。请你沿用上面选日期选时间那种同样的写法风格，不要另起一套。这里有个坑，局部抽取结果可能是空对象，也可能整个是空，请你和上面已有的代码一样先判空再取键，不要直接点下去，不然会报错。

第二处，在事项对象里加键。请在 time 那个键的后面加一个 endTime 键，值就是第一处算出来的那个，没有就填空。同时请在 status 那个对象里加一个 endTime 键，值的写法和 status 里其它键保持一致，抽到了就写 ok，没抽到就写 not 和 mentioned 两个英文词中间一个英文下划线。status 里现有的 date，time，location，materials，audience 五个键一个都不要动，也不要改动它们的取值逻辑。

还有一处必须一起改的是给模型的提示词模板。那个文件里有一段是告诉模型要返回哪些字段的，里面已经写了 time 和 eventTime 各自的含义。请你在 eventTime 那条的后面再加一条，字段名叫 eventEndTime，说明它是活动结束的具体时间，格式同样是小时两位数字英文冒号两位分钟，并且要写清楚两条硬要求，一条是原文没写结束时间就填 null，另一条是绝对不许根据常识去推测活动一般开多久，比如看到讲座就自己填两小时，这种一律填 null。那段里如果还有给模型的注意事项或者示例，请你也顺手补上对应的一句说明，但不要改动其他已有字段的描述和已有示例的结构。

还有一个地方请你顺手看一下，补充通知对比那个模块在把变更写回事项的时候，如果它改的是活动时间，那这条事项上原来的结束时间就作废了，因为新的安排结束时间并不知道。请你找到那里改时间的那个分支，在改时间的同时把这条事项上的 endTime 清成空，并且把它对应的状态键改成 not 和 mentioned 两个英文词中间一个英文下划线。如果它改的不是时间，就不要动结束时间。请你只在这一处加，不要动那个模块的其他逻辑。

最后一件事，这一步还是不要碰冲突判断，也不要碰界面。改完我本机跑，跑不过再回来找你。
```
