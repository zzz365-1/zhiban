# 011 复制日程摘要到剪贴板

**立项**：2026-10-31 17:45
**定位**：替代当初那条走不通的「导出 ics 再导进手机」路线，换成学生真正在用的渠道。

## 为什么做这个

用户实测：导出的 ics 在手机上导不进日历，身边同学也不用日历软件，
真实的信息渠道是班群 / QQ 群。一段能直接粘进群里的纯文本，
当场能演示成功，且本身就是产品洞察的证据。

这也是 008 决策里「保留代码不给界面入口」之后补上的**真正对外通路**。

## Prompt 正文

```
日历和手动修改都做好了，现在我想加一个能把事情发出去的功能。
我们学生平时根本不用日历软件，通知基本都是在班群里看的。所以我想加一个按钮，点一下就把最近几天要截止的事情整理成一段文字，直接复制到剪贴板，我粘到班群里就能发，全班都看得到。这样就不用再导出什么文件了。
整理出来的文字我希望是这个样子，第一行写个标题说明这是提醒，然后一条一行，每行要有日期、时间、事情的名字，如果知道地点和要带什么东西也写在后面。最后加一行小字，说明这是用我们这个工具自动整理出来的。
范围上我想能选最近三天还是最近七天，因为有时候想发一整周的安排。没有截止日期的那些通知就不要放进去，放了反而乱，已经过期的也不要。
按钮放在哪里我没想好，你看着办，别让界面变得乱糟糟的就行。
有个地方我不太确定。复制到剪贴板这个事，我记得浏览器好像有安全限制，有时候会失败。如果失败了要告诉我复制失败，不要什么都不说，更不要假装成功了。最好失败的时候能把那段文字显示出来，让我自己选中复制。
老规矩。给我一个能在终端直接跑的自检脚本，验证整理出来的文字格式对不对，三天和七天这两个范围筛得对不对，过期的和没有日期的确实没进去。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
不要为了这些装新的库。
这一步就只做复制这一件事，批量粘贴那些我们后面再做，这次不要顺手加上去。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 有按钮触发复制，范围可选三天 / 七天。
2. 文本含日期、时间、事项名，地点与材料有则带上，末尾有来源小字。
3. 已过期与无截止日期的条目不进入文本。
4. 复制失败时有明确提示，并能退化为手动选中复制，不静默假装成功。
5. 自检脚本 import 生产模块，含故意错的用例且被判定失败。
6. 没有新增依赖。
