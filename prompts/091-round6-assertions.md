# 091 第六轮回归断言与第五轮旧判据收敛

## 背景

087 到 090 四段改动落位后，31 条离线命令里第五轮有一条静态断言报红，
说的是多通知逐条解析也传基准没过。新写法先把基准存成变量再传给解析函数，值其实仍然传了，
旧断言盯死了原来的字面写法。按项目惯例不能删断言，也不能把它改成永远通过。

## 本机已核验事实

第五轮断言写的是页面源码里必须有 parseOne 调用时直接内联对象。
落位后的写法是先声明基准变量，再调用 parseOne 并传这个变量，事项函数也用同一个变量。

## 验收要点

第一，旧断言改成认新写法，但仍要证明基准确实传进解析函数与事项函数。
第二，新增第六轮命令，钉住本轮四组修复的具体行为。
第三，动态断言必须调用生产模块，静态断言读真实源码，不许另抄一份相似实现。
第四，留两条故意会失败的金丝雀，期待报差异且不计入业务失败数。
第五，只给测试脚本和命令清单里要加的那一行。

## Prompt

```
我把四段改动放进去以后跑了全量回归，三十一条命令里有一条报红了，说的是多通知逐条解析也传基准这条检查没过。我看了下，新的写法先把基准存成一个变量再传给解析函数，值其实还是传了，是那条检查盯死了老写法。我不想直接把检查删掉，也不想把它改成永远通过，能不能帮我把这条检查改成认新写法但仍然证明基准真的传进去了。另外我还想给这一轮新加一组检查，把标题定位用显示文字，摘要分类不做原文核对，确认切分后清掉待重新解析标记，批量每条补事项，服务端不丢活动日期活动时间和结束时间，来源标签写本地识别，日期没认出来时按钮禁用，依据原句不是下标对象时不乱选这些都钉住。新检查要真的读生产代码和调用生产模块，别另抄一份相似实现，还要留两条故意会失败的对照证明它真会报红。只给我要改的检查脚本和加到命令清单里的那一行。
```
