# 100 各页面统一时间类型与具体时刻说明

## 背景

单条详情里的事项卡已经能正确把讲座的 14:30 显示成开始时间，
但解析页的字段标签写死了截止日期，多通知批量结果面板也写死了一行叫截止，
于是同一条讲座通知在不同页面一会儿是开始一会儿是截止。
另外只有日期的通知，解析页时间那一格现在显示未识别，跟抽取失败混在一起，
应该明确写具体时刻未说明。

## 本机已核验事实

讲座通知原文是学术讲座通知，下一行是学术讲座定于11月14日14:30在图书馆报告厅举行。
本机实跑抽取结果 deadline 是 11月14日，time 是 14:30，eventDate 是空，eventTime 是空，
事项层拆出一条事项，名字参加讲座，timeType 是 start，timeTypeLabel 是开始时间。
也就是说这条通知的 deadline 字段装的实际是活动举办日，不是提交截止日。

助学金通知原文有三行，标题是关于2026年国家助学金评审工作安排的通知，
第二行是各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室，
第三行是评审会定于11月8日晚7点在行政楼A302会议室召开。
抽取结果 deadline 是 11月5日，time 是 17:00，eventDate 是 11月8日，eventTime 是 19:00。
事项层拆出两条，一条 timeType 是 deadline，一条是 start。
这条通知的 deadline 字段确实就是提交截止日，标签不能改。

只有日期的两条通知，抽取结果 time 是空，事项层 timeType 是 deadline。

判定口径定为，看分析结果里的事项数组，只要里面有一条是截止类型就按截止处理，
一条截止都没有但有活动开始类型就按开始处理，没有事项数组的老数据保持原来的截止说法。
这个判定请放在事项层模块里做成一个导出函数，解析页和批量结果面板都引用它，
不要两边各写一遍，免得以后又不一致。

具体时刻未说明这句话在 app/lib/deadline.js 里已经导出成 NO_TIME_NOTE，请直接引用。

## 涉及文件与当前关键行

解析页 app/components/AnalysisPanel.js 是 LF。
第12到41行 FIELDS 数组，deadline 的 label 是截止日期，time 的 label 是具体时间，
eventDate 与 eventTime 带 hideWhenEmpty。
第44到62行 getDisplayText，摘要返回暂无摘要，分类返回未分类，其余空值返回未识别。
第267到275行算出 text 和 isEmpty，isEmpty 目前认 未识别 未分类 暂无摘要 三种。
第292到296行渲染 field.label。
第127到132行 handleLocate 里 isEmpty 就直接返回，不做定位也不报错。

批量结果面板 app/components/MultiResultPanel.js 是 LF。
第72到73行 const when = [a.deadline, a.time].filter(Boolean).join(" ");
第93行 <Row label="截止" value={when} />，第94行是活动那一行。
Row 组件在第38到46行，value 为空就整行不渲染。
组件收到 items，每项的 analysis 里带着 items 事项数组。

事项卡 app/components/ItemsPanel.js 第186到189行，parts 依次放 timeTypeLabel、date、time，
然后用空格拼起来显示。事项的 time 为空时这里没有说明文字。

事项层模块 app/lib/noticeItems.js 已导出 classifySentence、normalizeMaterials、
SUGGESTION_SOURCE_SYSTEM、buildItems 等，把新函数加在文件靠前的辅助区即可。

## 验收要点

第一，讲座那条在解析页和批量结果面板都表达为开始，不出现提交截止或办理截止的含义。

第二，助学金那条同时有报名截止和活动开始，两个事项各自的时间地点材料不变，
解析页的截止日期标签保持原样，零回归。

第三，只有日期的通知，解析页时间那一格显示具体时刻未说明而不是未识别，
这一格不许被当成有值去定位原文，也不许弹出原文里没找到的红字。
批量结果面板和事项卡也要带上这句说明。

第四，有明确时刻的通知，这几个页面原本显示什么还是什么，一个字不变。

第五，判定函数放在事项层模块导出，两处引用同一份，别新建名字差不多的模块。

第六，只输出成对改动片段，逐文件分开写，不重写整个文件。
