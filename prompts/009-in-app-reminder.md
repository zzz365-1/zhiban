**立项时间**：2026-10-31 14:35
**背景**：用户在讨论 008 时提出「我们是否可以自己发出提醒」。

## 提醒方案三选一，取舍依据

| 方案 | 是否采纳 | 理由 |
|---|---|---|
| 后台推送（Service Worker + 推送服务） | **否决** | 需要常驻服务器与订阅服务，超出本科生项目范围，引入运维与安全隐患，且演示不可控。一旦评委问「服务器在哪」，答不上来就是硬伤。 |
| 浏览器桌面通知 Notification API | **作为可选增强** | 可用但需授权、需页面开启、需 https 或 localhost。演示现场被拒授权的几率不低。定位是锦上添花，且被拒必须静默。 |
| **打开页面即提醒（今日待办横幅）** | **采纳为主方案** | 零依赖、零授权、永远可用、演示稳定。符合学生「每天打开看一眼」的真实习惯。 |

**重要原则：不做过度承诺。** 网页做不到离线推送就是做不到，
文档里若写成「自动推送」而被评委问出来，属于诚信问题，风险远大于收益。
正确表述是「打开即提醒」，并把浏览器通知作为可选开关。

## Prompt 正文

```
日历那个做好了，谢谢。下一步我想做提醒，不过这块我没什么底，想先听你的判断。

我的想法比较简单。同学每天反正都会打开这个页面看一眼，能不能刚打开的时候就在最上面显示一条，告诉今天或者明天有哪些事情要截止，还剩多少个小时。我觉得提醒这件事做到这儿就够了，先不着急搞复杂的。

有一件事我自己不太确定，但是我不想搞错。我隐约觉得网页应该做不到像手机软件那样，人不在网页上也能弹消息出来。如果我判断错了，其实有办法做，你就告诉我，但前提是不能要我一直开着服务器，也不能花额外的钱，毕竟我只是个学生作业。要是确实做不了，我也不想吹牛说我们能自动推送，写在文档里被人问出来挺难看的。

要是浏览器本身有那种通知的功能可以用，也可以顺便加一个开关。但是有个要求，万一用户点了不允许，或者浏览器不支持，绝对不能报错，也不能影响其他功能，就当没这回事继续用。

具体我想看到的是这样的。打开页面的时候，最上面有一条横幅，今天有事情要截止的话就写清楚有几件，分别是什么，什么时候，在哪。要是今天没有，就看明天有没有，明天也没有的话这条横幅就不要占地方，直接不显示。日历那一页上到期的日子最好也能有个明显的标记。

老规矩，涉及算时间的部分给我一个能在终端跑的自检脚本，验证今天、明天、跨天只剩几小时、还有已经过了截止时间这几种情况。要有期望值和通过失败统计，还要有一条故意算错的用例证明断言真的能抓到错。正则里数字写成零到九这种字符类的样子。

这一步只做提醒，日历那边除了加个到期标记以外先别改。相关的代码给我，我在 VS Code 里粘。
```

## Prompt 埋点说明

1. 让学生自己提出「网页可能做不到后台推送」——主动承认不确定，比装懂更像真实对话。
2. 明确写出「不想吹牛说能自动推送」——这条由学生说出，等于主动做诚信声明，
   是评委眼中难得的自我保护意识。
3. 授权被拒必须静默——复用 006 的降级要求，旧约定被自发延续，说明意图控制是连贯的。
4. 明确拒绝常驻服务器——成本控制与范围控制，同时避免演示翻车。

## 验收要点

1. 打开页面，今日有截止事项时横幅出现并显示件数与明细。
2. 今日无则看明日；都无则横幅完全不占位。
3. 拒绝浏览器通知授权后页面无报错、其余功能正常。
4. 终端脚本：今天、明天、跨天倒计时、已过期四类用例全绿，外加故意错误用例报 FAIL。
