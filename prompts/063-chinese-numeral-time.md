# 063 第一轮自检 中文数字时间抽不出来

## 背景

第一轮自检时，用一批没有参与过开发的新通知跑生产模块，
发现一个很常见的写法抽不出时间。
原文写的是活动于下周三下午三点在大学生活动中心208室开展，
抽出来的时间字段是空的。
又试了几条，讲座定于11月14日下午两点半，上午九点，晚上七点，
这些中文数字的写法全部抽空。

反过来，写下午3点半，下午2点，下午5点，下午3点这种带阿拉伯数字的，
全都能抽出来。所以毛病只出在中文数字上。

这条不是小事，因为校园通知里中文数字时间非常常见，
抽不出时间就没有办法生成日历提醒，事项卡片上也缺关键信息。

## 本机已核验事实

抽取模块里，时间匹配用的是三个正则片段常量，
一个管上午下午晚上加数字，一个管冒号写法，一个管数字加点。
三个片段里写的都是方括号零到九这种字符类，
所以中文数字一个都匹配不上。

相对日期那条已经单独查过，不是缺陷。
下周三在传入基准日期之后能正确算成2026年11月11日，
之前抽成空是因为我在测试脚本里把参数名写错了，已经排除。

## 验收要点

第一，下午两点半要抽成十四点三十分，晚上七点要抽成十九点，
下午三点抽成十五点，上午九点抽成九点，十点抽成十点，十二点抽成十二点。

第二，原来能抽的阿拉伯数字写法一条都不能坏。

第三，十点十一点十二点这种两位数的不能算错。

第四，改完跑全量回归，所有离线命令都要过。

## Prompt

```
我发现我的程序有个毛病，很多校园通知里写的是下午两点半或者晚上七点这种说法，我的程序抽不出时间，时间字段一直是空的。我又试了试，发现写下午3点半或者下午2点这种带阿拉伯数字的就能抽出来，写中文数字就不行。

能不能帮我改一下，让下面这些写法都能抽出时间来。下午两点半是十四点三十分，上午九点是九点，晚上七点是十九点，下午三点是十五点，两点半是两点三十分，十点是十点，十二点是十二点。

我自己的想法是，在匹配之前先把中文数字换成阿拉伯数字，然后再走原来的匹配逻辑，你看看这个办法行不行，或者你有更稳妥的办法也可以。

有几条请你严格守住。第一，原来能抽出来的那些阿拉伯数字写法一条都不能坏。第二，十点十一点十二点这种两位数的别算错，十点就是十点不是一点。第三，正则请一律用字符类，不要出现反斜杠加数字的写法，我这边有个检查命令会卡这个。第四，只改时间抽取这一块，别的地方不要动。

请只给我需要改的那几段代码，标明文件路径和要替换的原文，不要输出整份文件。改完我本机跑全量回归，跑不过再回来找你。
```
