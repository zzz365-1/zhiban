# 012b 修分割边界判据不一致

**立项**：2026-10-31 20:40
**定位**：012 的自检脚本抓到了 AI 自己写的代码与自己写的用例互相矛盾，两条 FAIL。

## 本机实测结论（未采信表面结果）

`npm run test:batch` → **16 通过 / 2 失败**，金丝雀正常咬人。
两条失败是同一个根因，用例 11 与 12：

- 场景：一段文字里出现很多次「请于」，但中间没有空行、也没有多个标题，看不出该在哪断开。
- 期望：`ok: false`（拒绝硬拆）
- 实际：`ok: true`（当成一条放了过去）

根因：`splitNotices.js` 的判据是 `text.length > 800 && countSubstring(text, "请于") >= 2`，
而用例构造的文本只有约 207 字，字数条件不满足，于是走了「像单条」分支。
**即 AI 写用例时心中的判据与写代码时写的判据不是一个。**

这是好事：断言真的咬到了不一致，不是假绿。

## 本机已代为修掉的两处（无需再让 AI 改）

1. `app/lib/sprseOne.js` 文件名笔误，而 `BatchDialog.js` 与 `page.js` 都 import `parseOne`，
   **页面当时根本编译不过**。已重命名为 `parseOne.js` 并验证模块可加载。
2. `test:batch` 命令未注册进 package.json（Dec-027 第三次出现），已补。
   **注**：本次两条是纯笔误与遗漏，代为修复；边界判据这类需判断的问题仍交还 AI。
