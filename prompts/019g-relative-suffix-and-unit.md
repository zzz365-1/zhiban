# 019g 相对日期的后缀与单位边界

## 背景

018 把相对日期换算本地化之后，019 补齐了数量型，但边界没收干净。
本机实测（基准 2026-11-02 周一）当前真实状态：

能算：三天后、两天后、一周内、两周后、一个月后、下周三、十五天后、两周之内、一个月之内

返回空：下周三之前、下周三前、本周五中午前、三天之前、三天以前、
本月底前、大后天之前、半年后、半个月后、一季度后

根因是全串精确匹配：结尾多出「之前」「前」「以前」这类限定词后无法匹配，
于是返回 null 并回落给模型做日期算术——正是 018 想消灭的那类概率性错误。

老师明确点名的边界就是这一类：两天后、一周内、下周三之前。

## 设计口径

**必须区分的两类，不能一刀切：**

- 日期型说法后面带「前/之前/以前」（下周三前、本月底前、大后天之前）→
  语义就是那一天，应当剥掉后缀按原日期算
- 数量型说法后面带「前」（三天前）→ **语义是过去时，不是将来的截止日**，
  必须保持返回 null，绝不可当成加三天。这是本轮最大的陷阱
- 数量型后面带「之内/以内/内/之后/以后/后」的现有逻辑不动

**宁缺勿滥优先于覆盖**：凡语义拿不准的，一律返回 null 交给模型，
不允许为了覆盖率去猜。假日期比空值危险得多（Dec-021）。

**单位补齐**：半个月、半年、一季度这类语义确定的中文单位一并补上，
但必须同时验证没把现有能算的说法弄坏（Dec-034 防误杀）。

## 验收要点

1. 下周三之前、下周三前、本周五中午前、本月底前、大后天之前 均能算出日期
2. 三天前 必须仍返回 null（不许算成加三天）
3. 原有能算的九种说法一个都不能坏
4. 半个月后、半年后、一季度后 若纳入，结果须与语义一致
5. 测试脚本必须 import 生产模块，不得另抄（Dec-022）
6. 必须含故意写错的金丝雀，且注入坏实现后真的会报红（Dec-024）
7. 正则一律用字符类，禁止反斜杠加数字（Dec-013）
8. 那条查密钥的命令等原有命令一条都不能删，改完跑全量回归（Dec-027）
9. 禁止把期望值改成实际值了事（Dec-031 / Dec-039）
