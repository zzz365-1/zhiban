# 062 第六轮之二 另行通知误判窄口径修复

## 背景

第六轮整体验收时，粘贴一条很普通的信息缺失通知，
原文写的是时间另行通知，地点待定，
点解析之后程序没有走正常解析，而是弹出请选择它要修改的原通知，
把一条新通知劫持进了补充通知关联流程。

本机取证确认，变更词表里有一个词叫另行通知，
它命中了待定类说法那一段，整句被判成变更句。
这个词本来是留给真正的补充通知用的，
比如原定十一月八日的评审会时间另行通知，
那种确实是变更。但一条从头到尾没有提到原安排的新通知里，
这句话只是在说时间待公布，不是改时间。

第四轮修逾期不再受理时用的是同一套路子，只排掉一组很窄的固定说法，
不扩成通用动作词黑名单，免得误伤单位名。这一轮照办。

## 几条硬约束

第一，不许把另行通知这个词从词表里整个删掉，
原定某某时间另行通知这类真正的补充通知必须照常识别。

第二，不许用通用动作词黑名单，也不许按标题里有没有补充两个字来猜。

第三，改动只在补充通知抽取模块里，测试脚本补两条回归用例，
其他文件一个都不要碰。

第四，改完必须能本机跑通 test 短横线 patch，原有二十三条一条都不能挂。

## 本机已核验事实

补充通知抽取模块里，变更词表的最后一项是另行通知。
另有一个待定说法数组，里面是另行通知，待定，暂定，择期。
主函数叫 buildNoticePatch，先把原文切成句，
逐句用 isPatchSentence 判断，命中就把 isPatch 置为真。
顶层还有一个固定说法过滤，叫 RECEIPT_NOT_WORDS，
是第四轮为逾期不再受理加的，那一组只排掉五组收件说明。
测试脚本在 scripts 目录下，叫 test 短横线 patch 点 mjs，现有二十三条用例。

交给正常解析流程去处理，界面会显示待确认，这正是我想要的。

断言 buildNoticePatch 返回的 isPatch 是假，changes 长度是零。
第二条，原文是关于助学金评审会的补充通知，换行，
原定十一月八日的助学金评审会时间另行通知，其余安排不变，
断言 isPatch 是真，别让这道新防线把真正的补充通知也拦掉。
用例里的日期请按这个测试脚本现有的写法来，别引入新的日期基准。

请只输出这两个文件的改动片段，标明文件路径和要替换的原文，
不要输出整份文件。原有二十三条用例一条都不能挂，改完我本机跑，
跑不过再回来找你。
