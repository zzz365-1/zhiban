# 013e 材料字段收官：穷举列举触发词变体

## 背景

013d 自测 18/0、全量回归八条命令全绿、跨路径注入 18 条中 16 通过。
失败两条经对比证实**均为遗留，非 013d 引入**（013d 前后输出一致）。

前四轮的教训是同一个模式：每轮修好一部分变体，下一轮冒出没覆盖到的变体。
013b 修了去标点漏了括号，013c 修了「和」连接漏了顿号列举，
013d 修了「材料：」与部分「材料如下：」，独漏了「需带材料如下：」。

本轮要求**穷举变体**，终结这种打地鼠。

## Prompt

```
上次那个材料改完以后十八条全过了，之前那四个也都对了。不过我又试了几条，还有两个小的。
第一个。一条通知写着，需带材料如下：身份证、学生证、一寸照片、黑色签字笔。结果认出来的第一样是材料如下：身份证，把前面这五个字也带上了。可是我试过另外两句是对的，一句是需提交材料：身份证、学生证，另一句是请交材料如下：申请表、汇总表，这两句都没问题。我猜可能是你只认了其中几种说法，这一句漏了。
常见的说法其实有好几种，我想了想大概有这些，材料加冒号，材料如下加冒号，材料包括加冒号，附件加冒号，附件包括加冒号，需带材料加冒号，还有到办公室交材料加冒号。能不能把这些都试一遍，都要能把前面那些字去掉，只留下真正要带的东西。你要是还想到别的常见说法，也一起加上。
第二个。一条通知写着，请携带二寸照片两张。认出来是二寸照片两张，后面那个两张说的是数量，不是名字的一部分。我们只想知道要带二寸照片，几张不重要。能不能把后面的数量去掉，一张两张三张这些都不要留着。
老规矩。给我一个能在终端直接跑的自检脚本，要验证那几种说法每一种都不会把前面的字带进清单，还要验证后面的数量会被去掉。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
另外提醒一下，你每次改 package.json 的时候，里面原来就有的命令要都留着。
不要为了这些装新的库。
这一步就只修材料这一个格子，其他字段和其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 穷举的每一种列举说法都要单独有用例，不许只测其中一两种
2. 注入 L 与 P 两个场景必须成立
3. 防误杀：正常句子不得被抽出一堆垃圾（如「请各班班长于周五前完成统计。」应为空）
4. 全量回归八条命令均需通过，原有 npm 命令全部保留
