## 根因定位（已本机复现）

007c 新增的规则 4 要求「多个日期时取截止/报送/提交/报名前的日期，而不是活动开始日期」。
该规则在**通知里没有明显的截止动词时会被过度应用**——模型索性返回 null。

对照实验，同一份共享提示词：

| 输入 | AI deadline |
|---|---|
| 于下周三中午前将名单**报送**至就业邮箱 | 2026年11月4日 |
| **定于**下周三下午3点**召开**就业推进会 | 空 |
| **定于**2026年11月20日上午8:30**进行** | 空 |
| **定于**下周一下午3点**召开**推进会 | 空 |
| **定于**本周三下午3点**召开**推进会 | 空 |

结论：**有无「截止类动词」是唯一变量**。会议类、活动类通知通常没有报送动作，
出席本身就是截止时间，却被整条丢弃。

另一处：`scripts/test-relative-dates.mjs` 只断言 AI 原始输出，未走 `extractNotice` + `mergeAIResult`
这条真实合并链路，因此第 7 条出现**假失败**（本地规则本可给出 2026年11月20日，线上其实正确）。
Dec-022 的延伸：**不仅要共享提示词，还要测真实合并后的结果。**

## Prompt 正文

```
这一步接着刚那十八条例的测试结果往下说，有三条没过，我把原因摸清楚了。

先说结论，这三条其实是同一个毛病。那几条没过的通知有个共同点，里面都没有「报送」「提交」「截止」「报名」这类词，全都是「定于某日几点开会」「定于某日几点进行」这种写法。我猜是上次加的那条规则造成的，就是让它在遇到多个日期的时候挑那个需要赶的日期、不要挑活动开始日期。这条规则本身是对的，但现在碰到根本没有截止动作的通知，它就不敢给答案了，干脆返回空。

可是大学里大把通知就是这样的。开会、讲座、采集、体检、演练，全都是写「定于某月某日几点在某地举行」，本身就不存在交材料这回事。对收到通知的人来说，那个时间点就是他必须到场的时间，这一天就是他的截止日期。现在返回空的话，这类通知等于白解析了，前半段的努力全白费。

我想改成这样，你帮我看看合不合理。原文里如果确实有截止动作，比如写明在某日几点前报送，那就照现在的规则挑那个日期；如果通篇找不到任何一个截止类的动作，就把那场活动本身的日期当成截止日期，别返回空。这样两类通知都能用。至于那种既有活动日期又有报送日期的，还是按现在的办法挑要赶的那个。
```
