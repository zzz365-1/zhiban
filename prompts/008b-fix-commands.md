# 008b 补齐两条空壳命令

**立项**：2026-10-31 16:50
**触发**：本机验收时发现，008 交付在 package.json 注册了两条命令，但都没有真实实现。

## 本机实测的硬证据

| 命令 | 现象 | 性质 |
|---|---|---|
| npm run test:calendar | 报 Cannot find module scripts/test-calendar.mjs | 响亮失败，脚本没给 |
| npm run export:ics | 退出码 0，一行输出都没有 | 静默失败，scripts/export-ics.mjs 是 0 字节空文件 |

第二条比第一条危险。空文件不报错，看起来像成功，实际什么都没做。

**已确认仍然真实的部分**：`app/lib/generateICS.js` 被 `scripts/validate-ics.mjs` 真实引用，
`npm run validate:ics` 跑得通并通过结构检查，所以标准格式那块工程证据没有丢，
坏的只是 export:ics 这一条命令入口。

**已确认月历与待办算法本身正确**（本机 import 生产模块实跑）：
闰年二月 29 / 28 / 29 / 28 全对，跨年十二月对，一号是星期天的月份对，
格数永远是 7 的倍数，待办三天阈值与小时换算符合预期。

## 另一个实测到的显示瑕疵

距离截止 23 小时 50 分时显示「剩 24 小时」，`Math.ceil` 把不足一天进位成了一整天。

## Prompt 正文

```
上次做完日历和待办以后，我在终端试着跑了你给的命令，发现有两个对不上，你帮我看看。
一个是 npm run test:calendar。package.json 里确实有这条命令，可是我一跑，终端说找不到 scripts/test-calendar.mjs，也就是说这个脚本你没给我。我记得当时我特意要过能在终端直接跑的自检脚本，专门验证月历格子和待办清单的算法，这次麻烦把它补上。
另一个更要命。npm run export:ics 我也跑了，它没报错，看起来是成功的，但是一行字都没输出。我去看了那个文件，发现 scripts/export-ics.mjs 是个零字节的空文件。这种最吓人，因为它不报错，看着像成功，其实什么都没干。导出这个功能我们不打算在界面上放按钮，是留在终端里用的，那它至少得真能跑出点东西来。你把它真正实现一下，跑完能真的生成一个文件，并且在终端告诉我文件生成在哪了。
自检脚本还是老规矩。要引用页面真正在用的那两个模块，不要另外抄一份差不多的，我们之前在这上面吃过亏，抄的那份结论和真实的对不上，比没有脚本还危险。要覆盖闰年二月，2024 年二月是二十九天，1900 年是二十八天，2000 年是二十九天，还要覆盖跨年的十二月、一号正好是星期天、还有每个月天数不一样这几种。待办那边要验证三天这条线，不到一天的按小时算，已经过期的不能出现，没有截止日期的也不能出现。脚本要有期望值和通过失败的统计，还要有一条故意算错的用例，证明这套断言真的会报错。
另外我自己试出一个怪事。我拿一条通知试，距离截止还剩二十三个小时五十分钟的时候，界面上显示的是剩二十四小时，读起来像整整一天，其实还差十分钟才到。能不能改成不到一天的时候最多显示二十三小时。
还是那句，不要为了这些装新库。正则里数字写成零到九这种字符类的样子，不要用反斜杠。
这一步就只补这两个命令和那个小时的显示，日历和待办的其他地方都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. `npm run test:calendar` 能跑，输出通过失败统计，且脚本 import 的是 app/lib 下的生产模块。
2. 脚本含一条故意算错的用例，且该用例被判定为失败。
3. `npm run export:ics` 真的产出文件并在终端打印路径，不是静默退出。
4. `npm run validate:ics` 仍然通过，不被这次改动破坏。
5. 不足一天时不再出现「剩 24 小时」。
6. 没有新增任何依赖。
