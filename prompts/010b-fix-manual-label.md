# 010b 修正：手动修正标签没进列表

**立项**：2026-10-31 17:35
**触发**：本机核对时发现，`updateNoticeAnalysis` 只改了 `analysis._source`，
没有改 `notice.source`，而左侧列表渲染的正是 `notice.source`。

## 缺陷证据

| 位置 | 渲染来源 | 改完后实际显示 |
|---|---|---|
| 右栏解析面板 | `analysis._source === "manual"` | 手动修正（正确） |
| 左栏通知列表 | `notice.source` | 仍是原值，如「AI 辅助」（错误） |

用户看不到列表层面的「这条被人改过」，需求只满足了一半。
这是 Dec-020 的又一个实例：数据里有了，但界面上那一格没有出口。

**更值得记的一点**：自检脚本 14 条用例只断言了 `analysis._source`，
没有断言 `notice.source`，所以它全绿却漏掉了这个缺陷。
**测试覆盖了什么，决定它能发现什么；没覆盖的字段等于没保护。**

## 顺带修掉的问题

`app/lib/noticeOps.js` 里 `import ... from "./deadline"` 少了 `.js` 后缀。
Next 的打包器能解析，纯 Node 跑不了，`npm run test:manual` 直接 MODULE_NOT_FOUND。
已由本助手本地补上后缀（一行，非功能改动，不影响浏览器行为）。

## Prompt 正文

```
手动修正这个功能我做出来用了用，发现有一个地方没改干净。
我在右边改完一条已经保存过的通知，右边那个小标签确实变成了「手动修正」，可是左边列表里那条通知的标签还是原来的字，比如还是「AI 辅助」。我在列表里扫的时候根本看不出这条被人改过，只有点开才看得见。我想要的是列表里也能一眼看出来。
我猜是不是因为这个标记存在了里面的分析结果里，但是列表那个地方用的是另外一个字段，两边不是一个东西。你帮我看一下，把列表那个也一起改掉，改完两边显示的应该是一样的。
还有一个事情我更在意。你上次给的自检脚本里，验证了里面那个标记，但是没有验证列表这个，所以它全绿，其实列表没改它也不知道。能不能在脚本里加一条，专门验证改完以后列表那个标签也变成了「手动修正」，这样以后谁再漏掉就会被抓出来。
另外我跑脚本的时候遇到一个报错，说找不到 app/lib 下面的 deadline 这个模块。我后来发现是 import 那一行没写 .js 后缀，浏览器里能跑，但是在终端用 node 跑就找不到。这个我已经自己加上了，你后面写新文件的时候记得都带上后缀，别再出这种问题。
老规矩，脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，故意错的用例还要能报红。
不要为了这些装新的库。
这一步就只修标签和补那一条用例，别的功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 改完一条已保存通知后，左栏列表标签显示「手动修正」，与右栏一致。
2. 自检脚本新增一条针对列表标签的用例，且该用例在修复前会失败。
3. `npm run test:manual` 仍然全绿，金丝雀按预期 FAIL。
4. 新增文件 import 一律带 `.js` 后缀。
5. 没有新增依赖。
