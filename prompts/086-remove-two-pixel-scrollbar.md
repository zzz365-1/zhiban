# 086 去掉原文框两像素假滚动条并收紧上下区间距

## 背景

085 之后短通知三行原文已完整显示，长通知上区封顶四成且外层滚动正常。
但浏览器诊断发现短通知下 textarea 的 clientHeight 108 与 scrollHeight 110 只差 2 像素，
overflowY 仍是 auto，于是画出一根带上下箭头的小滚动条，视觉上像内容被截断。
这是本轮最后一处视觉瑕疵。

## 本机已核验事实

诊断输出 TEXTAREA client 108 scroll 110 diff 2 overflowY auto。
解析结果组件内部的 flex-1 overflow-y-auto p-4 是正常内容滚动，不在本轮范围。
上区结构与自适应 effect 均已实测正确，不许推倒重来。

## 验收要点

第一，短通知原文框不再出现自身滚动条，文字仍完整。
第二，长通知上区封顶四成与标题吸顶不变，下区仍可见。
第三，编号与高亮定位不变，上下两块分界清楚且间距更紧凑。
第四，只输出改动片段。

## Prompt

```
短通知那一版我又看了一遍，三行原文现在能看全了，可是原文框右边还挂着一根很细的滚动条，上下还有小箭头，明明内容没有超出却显得很脏。我本机量了一下，框的高度和内容高度只差两个像素。长通知那根滚动条是在整个上区，那个是对的，别动。我说的是原文框自己那一根。

能不能让原文框自己那根消失，内容还是按实际高度撑开，别把文字截掉，也别让上区的滚动受影响。上区最多四成和标题栏吸顶都要留着，长通知我已经截图验过是对的。

另外上下两块中间那条灰带现在有点宽，稍微收一点，让排版更紧凑，但别把两块贴在一起分不清。

只给我需要改的那几段代码，标明文件路径和要替换的原文，不要输出整份文件。改完我两种分辨率重新截图，短通知和长通知都看，跑不过再回来找你。
```
