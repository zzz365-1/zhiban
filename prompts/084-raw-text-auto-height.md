# 084 原文输入框按内容自适应，消除截断与留白

## 背景

080 把详情改成上下分区后，把原来固定四百像素的原文框最小高度整个去掉了，
浏览器于是把它压回默认两行。浏览器双分辨率截图证实短通知第三行被切，
二十一行长通知几乎全看不见，而且框自己冒出一根小滚动条。
新增通知弹窗里另一个原文框仍写死二百四十像素，只贴三行字时下方空一大片。
左右分栏时的圆角卡片外壳在改上下之后也丢了，原文区与结果区层级分不清。

## 本机已核验事实

1280 与 1920 两种分辨率截图，textarea 实测 clientHeight 65 像素。
上区外层已有最大高度四成与外层滚动容器，长原文应由外层滚。
字段高亮依赖 textarea 的编号，不能动。
其余验收项，上下分区，事项清单整宽，中文标签，折叠横条，日期中文占位，均已实测通过。

## 验收要点

第一，短原文完整显示无截断，框按内容长高，上区跟着收。
第二，长原文由外层上区滚动，textarea 自身不带滚动条。
第三，弹窗输入框按内容收，超长再自己滚。
第四，恢复原文区的卡片层级，与结果区分得清，间距紧凑不挤。
第五，编号与高亮，折叠，独立查看，状态栏一律不动，只输出改动片段。

## Prompt

```
上下分区改完之后我又在两种分辨率下截图看了一遍，发现原文那一块还有个毛病。原文框自己只有两行高，通知有三行的时候第三行被切掉一半，框右边还冒出一根小滚动条，二十行的长通知更是几乎全看不见。我要的是原文短的时候整段都在，框跟着内容长高，上面那块也跟着收，不留一大片白，原文长的时候由上面那一整块自己滚，不要靠原文框里面的小滚动条。

还有一处。新增通知弹窗里那个原文输入框固定撑得很高，我只贴三行字，下面空掉一大块，能不能也跟着内容收一点，但还是要留够位置让人粘贴长通知，超长了再自己滚。

另外原来原文是包在一张带圆角边框的白色卡片里的，现在改成上下之后那层卡片没了，标题和输入框直接贴在白底上，跟下面解析结果那块分不太清。能不能把层级补回来，两块之间留一条清楚的边界，间距收紧一点，别把内容挤在一起，所有文字都要完整显示。

只给我需要改的那几段代码，标明文件路径和要替换的原文，不要输出整份文件。原文输入框的编号别动，高亮定位还要用，折叠和独立查看也别动。改完我本机两种分辨率重新截图，跑不过再回来找你。
```
