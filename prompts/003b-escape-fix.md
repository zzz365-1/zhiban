# 003b - 规则引擎转义缺陷二次修正

> **状态**：待发出。这是 003 号的第二轮追问，用于修正同一 Bug 的首次失败修正。
> **写作原则**：参赛学生第一人称，逗号句号断句，不用括号星号破折号，不许出现 markdown 强调符号。

## 背景（架构师注，不进 Prompt 正文）

DeepSeek 首版把正则写成四个反斜杠（`\\\\d`），导致日期/时间/地点三组规则全部失效，仅 `materials` 字段因采用「字符串数组 + `new RegExp`」写法而幸存。

追问一轮后，它把四个反斜杠改成了两个（`\\d`），**仍然错误**——JS 正则字面量里 `\d` 才表示数字，`\\d` 表示匹配一个字面反斜杠加 d。

已本地验证：把全部双反斜杠替换为单反斜杠后，五条测试通知的日期、时间、地点抽取**全部正确**。
遗留次要缺陷：`extractAudience` 中 `全体[\u4e00-\u9fa5]{1,8}?(?:同学)` 量词下限为 1，导致「全体同学」无法匹配。本轮暂不提，留待评测阶段统一反馈。

## Prompt 正文

```
我又试了一遍，还是不行，截止日期、具体时间、地点这三个依然全部显示未识别，需提交材料和面向对象这两个倒是好的。

我回去把你给的代码仔细看了一遍，发现一个地方我觉得可疑。你写的日期正则里面，d 前面是套了两个反斜杠的，我记得查资料的时候看到，JavaScript 正则里表示数字好像写一个反斜杠就够了，写两个的话它就变成要匹配一个反斜杠字符本身了。这条我不确定我没理解错，你帮我确认一下是不是这个原因。

另外我有个想法想跟你商量。我注意到需提交材料那个字段，你的写法是先把关键词放进一个字符串数组，再用 new RegExp 构造正则，这个字段从一开始就一直是好的，从来没出过毛病。而用斜杠包起来直接写正则的那几个，老是出这种转义的问题。既然这样，能不能麻烦你这次干脆把日期、时间、地点这几个也改成 new RegExp 那种写法？我想这样应该能一次性绕开这个坑，省得一直来回改。

麻烦把整个文件重新完整地给我一份，我直接覆盖掉原来那个。

还有一件事比较重要。我们这样改一次、打开浏览器粘贴一次、看一次结果，来回太麻烦了，中间还要等页面重新编译。有没有办法能不走浏览器，在命令行里直接跑一下这套规则看看它抽出来的东西？比如写一个小脚本，我每次改完敲一行命令就能看到那五个字段的输出，有的话麻烦你顺便帮我写一个，告诉我怎么运行。
```

## 这条 Prompt 的三个设计点

1. **给出答案但保留不确定语气**：指出双反斜杠可疑，同时说「不确定我没理解错」。学生查了资料后提出怀疑是合理的，但把最终判断权留给 AI。
2. **提出架构级规避方案**：用「materials 字段从没出过错」这条**它自己代码里的证据**，推导出改用 `new RegExp` 写法。这是观察力，不是术语堆砌。
3. **索要命令行验证脚本**：既是真实痛点（来回切浏览器太慢），也为后续量化抽取准确率提供载体。这个测试脚本本身是 20% 方法创新性得分点。

## 验收标准

- 文件中不再出现任何 `\\`（双反斜杠）
- DepthSeek 应提供一个 `test` 脚本，可用 `node` 直接运行并输出五字段抽取结果
- 用户在浏览器粘贴五条测试通知，五个字段应全部正确填充
