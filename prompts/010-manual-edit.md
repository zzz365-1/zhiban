# 010 手动修正抽取结果

**立项**：2026-10-31 16:50
**编号说明**：009 号已用于「界面内提醒」那份稿子，该稿已并入 008 并标注归档，
因此手动修正顺延为 010，后续复制摘要 011、批量粘贴 012。

## 为什么先做这个

解析结果目前只读不可改。抽错时（地点抽成动词短语、截止日期差一天）用户只能删掉重贴，
这是实用性上最大的缺口。同时它补上「AI 兜底、人做最终判断」这段叙事的最后一环。

## 两个必须守住的边界

- **改完三处同步**：列表剩余天数、日历格子、待办清单必须同时更新，不能只更新解析面板。
- **认不出的日期不许瞎猜**：宁可提示无法识别并留空，也不要填一个看起来像答案的值。

## Prompt 正文

```
日历和待办做完以后我又用了一阵，发现一个很尴尬的事。解析结果那一栏，抽出来的东西我只能看，不能改。碰上抽错的，比如地点抽成了一串动词，或者截止日期差了一天，我一点办法都没有，只能把这条删掉重新贴一遍。这个我觉得不行，真用起来肯定天天碰到。
我想在右边解析结果那一块，让每个字段都能改。点一下那个字段就能输入，改完有保存和取消，取消就恢复成原来的样子。能改的字段就是截止日期、具体时间、地点、需要提交的材料、面向对象、还有标题这几个。
有两个地方我特别在意，你一定帮我处理好。
一个是改完以后，所有显示这条通知的地方都要跟着变。左边列表那个剩几天、日历里面的格子、还有那个待办清单，这三处必须同时更新，不能只更新一处。我最怕的就是右边改了，日历里还是旧的。
另一个是改过的通知要能看出来是人工改过的。我的想法是来源那个小标签变成「手动修正」，这样一眼就知道这个结果被人确认过了，不是机器自己定的。
还有个日期输入的问题。我改截止日期的时候，可能输 11月6日，也可能输 2026-11-06，或者 11/6，这几种最好都认。但是认不出来的，你要告诉我认不出来，不要自己瞎猜一个日期填进去，猜错的比空着更害人。改完的数据要存下来，刷新页面还在。
老规矩。给我一个能在终端直接跑的自检脚本，验证改完以后剩余天数、日历格子、待办清单这三处确实同步更新了，还要验证那几种日期写法都认得出来、认不出来的会报错。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的能抓到错。正则里数字写成零到九这种字符类的样子，不要用反斜杠，我们在这个地方栽过好几次。
不要为了这些装新的库。
这一步就只做手动修改这一个功能，复制摘要和批量粘贴那些我们后面再做，这次千万不要顺手给我加上去。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 右栏六个字段可点击编辑，有保存与取消，取消能还原。
2. 改完截止日期后，列表剩余天数、日历格子标记、待办清单三处同步变化。
3. 修改后的通知来源标签显示「手动修正」。
4. 三种日期写法都能识别；无法识别时给出提示而不是编造日期。
5. 刷新页面后修改仍在。
6. 自检脚本 import 生产模块，含一条故意错的用例且被判定失败。
7. 没有新增任何依赖。
