# 039 一条通知里往往有好几件事，拆成事项各自带时间地点与状态

## 背景

原来一条通知只有一份字段，截止日期活动日期地点材料各一个。真实通知常常是两件事，五号前交表到学生工作处，八号晚上去行政楼开评审会。挤在一个字段里地点只能留一个，两件事的地点串了。

这一轮新增事项层：按句切成事项，每个事项自己带时间类型日期时间地点材料面向对象办理状态和原文依据。

## 几条硬约束

第一，状态不许一律显示未识别，要区分原文未提及、不适用、待确认、解析存疑。

第二，相对日期在没有通知发布日期时不换算，保留原文标待确认，不许默默按今天算。

第三，去参加的活动没有材料要交，材料那一栏标不适用，不是未提及也不是存疑。

第四，手动改过的值不能因为原文找不到依据就判存疑。

## Prompt

```
上一轮材料和分类那两处改完都对了，十分感谢。这一轮我想请你帮我加一层，我先把同学的原话抄给你。

同学说，你们这个程序只给我一个日期，可是我这条通知里明明有两件事，五号之前要交申请表到学生工作处，八号晚上还要去行政楼开评审会，这是两件事，时间和地点都不一样啊。

我仔细一想确实是这样。我们现在是一条通知一份字段，截止日期活动日期地点材料各只有一个。真实通知常常是好几件事挤在一条里，挤在一个字段里地点只能留一个，交表的地点和开会的地点就串了，看着像程序错了。

所以我想请你帮我写一个新模块，把一条通知切成好几件事，每件事自己带自己的东西。放在抽取模块同一个目录下，文件名叫 noticeItems 点 js。

做法上我想的是按句切开，一句话算一件事，逗号不算断句，因为报名截止时间为某日某时报名表交到某处是一件事。每一句再判断它是要办的手续还是要去参加的活动，判断的依据是这一句里有没有截止报送提交报名这类词，或者举行举办召开开始比赛讲座检查这类词。

每个事项我想带这些东西。事项名称，种类是手续还是活动，时间类型是办理截止还是开始时间，日期，日期的原文写法，时间，地点，材料，面向对象，办理状态，还有上一轮你帮我写的那个依据模块给出来的原文依据。

有几点我特别想请你注意。

第一，状态一定要分开。之前我们界面上不管什么情况都显示未识别三个字，同学看了很不满意，说是等于没说。我想分成这几种。有值而且原文里找得到依据的，就是正常。这类事项通常有但这一句没写的，标原文未提及。这类事项本来就没有这个字段的标不适用，比如去开会根本没有材料要交，不能显示未提及也不能显示存疑。值依赖通知发布日期而我现在还没有发布日期的标待确认。有值但原文里找不到依据的标解析存疑。

第二，相对日期要小心。通知里写明天或者下周三，如果我不知道这条通知是哪天发的，就根本没有换算的基准。这种情况下不许默默按今天算，要保留原文那个词并标待确认，等用户补了发布日期再算。用户给了发布日期的才换算。

第三，事项名称要像人话。提交纸质申请表，参加评审会，这样的。不要叫事项一事项二。

第四，校验要有语义层面的检查，填满了不等于对。时间是不是一个合法的时刻，日期能不能真的进日历，地点里有没有混进报送提交这类动作词，值在原文里到底找不找得到依据，这些都查。查出来有毛病的标存疑。

第五，手动改过的字段要特殊对待。用户自己填进去的值原文里本来就没有，不能因为找不到依据就给人家标成存疑，那样很冤枉。手动改过的事项打个标记，校验的时候跳过找依据那一关，别的检查照旧。

下面这些是我一条一条跑出来的结果，请你照着核对，不要自己另算。

第一条原文是助学金那条，两句话，五号下午五点前交纸质申请表到学生工作处A302办公室，八号晚七点在行政楼A302会议室开评审会请班长到场。要切成两个事项。第一个名称是提交纸质申请表，时间类型是办理截止，日期十一月五日，时间十七点，地点学生工作处A302办公室，材料纸质申请表。第二个名称是参加评审会，时间类型是开始时间，日期十一月八日，时间十九点，地点行政楼A302会议室，材料那一栏是不适用。两个事项的地点不能是同一个。

第二条原文是歌手大赛那条，报名截止十一月十日十七点报名表交到团委办公室，初赛十一月十五日晚六点半在大礼堂举行请参赛选手提前半小时签到。也是两个事项。第一个提交报名表，办理截止，十一月十日，十七点，团委办公室，材料报名表。第二个参加初赛，开始时间，十一月十五日，十八点三十，大礼堂。注意提前半小时签到是另一码事，初赛的开始时间必须是十八点三十，不能被提前半小时给覆盖掉。

第三条原文是宿舍检查那条，十一月二十日上午九点起后勤管理处对全校学生宿舍进行检查请各寝室配合。只有一个事项，时间类型是开始时间不是办理截止，日期十一月二十日，时间九点。这一句里没有说地点，地点那一栏标原文未提及。

第四条原文是体温表那条，请各班于明天下午五点前将体温监测表交至学院学工办B203。材料是体温监测表，地点是学院学工办B203。因为没有给发布日期，明天这两个字不许换算，日期就保留明天，日期状态标待确认。

还有几个状态方面的结果。第四条那个事项的日期状态是待确认，第一条第二个事项的材料状态是不适用，这两个要同时对。

依据方面也请一起对上。第一条第一个事项显示的时间是十七点，依据要能指到原文里的下午5点。第二个事项显示十九点，依据要指到晚7点。第二条第二个事项显示十八点三十，依据要指到晚6点半。而且依据给出来的起始和结束位置切出来的字必须正好就是那几个字，不然界面上会选错。

手动改字段这边也有两条。第一条原文切出事项之后，把截止日期手动改成二零二六年十一月六日，改完第一个事项的日期要跟着变成二零二六年十一月六日，而且状态是正常的，不能是存疑。

老规矩请一起守住。拿不准就留空并标原因，不许猜一个填上。正则全部用字符类写法。这次只写这个新模块，别的任何文件都不要动，也不要给完整实现以外的东西，之前有一次你给了别处的完整实现，把已经做好的功能覆盖掉了一大片。

对了，上一轮那个依据模块已经写好了，就在同一个目录下，你可以直接用它，不用再写一遍。
```

## 验证

四个案例二十二条断言全过，四十条用例里属于这一层的也全过。往返四回。

第一回最大的毛病是没有对每一句调用抽取模块，而是把日期时间地点材料写成空值交给依据模块去找。依据模块是靠反查工作的，给它空目标自然什么都找不到，所以时间地点材料全是空的，还把标题那一行也切成了事项。第二回改成先对这一句抽出真实值再交给依据模块反查，并且一句里抽不出日期就不生成事项，四个案例才对上。

第三回和第四回都是正则写法。它给的空白转义仍然带着反斜杠加字母，被项目的检查命令拦下两次，最后改成用字符码拼进字符类才干净。

金丝雀按预期报红，证明这套断言不是摆设。
