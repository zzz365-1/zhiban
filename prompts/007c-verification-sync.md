# 007c 验收脚本与源同步修正

归档时间：2026-10-31
状态：待发给 DeepSeek

## 发现的问题

`scripts/test-relative-dates.mjs` 自带一份简化版提示词，与 `app/api/parse/route.js` 的
`buildSystemPrompt` 内容不一致，导致验证结果与线上行为背离。

同一批用例对照（基准日 2026-10-31 周六）：

| 用例 | 测试脚本结果 | 生产 Prompt 结果 | 真实日历值 |
|---|---|---|---|
| 明天 | 2026-11-01 | 2026-11-01 | 11月1日，一致 |
| 大后天 | 2026-11-03 | 2026-11-03 | 11月3日，一致 |
| 下周三 | 空 | 2026年11月4日 | 11月4日，**脚本误报失败** |
| 本月25日 | 2026-10-25 | 空 | 10月25日已过期6天，**脚本放宽了约束** |
| 本周五 | 2026-11-06 | 2026-11-06 | 严格应为10月30日，存在一周口径差 |

教训：**验证脚本必须复用生产代码，否则全绿也不代表系统正确。**

## Prompt 正文

```
这一步收个尾，还是接着上次那批模糊日期的改动往下说。

我先说一下我发现的情况。我跑你给的脚本，里面有一条显示下周三算不出来。我有点怀疑这个结果，就把脚本里的提示词和真正跑在线上的那一段对比了一下，发现两边不是同一份。脚本里自己写了一份简化的，跟线上那份差挺多，少了示例，也少了几条细规则。我把同一句话拿到正式的提示词下面重跑，下周三其实是能算出来的，11月4日，完全正确。所以那个失败是脚本自己造成的，不是真的坏了。

这件事让我挺后怕的。如果脚本验的不是线上真正跑的那份东西，那脚本全绿也不代表线上没问题，反而会让我误以为验收通过了，做出错误的判断。能不能把提示词单独抽出来放到一个公共的地方，接口函数和测试脚本都从同一个地方取，这样以后改提示词就不会出现只改一边的情况。之前我们在转义上连续栽过跟头，我不想再因为两份代码不同步吃第二次亏。

还有一件事。脚本现在只是把算出来的值打印出来，不判断对错，我得拿眼睛一行一行比对。我现在已经有十几条测试用例了，这样迟早会看漏。能不能加上期望值，跑完直接告诉我几条通过几条失败，有失败就让命令报错退出，我一眼能看出来。

最后一个我想请你帮我拿个主意。今天是10月31日周六，有一条通知写的是本周五之前。我发现算出来的是11月6日，可是严格说本周是10月26日到11月1日，本周五其实是昨天。它给的是整整一周以后。虽然往未来算听起来更合理，毕竟没人需要提醒一件已经过去的事，但如果通知说的真是昨天那个周五，这条提醒就差了一个星期，按它去办事准误事。我拿不准该怎么处理合适，能不能在这种今天已经过了本周五的情况下，在界面上提示一句这是推测出来的换算结果，让我心里有个数。你觉得有更好的办法也行，你看着办。

改完帮我把之前那五条模糊日期的加上我手里的十八条例一起跑一遍，输出我一眼看得懂的结果就行。老规矩，每个文件的完整代码给我，我在 VS Code 里粘。
```
