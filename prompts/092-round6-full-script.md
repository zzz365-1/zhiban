# 092 第六轮完整回归脚本

## 背景

091 那条一次要的东西太多，只给出了第五轮旧断言的改法，完整的新脚本没给出来。
按拆细的原则，这一条只求一份新的检查脚本与命令清单里的一行。

## 本机已核验事实

第五轮脚本的 check 与 canaryCheck 结构可以直接照用，动态断言 import 生产模块，
静态断言读源码，末尾两条金丝雀故意期待报差异且不计入业务失败数。
本轮要钉的八处行为与对应的源码字符串另见事实材料。

## 验收要点

第一，输出完整的新脚本文件内容，不是片段。
第二，动态断言真的调用生产模块，断言前不归一化。
第三，静态断言覆盖八个文件的关键改动。
第四，两条金丝雀故意失败且不计入业务失败。
第五，给出命令清单里要新增的一行。

## Prompt

```
上一条你给的那段改旧断言的代码我用了，跑起来没问题。还差新的一组检查没给我，可能是我一次要的东西太多了。这次只求你写一份新的检查脚本，把我这一轮改过的八处钉住就行。标题定位要用显示出来的文字，摘要和分类不要做原文核对，确认切分后要清掉待重新解析标记并且每条都补事项，服务端结果不能丢活动日期活动时间和结束时间，本地规则识别的来源标签要写本地识别，日期没认出来时解析按钮要禁用，依据原句传进来的不是下标对象时不要乱选。检查要真的调用生产模块和读生产源码，末尾留两条故意会失败的对照，证明它真会报红。请给完整文件内容，别只给片段，另外告诉我命令清单里要加哪一行。
```
