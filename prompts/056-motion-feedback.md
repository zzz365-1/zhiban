# 056 第四轮之八 三处动效收口

## 背景

视觉规范里写了动效这一节，前几步把组件和页面做出来了，但三处反馈还没接上。
一是解析完成后办理步骤要依次展开，二是通知变化的地方要短暂高亮，三是勾材料要有简洁反馈。

## 几条硬约束

第一，动效只能是一次的短暂反馈，不许变成持续运动的装饰。

第二，必须尊重系统减少动态效果的偏好。

第三，不许显示假的进度。

## Prompt

```
前三步都跑通了，现在把动效那一节的三处反馈补上。老规矩，这不是重做，你只改很小的地方，不要重写文件，也不要把已有文件整个重抄一遍。请只输出改动的那几段，标明落在哪几行附近。

先提醒一次，样式文件里已经定义了这三个类名，请直接用，不要自己再写一遍关键帧。入场动画那个类名结尾是 enter，纯淡入那个类名结尾是 fade 和 in 两个词中间一个英文短横线，高亮闪烁那个类名结尾是 highlight，闪烁那个是背景从很浅的蓝退回到透明，一次九百毫秒。另外样式文件最后有一段媒体查询，系统开启减少动态效果时会把所有动画和过渡清零，所以你只要用这几个类名就自动合规，不需要自己再判断系统偏好。

第一处，办理步骤解析完成后依次展开。事项清单那个组件里，每条事项是循环渲染出来的。请你给循环里每个事项的最外层容器加上入场动画类名，并且按序号设置动画延迟，第一项延迟零毫秒，往后每项多加八十毫秒，最多叠加到第五项就不再增加，也就是第五项及以后都给三百二十毫秒。这样解析完结果出来的时候，几条办理步骤会一张一张往下展，而不是一起蹦出来。请注意只给事项卡片那一层加，不要给整个面板加，整个面板一起动就看不出依次展开了。如果那个循环外层本来已经有别的类名，请在原来的类名后面追加，不要覆盖掉原有的。

第二处，通知变化的地方短暂高亮。变更记录那个组件里，每条变更明细是一个对比块。请你给每个对比块加上高亮闪烁类名，但只在刚刚确认过更新的那一次生效，也就是说只有成功提示存在的那条历史的对比块才闪，翻看历史记录的时候不要闪，不然每次进去都闪很吵。请你用一个判断，只有当这个组件收到的成功提示不是空，并且这条历史是这个通知的第一条时，才加这个类名。这样同学确认完更新切到变更页，改了哪几处会闪一下，之后翻看就不会再闪。

第三处，勾材料之后的简洁反馈。事项清单那个组件里，每条材料前面有个能勾的方框。现在勾上之后只有文字加了删除线，反馈太弱，同学不确定自己勾上没有。请你在这条材料的右边，勾上之后短暂显示一行很小的绿色文字写已准备，一点二秒之后自己消失。取消勾选的时候不要显示。这个功能请用组件内部的状态实现，用一个状态记住最近一次被勾上的那条材料的标识，再用一个定时器在一点二秒后把它清掉。组件卸载的时候请把定时器清掉，不然会有警告。标识请用一个能区分不同事项和不同材料的字符串，简单点的话就把事项序号和材料序号拼起来。显示出来的时候请用纯淡入那个类名，这样出现得不生硬。

还有一条硬要求，这三处都不许显示任何百分比或者进度条之类的东西，我们这边拿不到真实进度，显示假的会被当成骗人。加载状态只用一个转圈就够了。

请你只输出这几处改动，标明原位置和新内容，不要输出整个文件。改完我本机跑，跑不过再回来找你。
```
