# 097 只有日期的通知不许冒出默认时刻

## 背景

演示里发现，通知原文只写了11月9日前，没写几点，解析页也没识别出具体时间，
可工作台、日历和整理成文字里都出现了17:00。查下来是算截止时间那个函数里，
没给时间就默认填了17点，摊平成日历事件时又把这个时间戳转成时分塞进时间字段，
汇总文字也照着这个时间戳打印。这个17点不是通知要求的，会误导同学。

## 本机已核验事实

本机实跑生产模块，通知原文是请全体团员于11月9日前完成本季青年大学习网上主题团课。
抽取结果里截止日期是11月9日，具体时间是空。算出来的截止时间却是当天17点整。
摊平后的事件里名字是提交材料，时间字段是17:00，时间类型是deadline。
汇总文字里这一行是11月9日 17:00 关于本季青年大学习网上主题团课的通知。
另一条只有日期的通知是11月12日，同样冒出17:00。

算截止时间的函数在 deadline.js，当前有一行把小时初始化成17，
分钟初始化成0，只有在传入的时间字符串能匹配上时分正则时才覆盖。
函数签名是 buildDeadlineDate，收两个参数，返回一个 Date 或者 null。
同一个文件还导出 getRemainingDays 和 parseUserDateInput，这两个不要动。

摊平成日历事件在 routeEvents.js，导出 buildRouteEvents，收一批通知，
返回一串事件。有事项时每个事项出一条，用事项的日期和时间算时间戳，
然后把这个时间戳的小时和分钟拼成时间字段，还有时间类型、地点、材料、办理状态。
没有事项的老数据走另一条分支，直接用通知自己的截止时间戳，也拼了时间字段。

调用 buildDeadlineDate 的地方有四处，页面保存单条通知，页面批量保存，
手动修正后重算，还有摊平事件那个模块。这些地方都要继续能拿到 Date，
排序、日历格子、待办筛选都靠它，不能改成返回空。

## 验收要点

第一，只有日期没有时刻的通知，界面上不许出现17:00，也不许补00:00或23:59
当成通知要求的时间。内部用来排序的时间戳可以继续存在，但要能明确区分出
这个时刻不是原文给的，展示层不能把它当原文时间。

第二，摊平出来的每个事件要带一个布尔标记，说明这条有没有明确时刻，
没有的时候时间字段给空串，另给一句具体时刻未说明的说明文字。
老数据那条分支也要按同样口径处理。

第三，有明确时刻的通知，比如11月5日下午5点和11月8日晚7点，
时间字段和排序结果一个都不能变，这是回归红线。

第四，只输出成对改动片段，把改之前的行和改之后的行分别写出来，
不要重写整个文件，不要新建名字差不多的模块，不要动其他函数。

第五，正则一律用字符类，不要用反斜杠加数字。

## Prompt

```
我在演示的时候发现一件挺奇怪的事，有一条通知只写了11月9日前要完成，通篇没说几点，解析结果里具体时间那一栏也是空的，可工作台的事项卡，日历里，还有整理成文字那段话，全都冒出来一个下午5点。我问了同学，他们说这不是通知写的，是我们自己算出来的。我去翻了一下，算截止时间的那个地方，要是没给时间就直接按17点算，后面又把算出来的时间戳当成原文时间显示出来了。能不能帮我改成，只有日期的通知就老老实实只显示日期，另外写清楚具体时刻未说明，别再自己补17点，也别换成别的时刻来凑。我知道排序，日历格子，待办筛选还得靠一个时间戳，这个值可以继续留着，但请让它能被认出来只是内部排序用的，别再被当成通知要求的时间显示出去。摊平成日历事件那里也一样，没有明确时刻的话时间字段给空，另外给一句说明文字，老数据那条分支也一起改。有明确时刻的通知千万不能受影响，比如11月5日下午5点和11月8日晚7点这种，时间显示和先后排序都得跟现在一模一样。麻烦只把要改的那几行改前改后分别写出来，别把整个文件重发一遍，也别新建别的模块。
```
