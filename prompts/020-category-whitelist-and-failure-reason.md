# 020 分类值域校验与失败原因上屏

## 背景

两处均已本机取证。

一处是真缺口。`aiExtract.js` 第 120 行直接取 `aiResult.category`，
未做任何白名单校验，提示词里限定的五个取值形同虚设，
模型返回限定之外的值会原样进入界面。

另一处是真缺陷。`parseOne` 的 catch 确实返回了 error 字段，
但 `page.js` 第 156 行写成 `setAnalysis(result.analysis)`，
error 从头到尾没人接。后果是超时、网络错误、密钥缺失、
返回非法 JSON、返回空内容这五种失败在界面上长得一模一样，
用户拿着本地规则抽出的残缺结果去办事，还以为是自己漏看了。

按 Dec-024，加校验的同时必须加注入用例，断言必须拒绝，
只写几个正常值通过等于没验证。

## 验收要点

1. 分类必须是白名单校验，非法值一律置空，五种合法值一个都不能误杀
2. 必须有注入用例，构造五个词之外的分类值，断言必须被拒绝且报红
3. page.js 必须接收并使用 parseOne 返回的 error，五种失败原因界面上显示必须有区别
4. 测试脚本必须 import 生产模块，不得另抄一份提示词或常量
5. package.json 原有命令一条不能少，尤其 check:key
6. 正则表达式一律用字符类书写，禁止反斜杠加数字
7. 全量回归十二个离线命令必须全绿，不能只看自带脚本
8. 断网可跑，移走 .env.local 后仍出结果
