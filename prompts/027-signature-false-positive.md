# 027 落款剔除误杀正常日期（P0-1）

## 背景

024 加了按位置判断落款的 `isSignatureDate`，修好了"发文日期被当成截止日"。
但本轮全量审计查出它把三类正常写法也当成落款扔掉了：日期在行首、日期在行尾、
日期后面那段以单位名收尾。审计细节见 `docs/defect-audit-2026-11-02.md`。

被误杀的八种写法（生产模块实测，全部返回空）：

1. 11月5日前交
2. 12月31日前交
3. 截止日期为12月31日
4. 截止时间为11月20日
5. 11月20日截止
6. 材料报送截止到11月20日
7. 请于12月31日前将表交到教务处
8. 请于11月30日前将表交到教务处

对照能抽出来的：请于11月30日前提交、请于12月31日前将材料交至行政楼A301。

## Prompt

```
我又发现一个比较严重的问题想请你帮忙。

上次你帮我改完落款日期那个问题之后，我拿很多种写法去试了一遍，发现有一批很普通的通知，截止日期反而抽不出来了。我列给你看一下。

第一类是日期写在最前面的，比如整条就写11月5日前交，或者写12月31日前交，这两个都抽不出来。第二类是日期写在最后面的，比如写截止日期为12月31日，或者写11月20日截止，或者写材料报送截止到11月20日，这三个也都抽不出来。第三类是日期后面还跟着一段话，而那段话的结尾是个单位名的，比如写请于12月31日前将表交到教务处，或者写请于11月30日前将表交到教务处，这两个也抽不出来。

可是我对照着试了一下，同样的句子只要把最后那个词换成不是单位名的，就又能抽出来了。比如写请于11月30日前提交，能抽出来。比如写请于12月31日前将材料交至行政楼A301，也能抽出来。所以问题应该就出在单位名这个判断上。

我自己去看了你上次写的那个判断落款日期的函数，我猜是这样。它判断一行是不是落款的办法是看日期前面和后面还剩下什么，如果日期前面什么都没有，或者后面什么都没有，或者后面剩下那段话的结尾像单位名，就都当成落款给扔掉了。可是真实通知里这几种情况太常见了，日期本来就可能在一句话的最前面或者最后面，后面跟着教务处这种单位名也是常态，不能一看到就扔。

我想请你把这个判断改准一点。我的想法是这样，如果日期的前面或者后面带着截止那一类的词，比如截止，截至，之前，前，期限，之前完成这类，那它明显就是真的截止日期，不管它在什么位置都不要扔掉。另外如果日期前后的文字里还有别的实质内容，比如前面写着请于，后面写着将表交到教务处这种，那也不是落款。只有在日期所在那一行除了日期就只剩一个单位名，而且确实在开头或者结尾的少数几行里面，才当成落款扔掉。

有几件事要请你一定注意。第一个是不要把原来那个功能搞坏了，真正的落款日期还是必须被剔除，比如结尾写单位然后换行写日期，或者日期和单位写在同一行，还有落款写在开头那两种情况，这几种的截止日期仍然要是空的。第二个是测试要直接引用真正的那个模块，不要自己另外抄一份相似的来判断。第三个是要在正式那个测试文件里把上面这八种写法都补成用例，期望值都是能抽到对应的日期，不能是空。第四个是正则一律用字符类写法，不要反斜杠加数字。第五个是那个存各种命令的文件里原有的命令一条都不能删，特别是那条查密钥的，改完请把所有命令都跑一遍把结果一起给我。

还有一件事我想请你帮我判断一下。改完之后，如果把那个判断函数改成永远说是落款，那新加的这八条会不会报错。如果改成永远说不是落款，原来那几条落款用例会不会报错。我要的是两边都会报错，这样才说明这个判断是真的在起作用。这个你不用真的去跑，告诉我你的判断就行，我自己会在本机试。

回复的时候不要把这个文件整个重新输出一遍，只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。如果改动分散在好几处，就一处一处分开说清楚，每处都标明大概在第几行。

我不太懂这里面的写法，如果哪里说得不对，你按你的判断来就好。
```

## 验收要点（本机侧）

1. 上述八种写法全部能抽出对应日期
2. 024 原有的落款用例（单位换行日期、同行、文首两种）仍必须为空
3. 双向注入：判断函数恒为「是落款」→ 新增八条必须报红；恒为「不是落款」→ 原落款用例必须报红
4. 全量 18 条离线命令 exit=0
5. 改动不得触碰 024 之外的抽取逻辑（地点、材料、对象行为不变）
