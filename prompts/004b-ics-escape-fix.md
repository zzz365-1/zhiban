> **状态**：待发出。004 的修正追问。

## 背景（架构师注）

### 本机实测：escapeICSText 存在过渡转义

把 `app/lib/generateICS.js` 里的 `escapeICSText` 原样抽出，在 Node 里跑真实文本：

```
输入 : 材料：申请表,复印件
输出 : 材料：申请表\\,复印件        ← 两个反斜杠
```

RFC 5545 要求英文逗号转义为 `\,`，**只要一个反斜杠**。多出来的那个会被日历软件原样显示出来，
标题直接出现多余的反斜杠。

### 这是同一类缺陷的第四次出现

| 次序 | 位置 | 表现 |
|---|---|---|
| 1 | `extractNotice.js` 首版 | 正则四个反斜杠 |
| 2 | 第一次修正 | 改成两个，仍然错 |
| 3 | 第二次修正 | 换容器后照搬旧转义层级 |
| 4 | **`generateICS.js` escapeICSText** | **替换串写成 `"\\,"`，产出两个反斜杠** |

同一模型在同一项目中、**同一类缺陷上连续四次失手**，且这次绕过的有效性是我方 Prompt 的要求。
这是本项目最扎实的一条「AI 可靠性观察」，写进技术文档的方法创新章节极具说服力。

**它躲过去的地方值得记一笔**：换行符它没有写 `CRLF` 的字符串转义，而是用
`String.fromCharCode(13, 10)` 字符码构造，从而绕开了转义层。这反过来证明：
只要让他用**字符类/字符码**而不是反斜杠元字符，就能系统性地消灭这类缺陷。该经验应固化为长期对策。

### 同时存在的合规缺口

RFC 5545 规定单行不超过 75 字节，超出需折行。中文一个字占 3 字节，通知标题稍长就会超。
当前 `generateICS.js` **没有做折行**，`validate-ics.mjs` **也没有检查行宽**。
两个都补上，比事后在线校验再发现要省事得多。

## Prompt 正文

```
日历导出这个功能基本跑起来了，谢谢你，时区是对的，提前一天提醒也生效了，你给的那个检查命令我也跑过了，都说通过了。

不过我拿实际内容试的时候发现一个小毛病。通知里如果写到材料要交"申请表,复印件"这种带半角逗号的句子，导出来的日历文件里，逗号前面出现了两个反斜杠，正常应该只有一个才对。我记得这个文件的规矩是逗号、分号、反斜杠这几个符号前面加一个反斜杠做转义，加多了日历软件反倒会显示错。你帮我看一下是不是又写重了。

另外还有一件事想问你。我听说这种日历文件每一行不能超过 75 个字节，而中文一个字好像要占 3 个字节，那通知标题稍微长一点是不是就超了？如果确实需要拆行的话告诉我怎么处理。还有你那个检查命令，能不能顺便也加一条行宽的检查，让我以后能一眼看出哪一行超长了。

麻烦把改好的完整文件给我，我在 VS Code 里覆盖保存，然后我再用命令验一遍。
```

## 这条 Prompt 的两个设计点

1. **前半句先确认成果**：「时区是对的、提醒也生效、命令也通过了」。真实协作里人不会上来就挑毛病，
   先给 AI 一个正确的落点，它定位会更快，也更接近真人说话的顺序。
2. **用一句大白话点破根因**：「是不是又写重了」。没有术语，只是把昨天亲眼见过的失败经验
   迁移到今天的新场景。比让 AI 自己重新排查省一轮，也比甩技术名词更像一个学生的口吻。

## 验收标准

- `escapeICSText("申请表,复印件")` 输出 `申请表\,复印件`（单个反斜杠）
- 半角分号、反斜杠同样只转义一次
- 生成的 ICS 每行不超过 75 字节，超长行已按 RFC 5545 折行
- `npm run validate:ics` 输出中增加行宽检查项，且样例全部通过
