# Prompt 003 · 本地规则引擎（结构化抽取）

- **日期**：2026-10-30
- **状态**：待发出
- **前置**：002 已完成，三栏界面可正常渲染，「解析」按钮目前仅弹占位提示
- **目标**：不联网、不调 AI，纯用代码从通知原文中抽出结构化字段

## 写作原则（在前 001/002 基础上新增第 6 条）

1. 以参赛学生本人第一人称叙述；
2. 不使用中括号小标题，全部揉进自然段落；
3. 不预设只有资深工程师才知道的技术细节；
4. 允许适度示弱，但保持"科班出身、缺实战"的分寸；
5. 对程序的要求要具体，但不指定实现方式；
6. **禁用一切 markdown 排版符号**——不得出现 `**加粗**`、`*斜体*`、`` `代码符` ``，避免 `——` 破折号；避免使用嵌套引号。
   **理由**：真人打字只会用逗号、句号、问号。任何强调符号都会破坏"真实对话"的可信度，直接伤害 20% 的方法创新性得分。

## 战略定位（架构师内部说明，不进 Prompt）

这是本项目「20% 方法创新性」的落点。核心主张：**不是什么都丢给大模型**。

- 确定性抽取（日期、时间、地点、材料）交给规则引擎，零延迟、零成本、可离线、全程可解释
- 不确定性推理（模糊语义、行动建议生成）才交给大模型，后续 005 步接入

此划分若能讲清楚，比做一个花哨界面更有说服力。规则引擎可写评测脚本，为技术文档提供「抽取准确率 XX%」这类硬指标。

## Prompt 正文（可直接整段复制）

```
界面那步做完了，三栏已经出来了，我一直在想一件事，现在点"解析"只是弹个提示，什么时候能真的开始干活。

我想先做一件不用联网、不花钱就能做的事，让程序自己把通知原文里的关键信息抠出来。比如这段文字里
写了"请各班班长于11月15日下午5点前将名单报送至教务处A301办公室"，我希望右边那栏能自动填上
截止日期11月15日、时间17点、地点A301办公室、要做的事是报送名单。

这一步我不想连AI，因为大部分校园通知的写法其实是套路化的，"请于某月某日前""截止到""地点在"，
这些都翻来覆去那几种。我感觉这种固定的东西用代码就能找出来，不一定非要问模型，
你觉得我想得对吗？对的话帮我写一套提取规则。

我想抽出来的字段是这几个，截止日期、具体时间、地点、需要提交的材料、这条通知面向谁，
比如全体学生、各班班长这种。有一个要求很重要，抽不到就留空或者写"未识别"，千万不要瞎编一个
填上去，我宁可看到空的也不想要假信息。

有个难点我不太确定能不能处理，中文日期写法太乱了，"11月15日""11/15""2026-11-15""下周三"
"本月月底"都有可能冒出来，还有"11月15日下午5点前"这种把日期和时间连在一起的写法。这块你看着处理，
覆盖常见的就行，不用追求百分百都认出来，认不出来的我们下一步打算交给AI去做。

代码放在哪里、要不要单独抽一个文件出来你决定。改完之后我再跟你确认效果，下一步我们再考虑接AI
处理那些实在认不出来的情况。还是老规矩，每个文件的完整代码都给我，我在VS Code里建文件粘进去。

最后麻烦帮我准备五条不同写法的测试通知，我想挨个粘贴进去试试，看看这套规则到底抽得准不准。
```

## 使用说明（给搬运者）

1. 整段复制，粘贴进 DeepSeek（**在同一个对话里接着聊**，它能看到 001/002 的上下文）；
2. 新增文件通常形如 `lib/parseNotice.js`（或 `utils/`），路径照它给的建；
3. 它会同时改动 `app/page.js`（接上解析逻辑）与 `app/components/AnalysisPanel.js`（展示结果）；
4. 全部保存后浏览器刷新，粘贴任意一条测试通知，点「解析」看结果。

## 验收标准

- [ ] 「解析」按钮不再弹占位提示，右侧真实填入抽取结果
- [ ] 至少识别：`11月15日`、`11/15`、`2026-11-15` 三种常见日期写法
- [ ] 空文本框点解析仍给出友好提示
- [ ] 抽不到时显示「未识别」而非编造内容
- [ ] 五条测试通知中至少三条核心字段抽对

## 关键提醒：准确率要留证据

抽完之后，把五条测试通知的实际输出截图存档，放进 `deliverables/`。理由：

> 技术文档中「抽取准确率 X%」这类硬数据，是方法创新性一栏最强的证据。五组太少，后续应扩充到
> 20 到 30 条形成正式评测集。这也是下一步决定是否接 AI 的依据，规则搞不定的那部分，
> 才是真正该花钱让模型干的活。
