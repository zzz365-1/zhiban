# 060 第五轮之五 主页面接线与变更后重新计算

## 背景

提醒组件和三处接线都做好了，现在差主页面把数据算出来喂下去，
以及补充通知改完安排之后要让提醒跟着重算。

## 几条硬约束

第一，提醒必须在主页面统一算一次，传给工作台和日历，不许各算各的。

第二，补充结束时间是用户自己填，不许预填，不许在填的时候顺手改官方通知里的时间。

第三，补充通知改完活动安排，提醒要按新安排重算，并且要让用户看见重算发生了。

## Prompt

```
提醒那一块都接好了，现在差主页面把数据喂下去，还有补充通知改完安排之后提醒要跟着重算。你只做加东西和很小的改动，不要重做，也不要把已有文件整个重抄一遍，请只输出改动的那几段，标明落在哪几行附近。

先交代主页面现在长什么样。它在计算区里已经有这样几行，先是拿到当前时间，再按搜索和分类过滤出通知列表，然后调摊平事件那个模块把这批通知摊成一串事件，接着用这串事件算待办。请在摊平事件那一行之后，紧接着加一行，调冲突提醒那个模块里算提醒的函数，把这串事件传进去，结果存成一个新变量。这个变量就是全页面唯一的一份提醒数据，后面两处都用它，不要在别的地方再调一次那个函数。

然后是两处渲染。第一处是工作台首页那个组件，它在视图等于工作台的那个分支里渲染，现在已经传了 now，groups，stats，focus，selectedKey，onOpenItem，onComplete，onToggleMaterial，onFocusStat，onCreate 这些属性。请再加两个，一个叫 alerts 把上面那个新变量传进去，另一个叫 onFillEndTime 传一个新写的处理函数，名字叫 handleFillEndTime。第二处是日历页那个组件，它在视图等于日历的那个分支里渲染，现在已经传了 notices，now，onOpenItem 三个属性，请同样加 alerts 和 onFillEndTime 这两个。

接下来是那个新写的处理函数，名字就叫 handleFillEndTime，它接收三个参数，依次是通知编号，事项序号，还有一个时间字符串，格式是小时两位数字英文冒号两位分钟。它要做的事是按通知编号找到那条通知，把对应序号那个事项上的结束时间改成传进来的值。请务必注意下面这几条。

第一条，事项在通知上存了两份，一份在通知最外层的 items 上，一份在通知的 analysis 对象里的 items 上，这两份必须改完保持一致，只改一份会出现界面变了日历没变的老毛病。请你改的时候用同一份新事项数组同时赋给这两个地方。

第二条，改结束时间的同时要改这个事项的 status 对象上的 endTime 键，填了值就写 ok，值空就写 not 和 mentioned 两个英文词中间一个英文下划线。status 里其他键不要动。

第三条，要校验传进来的值，格式必须是小时两位数字英文冒号两位分钟，小时在零到二十三之间，分钟在零到五十九之间，不合法就直接什么都不做返回，不要写进去。还有一条，如果填进来的结束时间不晚于这个事项自己的开始时间，也就是结束小于等于开始，也请直接返回不要写入，因为这种值要么是填错了要么是跨午夜，写进去只会算出假的重叠，宁可让它继续显示信息不足。

第四条，这个函数绝对不许改动这个事项的开始时间和日期，也不许改其它事项，用户只是补一个结束时间。

第五条，找不到对应通知或者对应序号的事项不存在，也直接返回，不要报错。

第三条主线是补充通知改完安排之后提醒要重算。现在主页面里确认补充通知那个处理函数，在它把变更写回通知之后，会调一个设置成功提示的函数，传进去一个对象，上面有 noticeId，title，itemNames，changes 这几个键。请你在这个对象上再加两个键，一个叫 alertCount，一个叫 alertTopTitle。值请你这样算，那一步里已经拿到了改完之后的通知对象，请你用摊平事件那个模块和冲突提醒那个模块，只针对这一条改完的通知算一遍提醒，条数放进 alertCount，如果条数大于零就把排在最前面那条提醒的标题放进 alertTopTitle，等于零就填空字符串。这样算出来的就是受影响的提醒。

然后请改变更记录那个组件，它现在接收的属性里有 success 这一个，就是上面那个对象。它在页面上方渲染成功提示那块，已经有显示受影响事项的那一段。请你在那段下面再加一行小字，内容是这样，先写提醒已按新安排重新计算，然后如果 alertCount 大于零就接着写当前这一条通知上有几条提醒，并且如果有 alertTopTitle 就把它用中文顿号接在后面，如果 alertCount 等于零就写当前这一条通知上没有需要提醒的事项。这行小字请用辅助文字那个灰色，字号小一号，并且只有在 success 上存在 alertCount 这个键的时候才显示，老数据没有这个键就不要显示，避免出现写着零的假提示。

还有一条，那个成功提示块里现在有个判断会用到 success，请你不要改动它已有的判断和已有的内容，只做加这一行。

最后一件事，这一轮不要动冲突计算模块本身，也不要动抽取那一层。改完我本机跑，跑不过再回来找你。
```
