# 021 老师建议第三条：反幻觉必须有实据校验

## 背景

老师的五条建议里，第三条是反幻觉不能只写在提示词里，必须能被验证。这一条打中了当前最根本的弱点。

融合模型结果那一层对模型返回的值没有任何实据校验，地点是直接拿来用的。本机实测，原文写的是把材料交到图书馆六楼研讨室，我假装成模型塞回去一个教务处一楼大厅，屏幕上老老实实显示成了教务处一楼大厅。我又接连试了凭空的时和凭空的面向对象。那么这意味着一件事，要求模型不许编造那句话完全依赖模型自觉。

这和上一轮的教训同源，把一件本该由确定性代码保证的事交给了概率性组件。

把老师的话翻译过来就是一句话，字段值必须能在原文里找到出处，找不到就当没有。这条规则是纯本地的确定性的，因此可以离线注入测试，凭空构造任意模型返回值喂进去，不需要真调模型，不需要密钥，不需要网络。

## 设计口径

1. 生成性字段豁免，摘要标题分类是模型组织出来的，不参与溯源，分类已有白名单把关
2. 已本地换算的日期豁免，凡是本地算出来的日期一律直接放行
3. 不可静默丢弃，被拦下的值要有记录出口
4. 防误杀与防漏同样重要，必须双向建用例

## 验收要点

1. 五类幻觉各有用例，凭空地点、凭空材料、凭空时间、凭空面向对象、模型擅改日期
2. 正常场景零误杀，汉字数字与阿拉伯数字、空格、括号补充、多种日期写法都要放行
3. 溯源成功要记录出处位置，为后面点字段高亮原文留出接口
4. 被拦下的值必须有出口，不能悄无声息
5. 金丝雀必须用真实的融合函数，注入后必须报红
6. 上一轮的日期用例一条不能少
7. 不得新增依赖，原有命令一条不能少
8. 全量离线命令回归

## Prompt

```
这一轮我想请你帮我对付一件事，是老师提的，我自己越想越觉得他说到点子上了。

老师问我们怎么防着模型瞎编。我说我们在给它的那些话里写清楚了不许编造，原文没有的就留空。老师说这不行的，写在话里只是你要求它这么干，不代表它真的做到了，你得拿得出东西来证明。我回来想了想，确实，我们现在能拿得出手的只是我们要求过它，说不出我们验证过它。

我就自己动手试了试，结果比我想的糟。我拿一句话去做实验，那句话里写的是把材料交到图书馆六楼研讨室，然后我自己假装成模型，塞回去一个完全另外的地方，写的是教务处一楼大厅。屏幕上居然老老实实显示成了教务处一楼大厅，一点反应都没有。我又接连试了几回，塞了一个原文压根没提过的材料，塞了一个原文里没有的时间，全都原封不动摆上去了。也就是说不管模型返回什么我们都是照单全收，写到一半我能确认一件事，那些话里那一句不许编造，其实一点约束力都没有。

所以我想请你给我加一道关口。模型每返回一个值之后，就拿它回原文里头去找，看这个值能不能找到出处。找得到的就留下，并且顺手记下它是在原文的哪个位置被找到的，我是想着以后点某一格的时候能在原文里把那一句标出来，现在先把位置记住就行。找不到的就当成没有，别让它在界面上露面。

有两件事我拿不准想听你的。一是像摘要和标题和分类这几个本来就是让它自己组织出来的，不是从原文里抄的，这种是不是就不该拿这条规矩去卡它。我倾向于不卡，但不确定还有没有别的也是这种性质。二是像面向对象这种，它有时候是根据上下文猜出来的，原文里不一定有那几个字连着出现，一律卡死我怕把对的结果也弄没了。这种情况是该严格，还是说只要跟我们自己那边算出来的结果一致就放行，我心里没底，你帮我定。

还有一件我挺担心的，这道关口别太狠了。原文写的是图书馆六楼，它返回图书馆6楼，这种明明是对的，不能因为一个汉字跟阿拉伯数字不一样就被当成编的。类似的还有地点中间隔着空格，材料名字后头带着括号说明，日期用横杠或者斜杠隔开写，这些我怕一不小心就误伤了。能不能麻烦你把这一类容易看走眼的情况尽量列全，每一种都配上例子，既要有真的编造必须被拦住的，也要有看着可疑其实是对的必须放行的，两头都得有，我不想为了拦错的把对的也拦没了。

另外，被拦下来的值请不要就这么悄悄扔掉，找个地方记一笔，说明这个值是因为在原文里找不到出处才被去掉的。不然以后界面上空着，我根本分不清到底是它没给还是被咱们自己拦了，出了问题也没处查。

还有一句话我要提前说清楚。上一轮咱们刚把像这个星期三和下个星期三这类说法改成本地自己算日子，这一轮加的这道关口可不能把这些已经算对的结果又挡回去。凡是我们这边用规矩算出来的日期一律直接放行，不用再去原文里找了。

老规矩。给我一个能在终端里直接跑的自检脚本，要引用咱们页面上真正在用的模块，不要另抄一份，要有期望值和通过失败的统计，还要有一条故意错的用例并且证明它真的会报红。上一回那条故意错的用例是假的，我把你写的检查弄坏了它还说自己正常，这次请务必让它真的去比咱们页面上跑的那个模块给出来的结果。改完之后你帮我把之前那一堆检查脚本都跑一遍确认没坏。相关的代码给我，我在编辑器里粘。
```
