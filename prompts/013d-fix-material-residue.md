# 013d 材料字段残留缺陷收敛

## 背景

013c 自测 15 通过 0 失败，金丝雀正常。本机注入九个场景后 8 通过 1 失败，
全量回归又发现 test:audience-materials 从 19/0 掉到 18/1。
四类问题同属材料字段，按 Dec-016 合并为一条 Prompt 一次收敛。

## Prompt

```
上次材料那个改完以后，十五条全过了，我自己又拿几条真的通知试了试，还是看到几个别扭的地方，我一起说。
第一个。一条通知写着，需提交材料：身份证、学生证、一寸照片。结果认出来的里面有一个孤零零的材料两个字。这个材料是那句话里本来就有的提示语，不是要带的东西，它不该出现在清单里。
第二个。同一句话里的一寸照片，认出来变成了寸照片，前面那个一字被切掉了。二寸照片也是一样。我们平时说的就是一寸照片和二寸照片，只留个寸照片看着很怪。
第三个。一条通知写着，报到时需交：一寸免冠照片、身份证复印件。这一条我上次提过，身份证复印件本来就是一样东西，不该被拆开。上次改成用和连的那种写法是对了，比如写请携带身份证和身份证复印件就正常，可是换成顿号隔开就又拆开了，变成身份证和复印件两样。通知里用顿号列清单比用和更常见，这个得修。
第四个。有一条写的是，请携带身份证和选民证，还要带一支黑色笔到现场。结果认出来的是黑色笔到现场，尾巴上那几个字没去掉。这条之前是好的，这次改完反而坏了，我那个测面向对象和材料的脚本里面第九条例现在就是红的。
我猜可能是你处理的时候，有的地方会在遇到顿号或者句号的时候停住，有的地方不会，两条路子不太一样。你看着办，能修好就行。
老规矩。给我一个能在终端直接跑的自检脚本，要验证清单里不会出现材料这两个字，验证一寸照片不会被切掉，验证顿号列举的身份证复印件不会被拆开，还要验证黑色笔后面不会拖着到现场。脚本要引用页面真正在用的模块，不要另抄一份。要有期望值和通过失败的统计，还要有一条故意错的用例，证明断言真的会抓到错。
另外提醒一下，你每次改 package.json 的时候，里面原来就有的命令要都留着。
不要为了这些装新的库。
这一步就只修材料这一个格子，其他字段和其他功能都不要动。相关的代码给我，我在 VS Code 里粘。
```

## 验收要点

1. 四个场景必须同时成立，只满足一部分算没修好
2. test:audience-materials 恢复到 19/0，用例 9 不许通过改期望过关
3. 全量回归八条命令均需通过
4. 原有 npm 命令全部保留
