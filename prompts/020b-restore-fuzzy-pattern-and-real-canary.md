# 020b 恢复周几识别范围，并把金丝雀换成真的会响的那种

## 背景

020 交付后本机验收，三处必须打回，一处附带。

**其一，它偷偷把 `isFuzzyDate` 里周几的正则改窄了。** 旧版共享常量里有十五个前缀，
新版只剩下七个。穷举比对，共十一说法失去识别：

```
这个周三 这个星期三 这一个周三 这一个星期三 下个周三 下个星期三
下一个周三 下一个星期三 下下周三 下下个周三 下下个星期三
```

恰好是 019d 前一整轮刚刚补齐的那批。

后果端到端可复现。同一句、同一时刻、同样连不上网络，只换这份正则：

```
请于这个星期三前将材料交至教务处A101。  旧 2026年11月4日   新 这个星期三
请于下下周三前将名单报送教务处A101。    旧 2026年11月11日  新 下下周三
```

联网时则退回模型做日期算术，正是 018 用本地纯函数消灭掉的那类概率性错误。

**最值得注意的是：这处改动不在任何现有测试的覆盖范围内。**
十三个套件三百一十六条用例无一引用 `isFuzzyDate`，所以全量回归全绿，
缺陷是逐个反查 diff 才发现的。这比缺陷本身更值得记。

**其二，它写的金丝雀是装饰品。** 把生产代码 `normalizeCategory` 改坏之后，
业务用例倒了六条，金丝雀依旧输出「按预期 FAIL」。原因是它只校验
常量数组里有没有某个硬编码字符串，从不与生产模块的输出做对比，
因此永远不可能因为生产代码被改坏而报红。

**其三，它又删了 `check:prompt`。** 这次替换得很隐蔽，总条数 18 对 18 没有变化，
删一条加一条，扫一眼数量发现不了，只有逐条比对名字才看得出来：

```
被删：check:prompt     新增：test:classify
```

提示词里明确提醒过“那条查密钥的”，结果这次删的是另一条。同一类错误第三次发生。

**附带**：它自带的清单红一条。第 23 条期望说明含中文「密钥」，
而它自己写的文案是 `DEEPSEEK_API_KEY` 这个英文变量名，两边自相矛盾。
顺带这也是个界面文案问题，环境变量名不该出现在学生看得见的地方。

## 验收要点

1. 周几识别恢复到 018 版本的覆盖范围，八种丢失说法逐个补回
2. 必须补端到端用例：从通知原文走到最终日期，不允许出现原字符串外泄
3. 新用例必须在 `normalizeCategory` 或 recognize 逻辑被注入破坏时报红，本机验证
4. 金丝雀必须与生产模块输出做对比，注入后必须 FAIL
5. `check:prompt` 必须恢复，scripts 总数不少于 19 条
6. 自带清单必须 30 条全绿，且不得靠改期望值凑绿
7. UI 文案里不得出现英文变量名，改成学生读得懂的中文
8. 全量十四个命令全绿

## Prompt

```
这一轮我要先谢谢你。分类那个检查加上之后，我拿一个根本不在五个词里的值试了一下，它果然被挡住了，那一栏显示的是未识别，没有再把稀奇古怪的词原样摆给我看。失败那块也做出来了，我断着网试的时候界面上多了一块黄颜色的说明，告诉我这次是栽在哪一步，跟以前只有一句摸不着头脑的话完全不一样了，你是真把原因一路带到了屏幕上。

不过我顺手又拿几句别的话试了试，发现有个地方退步了，我觉得还挺要紧的。我丢进去一句请于这个星期三前把表交上去那种话，界面上显示的竟然就是这一串字本身，不是几月几号。我又试了请于下个星期三前交，还有请于下下周三前交，全都是这样，屏幕上直愣愣摆着这一串字。可是上一轮刚收尾的时候它们明明是能算出日期的，我自己复核过一遍。

我回去翻了翻，发现你在处理日期那一段，顺手改了一个管着判断这串字该不该由本地来算的东西。改之前它能认出这一大批说法，改成现在这样之后，只剩少数几个词还认得出来，这个星期三，下个星期三，下下个星期三，这些全都认不出来了。认不出来会怎么样呢，本地就不算了，又把它交回给模型去算日子。这个方法咱们上一轮是实打实吃过亏的，模型算日子偶尔会差一天，差了还看不出来。所以我特别想让你改回去。

能不能麻烦你这么办。一把那个认的办法恢复到上一轮的样子，上面这几种说法都要能认出来。二给这块也配上专门的检查用例，从一条通知原文开始一路走到最后显示出来的日期，中间不许出现那种把这一串字原样端给用户的情况。我之所以这么较真，是因为我把你这次的改动挨个看了一遍才发现这个问题，那十几个检查脚本当时跑下来一条红的都没有。它明明已经坏了却没人报，说明这块是我们眼瞎的地方，我想借这一轮把它补上。

还有一件事我试出来了，说出来你可能觉得我瞎折腾。我想看看你写的那条故意错的用例到底灵不灵，就试着把你自己写的检查改动坏了一处，再跑了一遍。结果那条用例一动不动，还是说自己正常。我这才明白，它好像只是在自己跟自己对答案，跟我真正跑的那些代码没什么关系。能不能改成让它去拿真正跑的那个模块的结果来比，那样以后万一有人改坏了它才会真的跳出来喊。

另外你自己跑出来的那条清单里有一条是红的，说的是说明文字里应该有密钥两个字，可你写进去的是一串英文字母。那串英文字母我一个学生看着也有点头疼，能不能换成人能读懂的话。改的时候两边都过一眼，别光把期望值改成实际值了事。

最后一件事，我今天想去用那条专门检查我写的话有没有违了咱们事先定下的规矩的命令，跑到那个存各种命令的文件里找了半天也没找着。我记得里头是有一条干这个的，还有一条是查密钥的，查密钥那条还在，干这个的那条不见了，总数倒是一点没变，因为同时又多了一条新的，不一个一个数还真看不出来。麻烦你帮我加回去，数一数应该总共十九条，少一条就是又有谁被挤掉了。以后我每次写完都得靠它把关。

老规矩。给我一个能在终端直接跑的自检脚本，要引用页面真正在用的模块，不要另抄一份，要有期望值和通过失败的统计，还要有一条故意错的用例并且证明它真的会报红。你每次改那个存各种命令的文件的时候，原来就有的命令都要留着。不要为了这些装新的库。改完之后你帮我把之前那一堆检查脚本都跑一遍确认没坏。相关的代码给我，我在 VS Code 里粘。
```
