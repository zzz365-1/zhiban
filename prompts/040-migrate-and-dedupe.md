# 040 老数据要能补出事项，重复导入要分三种情况说清楚

## 背景

老通知只有截止日期和时间，没有事项字段，点开之后事项那一块是空的。重复导入方面，同一条通知粘两次会出现两条一模一样的；但标题相同正文不同属于改过的通知，既不能当重复丢掉，也不能静默覆盖旧的。

## 几条硬约束

第一，迁移只补字段，原有字段一个都不能丢。

第二，已经是新结构的不要重复迁移。

第三，重复判定分完全重复和标题重复两种，标题重复不能静默覆盖。

第四，比较前先去掉空白和标点，否则多一个空格就认不出来。

## Prompt

```
上一轮事项那个模块改完四条原文都对上了，十分感谢。这一轮我碰到两个新问题，都不是切分本身的毛病，是数据进来和进来之后的麻烦。

第一个问题是老数据。我早先存的那批通知，那时候还没有事项这一层，它们只有截止日期和时间，没有事项字段。现在点开一看，事项那一块是空的，看着像程序没干活。我不希望让用户丢数据，也不希望让人家手动重录一遍。想请你帮我写一个迁移的模块，把老的通知补出事项来，放在抽取模块同一个目录下，文件名叫 noticeMigrate 点 js。

第二个问题是重复导入。同一条通知我不小心粘了两次，列表里就出现两条一模一样的，这肯定不行。可是还有另外一种情况，标题是一样的，正文改过了，比如时间往后推了两天，这种不能当重复直接丢掉，也不能闷声把旧的那条覆盖掉，得弹出来让用户自己选。想请你帮我写一个去重的模块，文件名叫 dedupe 点 js。

迁移那边我有几个要求。

第一，只补字段，原来那些字段一个都不许丢。编号，标题，来源，那个存着截止时间的数字，还有整个解析结果，都要原样留着。

第二，已经是新结构的不要再迁一遍，不然事项会越迁越多。

第三，除了单条迁移，还要有一个整表迁移的入口，一次把一批通知都过一遍，条数不能变少。

第四，老通知的正文如果切不出事项来，就给一个空数组，不要报错，也不要编一个假事项塞进去。我们一直的原则是宁缺勿滥。

去重那边也有几个要求。

第一，要分三种结果。正文一模一样的叫完全重复，这种情况正常做法是跳过。标题一样但正文不一样的叫标题重复，这种情况要弹给用户选，不能闷声覆盖。剩下的是没见过。

第二，比较之前先把空格换行和标点都去掉，不然多一个空格或者多一个句号就认不出来了，那这个去重等于没有。

第三，标题指的就是正文的第一行，不是列表里那个标题字段。因为用户粘进来的东西第一行通常就是通知标题。

第四，还要有一个给事项去重的功能，同一件事在日历里只能出现一次。判断的依据是事项名称加上日期加上时间，跟它属于哪条通知没关系。一轮导入里出现重复的话保留先出现的那个。

下面这些是我跑出来的结果，请你照着核对，不要自己另算。

老通知这一条，编号是nold，标题是老通知，来源是本地识别，正文就是助学金那条两句话，解析结果里截止日期是十一月五日时间是十七点，另外还有一个存截止时间的数字是一。迁完之后事项是两个。而且编号标题来源那个数字还有解析结果里的截止日期这些都不能变，连起来应该是nold和老通知和本地识别和一和十一月五日。

已经有事项的通知不要再迁。给一条编号是x，结构版本是二，事项里已经有一个叫a的事项，正文是助学金那条。迁完之后事项还是一个。

整表迁移两条通知，一条是助学金那条两句话，一条是宿舍检查那条，迁完还是两条。

重复这边。拿助学金那条去比一条正文完全一样的，结果是完全重复。拿助学金那条去比一条正文第一行一样但后面内容不一样的，结果是标题重复。拿助学金那条去比一条运动会通知，结果是没见过。

事项去重这边。把助学金那条切出来的事项复制一份接在后面，一共四个，去重之后应该是两个。

老规矩请一起守住。正则全部用字符类写法，不要用反斜杠加数字。这两个都是新文件，别的文件都不要动，只给这两个新文件的完整内容。上一轮那个事项模块已经写好了，迁移的时候直接调用它就行，不用再写一遍。
```
