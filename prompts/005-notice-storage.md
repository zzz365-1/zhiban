# 005 - 通知持久化与紧急度分级

> **状态**：Prompt 已交付用户，尚未执行。
> **写作原则**：参赛学生第一人称，逗号句号断句，不用括号星号破折号，不用 markdown 强调符号。

## 产品定位（架构师注）

004 打通了「通知 → 行动」，但左侧列表仍是硬编码假数据。一个存不住用户数据的工具，评委第一眼就会质疑「我为什么要用它」。005 把假数据换成用户自己的数据，并补上通知类产品的核心信息：**还剩几天**。

选 localStorage 而非数据库，理由直接对应评分表里的可复现性——评委 clone 下来不需要装任何额外服务就能跑起来。这个判断由学生在 Prompt 里说出来，是产品决策而非技术无奈。

## Prompt 正文

```
日历那个功能跑通了，谢谢你，帮我解决了大问题。不过有个地方我觉得挺别扭的，想跟你商量一下。
左边那一列通知列表，现在还是写死在代码里的那几条假数据。我粘贴一条通知解析完之后好像什么都没留下，
刷新一下网页又变回原来那几条。同学真用起来肯定希望自己收到的通知能存住，不然每次解析完就白干了。
所以我想做成这样。中间解析出来以后，下面加一个"保存到我的通知"的按钮，点了之后这条通知就进到左边那一列里去，
左边就算真正属于自己的通知列表了。刷新网页不能丢，这点我觉得挺重要的，不然没人敢用。每条最好还能删掉，
万一手滑存错了能补救。
还有一件事我觉得挺关键的。同学看通知最关心的是还剩几天，不是具体日期。能不能在左边每一条下面直接显示
还剩多少天，快到期的用显眼一点的颜色，比如三天以内的标红，一周以内的标黄，时间还早的就正常显示。
已经过了截止日期的灰掉或者加个"已过期"的标记，让人一眼知道这条不用管了。
存储这块我不太懂。我听说浏览器本身好像能存一点东西，叫什么 localStorage 的，是不是直接用这个就行？
还是说有更合适的办法？你帮我判断，我这个项目不想搞得太复杂，最好不要装数据库什么的，那样以后人家
想跑起来还得多装一个东西，太麻烦了。
另外那几条写死的假数据，现在是不是可以删掉了。我的想法是第一次打开的时候左边显示一句提示，
告诉用户可以粘贴通知然后保存，这样看起来像个正经的工具，不知道这样合不合适，你看着办。
这一步先做通知的存取和剩余天数，别的暂时不动。老规矩，每个文件的完整代码给我，我在 VS Code 里粘。
```

## 设计点

1. **痛点从真实使用中长出来**：解析完不留痕迹，刷新就回到假数据，这是任何真实用户第一时间都会撞见的问题，比「加个保存按钮」这种功能陈述有力得多。
2. **「不要装数据库」把复现成本说成产品判断**：这是学生自己的主张，不是照抄的术语，直接支撑 25% 可复现性。
3. **紧急度分级（红/黄/灰）完全从用户视角提出**：AI 不会因为这段文字更聪明，但评委会因此相信产品是本人的。
4. **边界问题交还 AI 判断**：假数据删不删这种取舍让学生开口问，符合一贯路子。

## 验收标准

- 解析后可保存，左侧列表出现新条目
- 刷新页面后数据仍在
- 每条可删除
- 显示剩余天数，并按 3 天 / 7 天分色，过期置灰
- 首次打开显示空状态提示，假数据已移除
