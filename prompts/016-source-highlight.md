# 016 点字段高亮原文出处

## 背景

老师第 5 条建议：要能指出依据哪一句。排期里 016 必须排在 022 之后，
因为布局定了才知道高亮该往哪渲染。**016 不是交互糖，是回答"凭什么信这个结果"的必需品。**

022 已把布局改成上下结构（原文在上、结果在下），同屏对照的条件已经具备。

021 已有 `app/lib/grounding.js`，能判断模型返回的值是否在原文里出现，
但只返回判断结果，不带位置信息。本轮要做的是把"能不能对上"变成"对上了在哪一句"。

## 关键约束

- 高亮必须用**原文里真实找到的位置**，找不到就明确说找不到，不许瞎指一处
- 这是 021 反幻觉的界面出口，宁缺勿滥同样适用

## Prompt

```
我想请你帮我加一个小功能，起因是我自己用的时候发现一个问题。

现在程序把通知里的截止日期地点材料这些字段抽出来显示给我看，可是我看着这些结果心里没底，不知道它是根据原文哪一句话得出来的。特别是有些字段是模型抽的，我想确认一下原文里到底有没有这句话，不然我不太敢直接用。我们老师也提过这个问题，说要能指出依据的是哪一句。

所以我想加一个功能，就是我在下面结果区点一下某个字段，上面输入框里对应的那段原文就能被高亮选中，让我一眼看到这句话在原文的什么位置。比如我点截止日期那个字段，上面原文里写截止日期的那一句就应该被选中。

有一个地方我觉得挺重要。如果那个字段的值在原文里根本找不到，就不要随便高亮一处假装找到了，要明确告诉我原文里没找到。因为之前我们花了很大力气做了一个出处核对的功能，就是防止模型编造原文里没有的内容，如果这里随便指一处，那个功夫就白费了。找不到就老实说找不到，这样反而能帮我发现问题。

还有几种情况你帮我一起考虑一下。第一种，字段的值和原文里的写法不完全一样，比如原文写的是图书馆六楼，结果显示的是图书馆六层，这种应该算找到了。第二种，字段的值是程序自己算出来的，比如原文写下周三，结果显示的是换算后的具体日期，那原文里就没有这个日期，这种情况怎么处理你帮我拿个主意，可以在回复里说明你的想法。第三种，有的字段是空的，空的就不需要高亮了。

实现上我有个想法不知道行不行，输入框是一个可以输入文字的框，我记得浏览器好像可以让里面的文字被选中，如果能用这个办法就不用改输入框的结构了。如果这个想法不行，你按你觉得稳妥的方式来。

还有几件老规矩麻烦你一起遵守。第一，这个项目没有配置路径别名，写代码不要用那个艾特符号开头的路径，一律用点杠开头的相对路径。之前用了艾特开头的路径，程序直接报找不到模块，网页打不开。第二，不要另外新建一个名字差不多的模块。之前新建过一个，结果两份代码判断逻辑不一样，反而更乱，后来删掉了。第三，写正则一律用字符类，不要出现反斜杠加数字。第四，不要加新的依赖包。第五，那个存各种命令的文件里原有的命令一条都不能删，特别是那条查密钥的，改完请把所有命令都跑一遍，把结果一起给我。

还有一件很重要的事，请你回复的时候不要把文件整个重新输出一遍，那几个文件都很长，你全部打出来我会看不过来，而且容易把本来没问题的地方也改坏。你只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。如果改动分散在好几处，就一处一处分开说清楚，每处都标明大概在第几行。

另外说明一下，我是新开的一个对话，之前聊过什么你这边看不到了，所以你只能根据我这次发给你的这些文件来判断，不要假设你还记得之前我们说过什么。如果我给的信息不够你判断，你直接问我，我去补。

我不太懂前端怎么实现选中，如果哪里说得不对，你按你的判断来就好。
```
