# 058 第五轮之二 冲突与集中提醒的计算模块

## 背景

结束时间抽出来之后，就可以判断两项活动有没有真的撞车了。
这一条要一个纯函数模块，把重叠和截止集中这两类提醒算出来，
同时把测试脚本一起写出来。

## 几条硬约束

第一，只有两头都有明确开始和结束时间的活动才能算出确定的重叠时长，
缺一头就不算确定重叠，也不许假设时长。

第二，一项的结束时间等于另一项的开始时间不算重叠，这叫无缝衔接。

第三，同一天多个截止不能叫冲突，只能叫截止事项集中，文案上必须分开。

第四，不许修改任何时间数据，这只是算提醒。

第五，同一条提醒在日历和事项卡片上要长得一样，并且不能重复堆叠，
所以每条提醒要有一个稳定的唯一标识。

## Prompt

```
结束时间那一步已经跑通了，现在做真正算冲突的那一块。这一步请你新建一个全新的模块文件，放在逻辑目录下，名字叫 conflict 点 js，是一个纯函数模块，不依赖任何浏览器接口，可以直接在命令行里跑。同时请你新建一个测试脚本放在脚本目录下，名字叫 test 短横线 conflict 点 mjs，命令我这边会自己配。

先交代一下输入长什么样。摊平事件那个模块会把每条通知拆成一串事项事件，每个事件上有这些键，noticeId 是通知编号，noticeTitle 是通知标题，itemIndex 是这个事项在通知里的序号，name 是事项名，date 是一个日期对象，time 是小时两位数字英文冒号两位分钟的字符串，ts 是毫秒时间戳，location 是地点，materials 是材料数组，progress 是办理状态，timeType 只有两个取值，start 表示活动开始，deadline 表示办理截止。现在每个事件上还会多一个 endTime 键，是活动的结束时间，同样那个字符串格式，没有就是空。有些事件可能根本没有这个键，你要当成没有处理。

请你导出一个函数叫 buildScheduleAlerts，它接收一串事件，返回一串提醒。每条提醒是一个对象，必须有这几个键。第一个是 key，一个字符串，用来做唯一标识，同一条提醒不管在哪个界面出现都必须是同一个值，界面靠它去重。第二个是 type，取值只有三种，overlap 表示确定的时间重叠，cluster 表示截止事项集中，needEndTime 表示信息不足需要补结束时间。第三个是 level，取值是 warn 或者 info。第四个是 title，是给用户看的一行短标题。第五个是 detail，是补充说清楚的一行文字。第六个是 items，是牵涉到的事件的精简信息组成的数组，每个元素至少有 noticeId，itemIndex，name，time，endTime，noticeTitle 这几个键，方便界面点进去看原文。

下面是三种提醒各自的判定规则，请严格照做。

第一种是确定的时间重叠。只有在两个事件都满足下面全部条件时才成立，两个事件的 timeType 都是 start，两个事件的 time 和 endTime 都不是空，两个事件算出来的日期是同一天，也就是年月日三个都相同。判定重叠的式子请用小于号，不要用小于等于号，具体是第一个的开始小于第二个的结束，并且第二个的开始小于第一个的结束，两个条件同时成立才算重叠。这样一项十六点结束另一项十六点开始的情况，第一个的开始小于第二个的结束成立，但第二个的开始小于第一个的结束不成立，就不会被判成重叠，这正是我要的，无缝衔接不算撞车。重叠的时长请用两个结束时间里较早的那个减去两个开始时间里较晚的那个，得到分钟数。请你再写一个导出的辅助函数叫 formatDuration，把分钟数变成中文，六十分钟就写一小时，九十分钟就写一小时三十分，四十五分钟就写四十五分钟，不足一小时只写分钟，正好整小时只写小时，不要出现零分这种尾巴。提醒的标题请写成时间冲突四个字，详情里要写清楚两个事项的名字和重叠的时段和重叠了多久，比如参加答辩十四点到十六点和听讲座十五点到十七点重叠一小时，重叠时段是十五点到十六点。详情里必须带上重叠时段和重叠时长这两样，缺一样用户不知道要挪哪一段。重叠时长为零或者为负数的直接丢掉，不要产生提醒。

第二种是截止事项集中。把同一天，也就是年月日相同的，timeType 等于 deadline 的事件归到一起，数量大于等于两个就产生一条提醒。标题请写成截止事项集中这六个字，一条都不要写成冲突或者撞车，这是最容易被挑错的地方，同一天要交两份材料不是冲突，只是那天比较忙。详情里请写这一天一共有几项要办，并且把这几项的名字都列出来，用中文顿号隔开，超过三项就只列前三项后面加等字。这类提醒的 level 请给 info，而第一种重叠请给 warn。已办理的截止事项要不要算进去，请你按已办理和无需办理两种状态排除掉，都办完了还提醒是骚扰。

第三种是信息不足。对 timeType 等于 start 并且有开始时间但没有结束时间的事件，产生一条提醒，标题请写成结束时间待补充，详情里说明只有开始时间不确定什么时候结束，暂时不能判断是否与其他活动重叠，并且写清楚一句不会替你假设活动时长。这类提醒的 level 请给 info。这里有个去重要求，同一个事件只能产生一条，不要因为别的事件也缺就重复产生。

去重和排序也请定死。同一个事件对只产生一条重叠提醒，请你在算之前先按时间戳排好序，再用两层循环，外层从零到倒数第二，内层从外层加一到最后，这样不会把同两个人算两遍。key 的拼接方式也请你定死，重叠那种就写成 overlap 加上两个事件的通知编号和事项序号，中间用竖线隔开，并且把排前面的放前面，保证不管怎么遍历结果都一样。集中那种就写成 cluster 加上那一天的年月日。缺结束时间那种就写成 need 加上这个事件的通知编号和事项序号。返回之前请把结果排序，重叠排最前面，其次是集中，最后是缺结束时间，同类的按涉及的最早时间戳从小到大排。

另外有一句硬要求，这个函数绝对不许修改传进来的事件对象，也不许修改任何时间，它只是算提醒，不许自动调整官方通知里的安排。你要算时间戳的话请自己新建一个日期对象，不要在原对象上改。

还有一条，事件上的 time 和 endTime 都是字符串，你要把它和事件上的日期对象拼成完整的时刻。请写一个内部的辅助函数，接收日期对象和那个时间字符串，返回一个毫秒数，小时和分钟从字符串里取，年月日从日期对象里取，秒和毫秒给零。字符串不合法就返回空，返回空的事件一律不参与重叠计算。注意这里有个坑，结束时间可能比开始时间早，比如原文写成晚上十点到凌晨一点，这种跨午夜的情况请直接不算重叠，把它当成信息不足处理，不要猜它跨了几天。

最后是测试脚本。请你写一个命令行脚本，用 node 直接跑，不依赖任何测试框架。它要构造一批事件去调上面那个函数，然后断言结果。至少要覆盖下面这些情况。第一，答辩十四点到十六点和讲座十五点到十七点在同一天，必须产生一条 overlap 提醒，并且重叠时长是一小时，重叠时段是十五点到十六点。第二，活动甲十六点结束，活动乙十六点开始，同一天，必须一条 overlap 提醒都不产生。第三，同一天有两项 deadline，必须产生一条 cluster 提醒，并且一条 overlap 都不产生，标题里不能出现冲突两个字。第四，只有一个开始时间没有结束时间的活动，不能产生 overlap，要产生 needEndTime，并且这条提醒里不能出现任何确定的时长数字。第五，不在同一天的两个活动，即使钟点一样也不产生 overlap。第六，已办理的截止事项不进集中提醒。第七，formatDuration 这个辅助函数要单独测，六十分钟是一小时，九十分钟是一小时三十分，四十五分钟是四十五分钟，一百二十分钟是两小时。第八，同一个事件对不会被算成两条重叠提醒，请把结果里 overlap 类型的条数断言成正好一条。脚本结尾请统计通过和失败的数量，失败要把期望值和实际值都打出来，并且失败时退出码给一，通过时打印一行总结。时间在测试里请写死成固定的日期，不要用当前时间，不然过几天就跑不过了。

请输出这两个新文件的完整内容，不要输出改动片段，因为是新文件。改完我本机跑，跑不过再回来找你。
```
