# 083 第五轮静态断言改钉新日期输入实现

## 背景

081 到 082 把通知发布日期从浏览器原生日期控件换成受控文本输入后，
`npm run test:round5` 三条静态断言报红。这三条钉的是旧实现的存在性，
属于需求变更后断言过期，不是功能回归。按 Dec-031 不许把期望值改成实际值了事，
要改成钉住新行为，并按 Dec-024 注入坏实现验证会报红。

## 本机已核验事实

报红的三条是弹窗 有日期输入框，弹窗 日期框受状态控制，弹窗 日期框变化会回写状态。
分别找的是旧控件类型，旧受控写法，旧回写写法。
其余 43 条业务断言与末尾两条金丝雀全部正常。
新组件用本地草稿 state，导入日期解析模块，有中文示例占位与中文错误提示，
失焦回显标准写法，留空立刻回传空串。

## 验收要点

第一，三条改成能覆盖新行为的静态断言，条数只增不减。
第二，含一条反向断言，确认不再出现旧的日期控件类型。
第三，断言挑不可替换的具体行为，不许只查一句通用注释。
第四，其余断言和金丝雀一条不动，只输出改动片段。
第五，应用后当场改坏生产组件，断言必须报红，还原后与干净副本逐字节一致。

## Prompt

```
我把通知发布日期那个框换成普通文本输入之后，第五轮自检回归有三条报红，都是弹窗那边的静态断言。我看了一下，那三条还在找原来那种日期控件的写法，还有原来的受控写法和回写写法，现在当然找不到了。这不是功能坏了，是断言钉的是旧实现。

能不能帮我把这三条改一改，改完它们要能钉住现在的新行为，不是简单删掉，也不是把预期从成立改成不成立就完事。我希望能有一句反向断言确认界面上不再出现那种半中半洋的日期控件，还要能确认现在是普通文本输入，空着的时候有中文示例文字，输入用本地草稿接着所以打字中间态不会被吞，填进去的日期会转成页面原来保存的那种纯数字带短横线写法再回写，留空会立刻回传空值，填错有中文提醒，原来那句留空保持待确认的说明还在。

另外请帮我留意一件事，我之前吃过亏，断言写完永远全绿，其实是把失败洗成通过了。新断言要挑不可替换的具体行为，我改完会当场把组件里的实现改坏一次，确认这些断言真的报红，再还原。

只给我需要改的那几段代码，标明文件路径和要替换的原文，不要输出整份文件。其余断言和末尾两条金丝雀一条都不许动。改完我本机跑全量回归，跑不过再回来找你。
```
