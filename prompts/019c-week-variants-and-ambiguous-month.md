# 019c 口语周级变体 + 歧义月份不再硬算 + 修正写错的用例

## 背景

019b 交付后本机三层验收的结果， successes 与 defect 并存。

### 一、做得好的部分

- **注释全部恢复**：`git diff --numstat` 由 019 时的 aiExtract 增 3 删 12、
  extractNotice 增 4 删 18，变为增 44 删 1 与增 140 删 3。原来那些解释都回来了。
- **断网可跑**：移走 `.env.local` 后 `test:relative` 照常出结果。
- **主要说法全部命中**：过三天、过五天、一个月后、两个月内、三个月后均有正确值。
- **跨月跨年正确**：2026-11-01 三个月后落到 2027年2月1日，2026-12-31 加两个月到 2027年2月28日。
- **月末溢出被拒绝**：2026-11-30 三个月后 = 2027年2月28日，没有溢出成不存在的 2 月 30 日。

### 二、两个真实缺陷

本机穷举注入发现：

| 说法 | 结果 | 判断 |
|---|---|---|
| 过一周 / 过两周 | null | **遗漏**，与「过三天」同属口语无后缀，却没覆盖周级 |
| 三月之后 | 2027年2月1日 | **违反宁缺勿滥** |

「三月之后」有歧义：可能是「过了三月份」，也可能是口语省略的「三个月之后」。
现在一律按后者硬算，**属于 Dec-021 要防的假非空**——看起来像答案，
但对这个歧义它只有一半概率是对的，且界面完全无感。

按 018 立下的分工原则，这种歧义应当返回 null，交回给擅长语义的模型判断。

### 三、一条假失败：测试用例自己把基准日期写错了

```
[70/94] FAIL - 跨年：2025-11-15 三个月后 = 2026年2月15日
    期望：2026年2月15日
    实际：2027年2月15日
```

本机用生产模块直接对比两种基准：

```
基准 2025-11-15 三个月后 = 2026年2月15日   ← 用例名与期望值按这个写的
基准 2026-11-15 三个月后 = 2027年2月15日   ← 常量实际构造的
```

而脚本里 `const NOW_NOV15 = d(2026, 11, 15)`，常量是 **2026**，
注释也明写着「2026-11-15 周日」，只有用例名和期望值照 2025 写。

**结论：生产代码零 bug，是用例自身构造错误。**
这是 Dec-023 假通过的对偶形态——**假失败**，且同样危险：
若不看清楚就去"修"生产代码，反而会引入真正的 bug。

### 四、由此得到的一条新原则

Dec-031 原本讲「期望值本身也可能是错的」。这次是同一类问题的另一种入口：
**喂给被测函数的输入，也可能与用例描述不符。**
因此排查失败的用例时，不能只审期望值，必须同时核三样：
输入构造、用例描述、期望值，三者要对得上。

## 验收要点

**零、先验它不是把期望值改了凑绿（对应 Dec-031 与 Dec-039）**
必须看 scripts/test-relative-dates.mjs 里 NOW_NOV15 常量及其用例的 diff。
如果只见到期望值从 2026年2月15日 改成 2027年2月15日，
而常量与用例名没改，一律打回——那是把错题答案改对。
正确做法是常量、用例名、期望值三者统一。

**一、口语周级必须有值**
过一周、过两周。建议再顺手验过十天这种大数。

**二、歧义必须返回空**
三月之后、两月之后这类没有明确量词的说法，一律 null，交给模型判断。
同时确认「三个月后」这种带明确量词的仍然正常——这就是防误杀的双向验。

**三、宁缺勿滥的其他项不能被带坏**
半月后、半个月后、三个工作日、隔天、不久、近日，仍然必须是 null。

**四、断网可跑**
改完再移走 .env.local 跑一次。

**五、金丝雀仍要咬人**
现有坏实现注入必须报 FAIL。

**六、全量回归不可省**
test:relative test:sample test:calendar test:manual test:extract 全绿。

**七、本机先验**
交付后本助手会亲自跑穷举注入，不只信它自带脚本。
