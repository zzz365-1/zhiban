## 本机定位结论（2026-10-31 11:44）

用户报告「测试了两条但好像并没有成功」。本机复刻请求体直连 API 验证后确认：**服务端链路是通的**，
`deepseek-flash` 正常返回，`thinking: { type: "disabled" }` 参数被接受，页面左侧确已出现「AI 辅助」标签。

真正的问题有三处，且性质完全不同：

### 缺陷一：AI 独有字段没有出口（界面层）

`AnalysisPanel` 的 `FIELDS` 常量只有五个旧字段：deadline、time、location、materials、audience。
而 `mergeAIResult` 产出的 **title、summary、category 三个 AI 独有字段从未被渲染**。

也就是说 AI 干了活，用户一个字都看不见。这是最致命的一处，因为它让整个 006 的价值**在界面上为零**。

### 缺陷二：日期与时间在合并时被拆散（逻辑层，最严重）

`mergeAIResult` 逐字段按「本地优先」合并：

```js
deadline: base.deadline || aiResult.deadline
time:     base.time     || aiResult.time
```

本地规则在一条双日期通知上抽到的 `time` 是 **19:00**，那是「活动开始时间」，
而 AI 给出的是 **12:00**，才是「交伴奏材料的截止时间」。

按现有写法，本地 `deadline` 为空 → 采用 AI 的 11月18日；本地 `time` 非空 → 保留 19:00。
**结果是把 AI 的日期和本地的时间拼成了一条新的、原文里根本不存在的时间点。**

这个错误的杀伤力在于它是**静默的**：界面上每一格都填了值，看起来完全正常，
但导出的日历文件会落在错误时刻。004 的全部工作由此失效。

根因是 deadline 与 time 必须**成对同源**，不能逐字段独立择优。这是把「数值合并」误当成「语义归并」。

### 缺陷三：降级过程不可观测

`handleParse` 的 catch 分支只写 `console.warn`，页面无任何提示。
用户无法区分三种状态：AI 未被调用（本地已够好）、AI 调用失败、AI 返回空。
演示现场被提问时无法回答，这是 25% 答辩环节的隐患。

### 顺带确认：用户以为的「失败」其实是对的

用户第一条测试原文为「下周三下午之前交，地点群里通知。」——
这句话确实不含可用的时间与地点，模型返回 null。**模型拒绝编造，这是正确行为**，
已在 Prompt 中让学生表达认可，避免把正确的设计当成缺陷返工。

这条很重要：它说明 AI 的「不做」和「做不到」是两回事，写进答辩材料能体现对模型行为的理解。

## Prompt 正文

```
按你说的改完之后我测了两条，有个地方我觉得不太对，想让你帮我看看。

第一条我粘贴的是一句很随意的话，"下周三下午之前交，地点群里通知"。结果除了一句 下周三 之外，时间地点材料全都没识别出来。我一开始以为是模型没调用成功，后来发现旁边标签显示 AI 辅助，说明它其实已经跑了。我觉得它可能是对的，这句话本来就没写清楚时间地点，它不敢瞎编反而是好事。这个我基本认可，不算问题。

真正的问题在第二条。我粘了一条本地规则识不出来的通知，模型确实出手了，日期也补上了，而且补得比本地规则准。但是我盯着右边那一栏看了很久，感觉跟以前一模一样，一点变化都没有。我猜是因为模型多给我的那些东西，比如一句话摘要、通知分类这些，界面上压根没地方显示。我花了钱请它干活，结果干完活我看不见，这个肯定不行。能不能把摘要和分类加到右边那一栏里面去，另外也让我一眼能看出来这次到底是本地识别的还是叫模型帮忙了。

还有一个更严重的问题，我不确定是不是我看错了。那条通知里有两个日期，前面那个是活动开始的时间，后面那个才是真正要赶的截止时间。我发现右边显示的日期是对的，用的是模型给的那个，但是时间那一格显示的是 19:00，正好是前面那个活动开始的时间。也就是说日期用了模型的，时间却用了本地规则的，两个凑不到一块去，等于整条还是错的。这个如果不改，日历导出来的时间也是错的，前面做的就全白搭了。你帮我查一下是不是合并的时候有优先级写反了。

最后一件事。现在如果模型没配好或者网络不通，页面会一声不响地退回本地规则，我根本不知道刚才那次到底有没有叫模型。演示的时候这挺危险的，别人问起来我没法回答。能不能在右边加一行小字告诉我这次的结果是怎么来的，比如本地规则识别的，或者模型补充的，或者模型没接上已退回本地。不用弹窗，一行小字就行。

这一步只改这三处，别的功能不要动。老规矩，每个文件的完整代码给我，我在 VS Code 里粘。
```

## 设计点

1. **先肯定模型做对的部分**：开头那条「没识别出东西」学生自己判断为「不算问题」。
   这既避免了把正确设计当缺陷返工，也向评委展示参赛者理解「模型拒绝幻觉」的价值。
2. **把界面问题说成「花了钱看不见」**：这是最真实的用户视角，比「缺少字段渲染」有力得多。
3. **日期时间错配由学生自己发现并给出证据**：19:00 与 12:00 的对照具体到数值，
   AI 不需要猜就知道该怎么查，同时也再次证明「本机先验」流程的价值。
4. **可观测性要求是演示驱动的**：「别人问起来我没法回答」把技术需求转成了真实场景压力。

## 验收标准

- 右侧面板显示摘要与分类，AI 未被调用时这两项应为空而非报错
- 面板显示本次来源标识，至少区分 本地规则 / 本地加模型补充 / 模型不可用已退回
- deadline 与 time 必须来自同一来源，不得交叉拼接
  - 本机用例：通知含 11月22日19:00 决赛 与 11月18日12:00 交伴奏，
    期望结果 deadline 为 2026年11月18日 且 time 为 12:00
- AI 不可用时页面有一行可见提示，不再只写控制台
- 提供不需要点页面的本地验证手段
