# 022 符号检查器放行网址链接

> **当前状态：暂不需要，未投喂。**
> 原因：链接是外部内容，不进程序也不进归档。归档的提示词正文改用「前面那个链接」指代，
> 链接由用户发消息时自行粘贴在开头，因此检查器不会遇到 URL，不需要修改。
> 本文件保留作备用——**若将来决定把链接直接写进归档正文**，再投喂本提示词。

## 背景

2026-11-02 用户澄清一条规则边界：**提示词正文里出现网址链接是允许的**。
理由是链接由对话平台的分享功能生成，属于客观内容，冒号斜杠点是网址自带的结构，
不属于"正文禁用排版符号"要管的那一类。此前本项目把链接拆成单独一条消息发出去，
就是为了绕开这条限制，现在不需要了，链接可以直接写进正文。

但符号检查器不认识网址，把 URL 里的冒号、斜杠、点全算成违规：

```
违规  :x1 /x4 .x2      019g-relative-suffix-and-unit.md
当前标准：合规通过，违规 7 处
```

这是**工具规则没跟上，不是提示词真违规**（Dec-038 的对偶形态：
工具的结论同样要先证伪，不能照单全收）。

## 设计口径

- 识别方式：**匹配 http 或 https 开头的整串**，整串跳过，不计入违规统计
- 必须是"识别模式"，**绝不能做成豁免名单**。Dec-043 明令禁止用名单把既有违规洗成历史，
  这次也一样，名单形式会在下一轮继续被滥用
- 只放行 URL 串本身。URL 后面跟着的中文正文仍然照常检查，
  不能因为一段里出现了网址就把整段都放行
- 仓库里已经推送的文档（`.env.example`、环境说明等）里可能本来就有点号和斜杠，
  但它们不在被扫描的提示词正文块里，不受影响，不要为了它们放宽规则

## 验收要点

1. 含 URL 且其余干净的正文 → 违规 0 处
2. 不含 URL 且干净的正文 → 违规 0 处
3. 不含 URL 但含顿号的正文 → 报错，违规数大于 0
4. **含 URL 同时含顿号的正文 → 必须报错**（这条最关键，防止"一段里有网址就整段放行"）
5. 工具必须自带这四种样本的自校验，四种判定全对才算通过
6. 扫到零个对象必须当场报错，不许渲染成通过（Dec-043）
7. 正则一律用字符类，禁止反斜杠加数字（Dec-013）
8. 原有命令一条都不能删，改完跑全量回归（Dec-027）
9. 禁止把期望值改成实际值了事（Dec-031）

## Prompt

```
我又发现一个小问题，想请你帮我改一下。

我这边有一个小工具，是用来检查我写的提示词里有没有乱用符号的。规则是正文里只许出现逗号句号问号，别的符号都不许有。可是我今天写提示词的时候，在正文开头放了一个网址链接，结果这个工具直接报了七个违规，把网址里面的冒号斜杠还有点都算成违规符号了。

我觉得这样不太对。那个网址不是我自己打出来的符号，是对话平台的分享功能自动生成的分享地址，冒号斜杠点都是网址本来就有的结构，跟我乱用符号不是一回事。所以我想让这个工具碰到网址的时候直接跳过去不要算违规。

不过有个地方你帮我注意一下。我希望它是真的能认出网址然后跳过，不是做一个名单把这几个符号直接放开。之前我们踩过坑，用名单的话以后什么都能往名单里塞，检查就废了。所以我的想法是让它认出 http 或者 https 开头的那一整串，这一整串跳过，别的一个都不放过。

还有一个情况你一并考虑一下。网址后面一般还跟着我写的中文，比如网址后面接着写这是我们的沟通记录你先看一下。网址跳过之后，后面这句中文还是要照常检查的，不能因为一段里出现了网址就把整段都放过去了。

改完麻烦你帮我验一下下面这四种情况，四种都得对才算过。第一种，有网址而且别的地方都干净，应该是零违规。第二种，没有网址而且都干净，也是零违规。第三种，没有网址但是混进了顿号，这个必须报错。第四种最要紧，有网址同时又混进了顿号，这个也必须报错，不能因为有网址就整段放过。

另外请你确认一下，如果一份提示词都没扫到，它要直接报错说没扫到东西，不要显示成检查通过。

还有几件老规矩。写正则一律用字符类，不要出现反斜杠加数字。那个存各种命令的文件里原有的命令一条都不能删，特别是那条查密钥的。改完把所有命令都跑一遍把结果给我。回复的时候不要把这个文件整个重新输出一遍，只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。如果改动分散在好几处，就一处一处分开说清楚，每处都标明大概在第几行。

我不太懂正则，如果哪里说得不对，你按你的判断来就好。
```
