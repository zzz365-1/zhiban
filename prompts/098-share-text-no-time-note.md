# 098 文字汇总不显示内部排序时刻

## 背景

数据层已经把没有明确时刻的通知的排序基准改到当天零点，摊平事件也不再把它塞进时间字段。
但整理成文字那段话还是照着时间戳直接打印时分，于是原来冒17:00，现在变成冒00:00。
同学要的是只有日期就只显示日期，另外注明具体时刻未说明。

## 本机已核验事实

本机实跑生产模块，097 落位之后，汇总文字当前输出是

11月5日 17:00 - 关于2026年国家助学金评审工作安排的通知（地点：学生工作处A302办公室，材料：纸质申请表）
11月9日 00:00 - 关于本季青年大学习网上主题团课的通知
11月10日 15:00 - 关于2026年国家助学金评审工作安排的通知的补充通知（地点：行政楼B201会议室）
11月12日 00:00 - 关于核对2026级本科生学籍信息的通知
11月14日 14:30 - 学术讲座通知（地点：图书馆报告厅）

其中 11月9日 和 11月12日 两条原文都只有日期，没有具体时刻。
11月5日 17:00 与 11月14日 14:30 两条原文写了明确时刻，这两行一个字都不能变。

生成汇总文字在 shareText.js，导出三个函数。
formatShareDateTime 收一个时间戳，当前直接取小时和分钟拼成 月日 空格 时分。
buildShareText 收通知数组、当前时间、天数范围，先调 filterShareNotices 筛选，
再逐条用 formatShareDateTime 拼出 stamp，后面接标题，再接地点和材料。
判断有没有明确时刻的依据应该看通知分析结果里的具体时间字段，
算截止时间的那个文件里已经导出了 hasExplicitTime 和 NO_TIME_NOTE，可以直接引用。

另有一份自检脚本 scripts/test-share.mjs，它 import 的正是 shareText.js。
脚本里 makeNotice 手工造了一批测试通知，deadlineDate 传的是带时刻的时间戳，
可是 analysis 里具体时间字段全是 null，跟真实保存出来的通知不自洽。
脚本里有两条断言钉死了 10月31日 18:00 - 通知A 和
11月2日 17:00 - 通知C（地点：A101，材料：申请表）这两行文字。

## 验收要点

第一，没有明确时刻的通知，汇总里只显示日期，后面跟具体时刻未说明这句说明文字，
不许出现 00:00 或 17:00 或别的时刻。

第二，有明确时刻的通知，汇总文字逐字不变，特别是上面钉死的那两行。

第三，说明文字要引用已经导出的那个常量，不要自己再写一遍中文。

第四，自检脚本那批手工构造的通知要让分析结果里的具体时间字段与时间戳自洽，
断言的期望文字一个都不许改，不许把期望改成实际值了事，也不许删断言。

第五，只输出成对改动片段，不重写整个文件，不动筛选和排序逻辑。

## Prompt

```
接着刚才那个问题，我把算截止时间的那处改完以后又试了一次，工作台和日历不乱冒时间了，可点整理成文字那段话里，原来写下午5点的地方现在变成零点了。这两条通知原文都只写了11月9日前和11月12日前，通篇没说几点，我还是希望这里就只写日期，然后老老实实注明具体时刻未说明，别带任何时刻出来。判断的时候请直接看通知分析结果里那个具体时间字段是不是空的，别再从时间戳上反推了，之前就是反推才出的问题。算截止时间那个文件里已经有现成的判断函数和那句说明文字的常量，直接拿来用就好，别自己再写一遍中文。另外我们有一份自检脚本，里面手工造了一批测试通知，时间戳是带时刻的，可分析结果里具体时间字段全是空的，跟真实存下来的通知对不上。麻烦把这批构造数据补自洽，脚本里那几条钉死文字的断言一个字都别动，也别删。有明确时刻的通知，比如11月5日下午5点那条和11月14日下午两点半那条，汇总出来必须跟现在一模一样。只把要改的行改前改后写出来就行。
```
