# 知办 zhiban — 校园通知行动助手

把一条校园通知，变成一件可以立刻执行的事。

粘贴通知原文，系统拆出要办的事项、时间、地点和要带的材料，
排成一条可核对的办理路线，同步到日历，并在补充通知到达时对比新旧安排。
所有数据只存在本机浏览器，不上传服务器，不需要注册登录。

**本项目是第九届传智杯 AI 创新应用挑战赛参赛作品。项目中的产品代码由 DeepSeek 按归档提示词生成，
学生负责需求拆解、提示词编写、本机验收与返修，完整过程见第七节。**

## 作品速览

**解决的校园实际问题。** 校园通知常把好几件事写在同一段话里，时间写法五花八门
（「下午5点」「下周三」「11月5日前」），要带的材料散落在长句中，发完还可能再来一条
补充通知改时间改地点。同学真正需要的不是一份摘要，而是「我要做什么、什么时候、
去哪、带什么、凭哪句话」，以及改期之后旧安排会不会跟着变、办过的事会不会被冲掉。
知办把这件事收窄成一个面向行动项的窄任务，不做通用文档理解。

**已实现功能。** 粘贴或多条批量导入通知，自动拆出办理事项并标注时间类型（办理截止／活动开始）、
日期时间、地点、材料清单与原文依据；材料逐项可勾、事项可标记完成与撤销；
工作台按待确认、即将截止、待办理分组；大日历按事项摊平展示；
文字汇总可一键复制；时间冲突、截止事项集中、缺结束时间三类提醒；
补充通知须用户手选原通知、对比新旧安排并确认后才更新，保留修改历史；
重复导入分完全相同、疑似重复、标题相同内容不同、全新四档，可查看已有、跳过或明确另存。

**两个主要亮点。**

1. **可核对的办理路线**：每个事项的名称、时间、地点、材料都带一条原文依据，
   点结果字段会选中原文对应那句话；展示值与原文写法不一致时（例如展示 17:00、
   原文写「下午5点」）由出处核对做归一化反查。「通知要求」与「系统建议」分区展示，
   原文没写具体时刻就注明「具体时刻未说明」，不擅自补 17:00 或 23:59。
2. **补充通知对比与安排同步**：改期通知不自动覆盖，先列出变化前、变化后与依据原句，
   确认后只改被提及的字段，未提及的要求保留，已完成事项不回退，
   日历只留新安排一次，每次更新写一条可回看的变更记录。

## 一、10 分钟极速复现指南

面向第一次拿到本仓库的人。按顺序做即可，不需要理解实现细节。

### 前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | 20.9 或更高，本项目在 v22.22.2 上开发验证 | 官网 https://nodejs.org 下载 LTS 版 |
| npm | 随 Node.js 一起安装 | 用于安装依赖 |
| Git | 任意近年版本 | 用于克隆仓库 |
| 网络 | 仅首次 `npm install` 需要 | 安装完成后的自检与核心体验全部离线 |

### 步骤

```bash
# 1 克隆仓库
git clone https://github.com/zzz365-1/zhiban.git
cd zhiban

# 2 安装依赖，约 3 到 5 分钟
npm install

# 3 配置模型密钥，这一步可以整步跳过，见下一节
cp .env.example .env.local
# Windows CMD 用 copy .env.example .env.local，PowerShell 用 Copy-Item
# 用任意编辑器打开 .env.local，把等号后面换成你自己的 DeepSeek Key

# 4 启动
npm run dev
```

浏览器打开 **http://localhost:3000**。首次访问会先看到欢迎页，点「进入工作台」即可。

### 没有密钥也能完整体验

**如果你没有 DeepSeek 的 Key，请直接跳过第 3 步，应用照常启动，核心流程全部可用。**

这是刻意设计的降级路径：模型不可用时自动回退到本地规则引擎。
解析结果页顶部显示「本地规则识别」或具体的降级原因短标签，
保存后的通知详情来源标签显示「本地识别」，而不是「模型补充」。
填了通知发布日期之后的相对日期换算、事项拆分、办理路线、
材料勾选、日历、整理成文字、补充通知对比、冲突提醒全部照常工作，只有开放式语义抽取会弱一些。
日历文件导出已改为命令行方式（`npm run export:ics` 需带参数），界面上不再提供下载按钮。
2026-11-05 在独立干净目录、完全不配 `.env.local` 的条件下按本节步骤实跑过一遍，
接口 `/api/parse` 返回 `no_key`，浏览器里仍然完成了「新增通知 → 解析 → 保存 → 工作台」整条路线。

这个「弱一些」我们量过，分母是人工逐条判断有值的那些条，不是全部素材。
100 条真实校园通知里，人工判断有截止日期的是 91 条、有地点的是 70 条，
剩下 9 条没写日期、30 条压根没写地点，这类通知程序给空本来就是对的。

| 口径 | 截止日期 | 地点 |
| --- | --- | --- |
| 降级路径，本地规则 | 85 / 91，约 93% | 68 / 70，约 97% |
| 接模型路径 | 88 / 91，约 97% | 68 / 70，约 97% |

一条命令就能复现这两个数字，全程不联网、不要密钥：

```bash
npm run coverage
```

它现场跑降级路径，接模型路径读 `scripts/batch-run-031.mjs` 已经产出的报告，
不重复调用模型，跑完会把哪几条没抽到、人工判的是什么一起列出来。

**换句话说：评委不需要我们的密钥，也不需要联网，就能把应用跑起来并走完整条流程。**
需要如实说明的是，走本地规则路径时字段覆盖率低于接模型的水平，
第六轮 48 条评测语料的逐条结果见 `docs/eval-report.md`。

如果配置了密钥但调用失败，超时、网络异常、返回格式非法各有独立文案，
界面会明确显示具体原因并保留用户输入的原文，不会静默假装成功。

## 二、5 分钟走一遍核心功能

1. 首次进入是欢迎页，点「进入工作台」；也可以点「体验示例」直接载入标注为「示例」的演示数据。
2. 工作台上点「新增通知」，粘贴一条通知原文，点「开始解析」。
3. 右侧结果区给出办理路线，一条通知可以拆成多个事项，每个事项有名称、时间类型、日期时间、地点、材料清单和状态。
4. 点结果里的字段，上方原文区会自动选中对应那句话，用来核对依据。原文在上、解析结果在下，是上下分区，内容多时各自滚动。
5. 材料可以逐项勾选，事项可以标记完成和撤销，刷新页面后仍然保留。
6. 点「保存到我的通知」，之后在「我的通知」「日历」「变更记录」里都能看到它。
7. 收到补充通知时，再点「新增通知」粘贴，系统会让你手选要修改的原通知，
   显示变化前后与原文依据，确认后才更新，并同步刷新办理路线、日历和提醒。

一条可以直接粘贴的示例：

```
关于2026年国家助学金评审工作安排的通知
各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室。
评审会定于11月8日晚7点在行政楼A302会议室召开，请各班班长届时到场。
```

会拆成「提交纸质申请表」和「参加评审会」两个事项，
前者是办理截止 11 月 5 日 17:00，后者是活动开始 11 月 8 日 19:00，
各自带自己的地点，不会串。「下午5点」和「晚7点」都能在原文里定位到。

**演示数据说明**：欢迎页的「体验示例」和工作台右上角的「载入示例通知」插入的是
`app/lib/sampleNotices.js` 生成的**示例数据**，界面上有「示例」来源标签和「示例数据」紫色角标，
只往前插不清空你自己保存的通知。不配密钥时走的是**本地解析模式**，来源标签显示「本地识别」。
演示素材自检命令是 `npm run demo:check`，`docs/demo-notices.md` 里有 10 条示例原文，
`docs/demo-script.md` 里有 13 步演示流程。

**示例数据怎么载入、怎么用。** 两个入口：首次进欢迎页点「体验示例」，
或在工作台点右上角「载入示例通知」。两者都只往列表前面插入、不清空已有数据，
插入的条目带「示例」来源标签和「示例数据」角标，可在筛选里单独看或跳过。
想用自己准备的通知，直接点「新增通知」把 `docs/demo-notices.md` 里任一整段原文
粘进文本框再点「开始解析」即可；不需要先载入示例。
`docs/demo-outline-2026-11-05.md` 给出一条 7 步正式演示路线。

`package.json` 共 39 个 npm 脚本。上面这一节列出的 **34 条是校验命令**：
其中 33 条离线运行（零网络、零密钥），`check:key` 单独一条用于验证密钥配置、

`npm run test:round7` 132 条断言通过、2 条金丝雀按预期报差异。

## 五、技术栈与依赖

| 类别 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | 20.9 及以上，实测 v22.22.2 | 运行时 |
| Next.js | 16.3.8，App Router | 前端框架与服务端模型出口 |
| React | 19 | 界面 |
| react-dom | 19 | 渲染 |
| Tailwind CSS | 4.1.0 | 样式，配合 `@tailwindcss/postcss` 4.1.0 与 `postcss` 8.5.0 |
| DeepSeek | 生产用 `deepseek-flash`，代码生成对话用 `deepseek-chat` | 开放式语义抽取 |

零数据库、零外部服务依赖。通知数据存在浏览器 `localStorage` 的 `zhiban.notices.v1`，
另有 `zhiban.welcomed` 记录是否看过欢迎页；刷新后保留，同一浏览器多个标签共享。
**实际使用限制**：换浏览器、换设备、清理站点数据、使用无痕窗口都会丢失，
没有账号体系、没有云同步、没有服务端备份，也不支持多人协作。
解析时通知原文只在本机内存中处理；只有配置了模型密钥时，
服务端 `/api/parse` 才会把原文发给模型接口做语义抽取，密钥不落盘、不进日志。
这是刻意选择：不收集任何个人信息，代价是数据不做跨设备持久化。

### 环境变量

只需一个变量，模板在 `.env.example`：

```
DEEPSEEK_API_KEY=sk-在这里粘贴你自己的key
```

复制成 `.env.local` 后填入自己的 Key。`.env.local` 已被 `.gitignore` 忽略，
**真实密钥不进代码、不进文档、不进仓库**。不配置也能用，见第一节。
模板文件 `.env.example` 只有占位符，没有任何真实密钥。

| 变量名 | 必填 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 否 | 只在服务端 `app/api/parse/route.js` 读取，浏览器端拿不到 |

模型配置方式是固定的：服务端向 `https://api.deepseek.com/chat/completions`
发送单轮请求，模型名 `deepseek-flash`，`stream: false`，20 秒超时；
提示词由 `app/lib/parsePrompt.js` 构造，返回结果与本地规则结果由
`parseOne.js` / `aiExtract.js` 融合，并经过 `grounding.js` 回原文核对。
代码生成对话使用 `deepseek-chat`，那是开发期工具，与运行时模型不是同一处调用。
未配置、超时、网络异常、返回为空、格式非法各有独立错误码与界面文案，
不会静默假装成功。配置后可用 `npm run check:key` 验证（该命令会发起一次模型请求），
其余校验命令一律不读密钥。

## 六、核心设计思路

一句话概括：**用最小的模型能力解决最大的语义难题，其余全部交给确定性代码。**

模型擅长理解自然语言，不擅长算术，也不保证不编造。所以本项目做了三件事。

**1 相对日期交给本地代码算。**「下周三」「三天后」这类说法，早期交给模型换算，
实测约 1/20 概率算错，把 temperature 设为 0 也消除不了。现改为本地纯函数
`relativeDate.js` 换算，提示词要求模型原样返回相对说法、不要自己算。

**2 模型输出必须回原文溯源。**`grounding.js` 把模型返回的日期、时间、地点、材料、
面向对象回原文找依据，找不到即置空并记录原因。提示词里写「不许编造」只是要求，
代码里回查才算约束。

**3 只有确定的信息才做确定的判断。**第五轮的冲突提醒只在两项活动都有明确开始和
结束时间时才计算重叠，一项结束等于另一项开始不算撞车，只有开始时间时只提示
「结束时间待补充」，绝不假设活动一般开多久。同一天多个截止叫「截止事项集中」，
不叫冲突。

**4 不自动改官方通知。**补充通知必须用户手选原通知、看过变化前后对比、点确认才落盘，
未提及的字段保留，歧义先确认不覆盖，每次更新都留修改历史。

### 开发工具链与运行时模型是两件事

这里特意分开说明，避免把「谁帮我们写代码」和「应用运行时调谁」混为一谈。

**开发期，把代码写出来。** 学生始终是决策方：定义问题与痛点、划定架构边界、
编写每一条提示词、给出验收口径、判断模型产出能不能要、发现缺陷后拍板返修。
WorkBuddy 作为 AI 助手协同做架构梳理、提示词打磨、代码片段落位、
本机实跑验收、回归与文档整理。具体产品代码由 DeepSeek 对话按归档提示词产出，
早期手工粘贴，后期由 `scripts/ai-patch.mjs` 读取归档提示词调用对话式模型，
回复先落到待审文件，逐片段核对唯一命中后才落位生产代码。
全过程没有事后补造对话，提示词全文在 `prompts/`，返修往返与真实提交可逐条回溯。

**运行期，应用跑起来之后。** 应用自己通过 `app/api/parse/route.js` 调用
`deepseek-flash` 做开放式语义抽取，密钥由使用者写进自己的 `.env.local`。
这是产品的一个可选增强功能，与开发时用的工具完全无关。
模型不可用就回退本地规则，所以评委不配密钥、不联网也能走完整条流程。
除开放式语义抽取外，相对日期换算、出处核对、事项拆分、日历构造、
冲突判断和落盘全部是本地确定性代码，不调用任何模型。

## 八、已知边界，诚实说明

以下尚未解决，不夸大：

- 「半个月后」「半年后」等相对说法、区间日期、周期性时间、「原定 X 推迟至 Y」的改期语义，
  本地规则尚未完全覆盖，会标待确认或留给模型处理。
- 材料提取是开放集合，中文「要带什么」的写法近乎无限，无法保证穷尽。
  第六轮 48 条评测里材料漏抽 4 件、误抽 0 件，误提防线有效但覆盖面还不够。
- 部分通知在本地规则路径下拆不出事项，界面会显示「这条通知里没有拆出具体事项。」，
  此时可以点顶部「重新解析」，或在接模型路径下重试。
- 事项名已改为按原文动作生成（最后一轮 `prompts/101`），不再把没有提交要求的通知一律叫「提交材料」；
  但动作判断不出来的写法仍会谨慎回退成「待确认办理事项」或「参加活动」这类名称，
  48 条评测里事项名正确率 65.5%，见 `docs/eval-report.md`。
- 多句通知里偶尔出现日期或地点串到相邻事项的情况。
- 模型路径的准确率依赖使用者自己的 Key，交付材料里无法复现，
  README 中的接模型数字来自此前已经跑完并留档的批量报告。
- 数据只存本机浏览器，没有云同步，换设备不会带过去。
- 最终演示视频由学生按 `docs/demo-outline-2026-11-05.md` 与 `docs/video-record-template-2026-11-04.md`
  自行录制，**成片尚未产出**；技术说明 PDF、AI 迭代记录、提交清单与录制材料
  已整理在交付目录 `知办参赛材料/`，仓库里保留写作提纲 `docs/tech-doc-outline.md`
  与评审速览 `docs/feature-list.md`。

## 九、常见问题

**问：没有 DeepSeek Key 能跑吗？**
能。跳过第 3 步，全部核心功能可用，来源标签显示「本地识别」。这是无密钥演示模式。

**问：为什么解析结果和我预期的不一样？**
先点结果字段，看原文里被高亮的是哪句话。规则只能抽它认得的写法，
抽不到的字段会留空并标「待确认」，可以在界面上手动补齐。
`docs/eval-report.md` 里列了 48 种写法的实际表现。

**问：刷新之后数据还在吗？**
在，数据存在浏览器 localStorage。清理浏览器数据、换浏览器、用无痕窗口会丢失。

**问：示例数据会覆盖我自己的通知吗？**
不会，示例只往前插，且带「示例」标签，可以在筛选里单独看。

**问：模型调用失败会怎样？**
界面显示具体失败原因，原文完整保留，点「重新解析」可以重试，
不会把失败结果显示成一个看起来正常的解析结果。

**问：补充通知会不会自动改我保存的安排？**
不会，必须你手选原通知、确认对比表之后才更新，并且保留修改历史。

**问：`npm run build` 报错怎么办？**
先跑 33 条离线自检命令。本机曾遇到构建被安全软件的批量删除守卫打断，
与代码本身无关，把旧 `.next` 整体移走再构建即可。2026-11-04 已实测 `npm run build` 通过，
浏览器验收也跑在刚构建出来的生产产物上。

**问：怎么确认数字不是编的？**
`npm run coverage` 和 `npm run eval` 都会现场重跑并生成报告，
不联网、不读密钥，报告里连哪条没抽到都列出来。

**问：在完全干净的机器上照这份 README 真的能跑起来吗？**
2026-11-05 实测过一次：把 `cffa508` 导出的源码 ZIP 解压到独立空目录，
该目录没有 `node_modules`、没有 `.next`、没有 `.env.local`，
`npm install --offline` 45 秒装好 42 个包（联网时装得慢一些，
README 里按 3 到 5 分钟估），随后 8 条代表性自检命令全部 `exit 0`、
`npm run build` `exit 0`、生产服务返回 HTTP 200、
`/api/parse` 在无密钥时返回 `no_key`，浏览器里仍完成了
「新增通知 → 解析 → 保存 → 工作台」整条路线，页面无脚本异常。
完整记录见交付目录 `01_源码与复现说明/干净环境复现记录.md`。

**问：怎么确认我看到的截图、文档和代码是同一个版本？**
看本页开头的「本次交付版本」区块，核 `git log -1` 是否为 `cffa508`。
截图文件名带 `2026-11-05` 与编号 146 到 163，
自检报告是 `docs/self-check-2026-11-05-round7.md`。
若提交号不同，说明代码已更新，材料需要重新对应。
