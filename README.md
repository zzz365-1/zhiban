# 知办 zhiban — 校园通知行动助手

把一条校园通知，变成一件可以立刻执行的事。

粘贴任意一条通知原文，系统自动抽出截止时间、地点、面向对象、需带材料等要素，
判断紧急程度并分级标色，可导出日历文件，也能一键复制成待办清单。

---

## 一、10 分钟极速复现指南

这份指南面向第一次拿到本仓库的人。按顺序做即可，不需要理解实现细节。

### 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| Node.js | **20.9 或更高**（本项目在 v22 上开发验证） | 官网 https://nodejs.org 下载 LTS 版，一路下一步即可 |
| Git | 任意近年版本 | 用于克隆仓库 |
| 网络 | 首次安装依赖时需要 | 安装完成后的自检全部离线，不联网也能跑 |

### 步骤（约 6 分钟，主要在等依赖下载）

```bash
# 1. 克隆仓库
git clone https://github.com/zzz365-1/zhiban.git
cd zhiban

# 2. 安装依赖（约 3-5 分钟）
npm install

# 3. 配置模型密钥【这一步可以跳过，见下方说明】
cp .env.example .env.local
# 然后用任意编辑器打开 .env.local，把等号后面换成你自己的 DeepSeek Key

# 4. 启动
npm run dev
```

浏览器打开 **http://localhost:3000** 即可看到界面。

### 没有密钥也能完整体验

**如果你手头没有 DeepSeek 的 Key，请直接跳过第 3 步，应用依然可以正常启动和使用。**

这是本项目刻意设计的降级路径：模型不可用时，系统自动回退到本地规则引擎，
界面来源标签会显示「本地识别」而不是「模型识别」。此时相对日期换算、
分类分级、日历导出、复制摘要等全部照常工作，只有开放式语义抽取会弱一些。

换句话说：**评委不需要我们的密钥，也不需要联网，就能把应用跑起来并看到完整流程。**

如果配置了密钥但调用失败（超时、网络异常、返回格式非法等），
界面顶部横幅会明确显示具体失败原因，不会静默地假装成功。

## 二、怎么用

1. 打开页面，在输入框粘贴一条通知原文（空状态下界面自带 6 条示例通知，点一下即可填入）
2. 点「解析」，右侧结果区给出抽取出的字段
3. 字段可手动修改，修正后结果实时更新
4. 可导出 `.ics` 日历文件，或复制成一段待办文字

```
示例：

请各班班长于下周三前把班会记录表交到学生处一楼，
需带纸质版和电子版各一份，逾期不再受理。

→ 截止：下周三（本地自动换算为具体日期）
→ 地点：学生处一楼
→ 材料：班会记录表
→ 面向对象：各班班长
→ 紧急度：高（红色）
```

## 三、自检命令

本项目把「验证」当作一等公民。以下命令**全部离线运行，不依赖网络，不需要密钥**，
可用来复核代码行为的真实性：

```bash
# 配置与安全检查
npm run check:key        # 检查密钥是否配置正确
npm run check:prompt     # 检查归档提示词是否符合书写规范
npm run check:regex      # 检查代码中是否有过度转义的正则

# 功能测试（覆盖三块核心抽取能力）
npm run test:extract     # 规则引擎抽取
npm run test:location    # 地点抽取
npm run test:relative    # 相对日期本地换算（140 条用例）
npm run test:classify    # 分类值域校验
npm run test:grounding   # 反幻觉出处核对（37 条用例）

# 其他
npm run test:calendar    # 日历视图
npm run test:batch       # 批量粘贴
npm run test:title       # 标题生成
npm run validate:ics     # 日历文件导出校验
```

这些测试脚本都直接 import 生产模块，不存在另写一份「相似实现」的情况；
其中相对日期与反幻觉两组还包含**故意写错的金丝雀用例**，
用于证明「如果实现坏了，测试真的会报红」，而不是永远显示通过。

## 五、核心设计思路

一句话概括：**用最小的模型能力解决最大的语义难题，其余全部交给确定性代码。**

模型擅长理解自然语言，不擅长算术，也不保证不编造。所以本项目做了三件事：

**1. 相对日期交给本地代码算**

「下周三」「三天后」这类说法，早期交给模型换算，实测约 1/20 概率算错，
且把 temperature 设为 0 也消除不了。现已改为本地纯函数 `relativeDate.js` 换算，
提示词改为要求模型**原样返回相对说法、不要自己算**。覆盖范围内若出错，必是代码 bug。

**2. 模型输出必须回原文溯源**

新增 `grounding.js` 出处核对：模型返回的日期、时间、地点、材料、面向对象，
都要回原文找得到依据。找不到即置空并记录原因，界面可看到被丢弃的字段。
「提示词里写了不许编造」只是要求，「代码里回查」才算约束。

**3. 失败必须被用户看见**

密钥缺失、超时、网络异常、返回为空、格式非法——五种失败各有独立文案，
在界面横幅显示。绝不允许解析失败却显示成一个看起来正常的结果。

## 六、已知边界（诚实说明）

以下内容我们**尚未解决**，如实列出，不夸大：

- 相对日期中「半年后」「半个月后」「一季度后」等说法，本地尚未覆盖，会回退给模型处理
- 材料提取属于开放集合，中文表达「要带什么」的方式近乎无限，无法保证穷尽
- 时间区间（如「11月5日至10日开放」）与周期性时间（如「每周三下午例会」）尚未专门建模
