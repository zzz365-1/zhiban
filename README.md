# 知办 zhiban — 校园通知行动助手

把一条校园通知，变成一件可以立刻执行的事。

粘贴通知原文，系统拆出要办的事项、时间、地点和要带的材料，
排成一条可核对的办理路线，同步到日历，并在补充通知到达时对比新旧安排。
所有数据只存在本机浏览器，不上传服务器，不需要注册登录。

**本项目是智传杯 AI 创新应用挑战赛参赛作品。项目中的产品代码由 DeepSeek 按归档提示词生成，
学生负责需求拆解、提示词编写、本机验收与返修，完整过程见第七节。**

## 一、10 分钟极速复现指南

面向第一次拿到本仓库的人。按顺序做即可，不需要理解实现细节。

### 前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | 20.9 或更高，本项目在 v22.22.2 上开发验证 | 官网 https://nodejs.org 下载 LTS 版 |
| npm | 随 Node.js 一起安装 | 用于安装依赖 |
| Git | 任意近年版本 | 用于克隆仓库 |
| 网络 | 仅首次 `npm install` 需要 | 安装完成后的自检与核心体验全部离线 |

### 步骤

```bash
# 1 克隆仓库
git clone https://github.com/zzz365-1/zhiban.git
cd zhiban

# 2 安装依赖，约 3 到 5 分钟
npm install

# 3 配置模型密钥，这一步可以整步跳过，见下一节
cp .env.example .env.local
# 用任意编辑器打开 .env.local，把等号后面换成你自己的 DeepSeek Key

# 4 启动
npm run dev
```

浏览器打开 **http://localhost:3000**。首次访问会先看到欢迎页，点「进入工作台」即可。

### 没有密钥也能完整体验

**如果你没有 DeepSeek 的 Key，请直接跳过第 3 步，应用照常启动，核心流程全部可用。**

这是刻意设计的降级路径：模型不可用时自动回退到本地规则引擎，界面来源标签显示「本地识别」
而不是「模型识别」。填了通知发布日期之后的相对日期换算、事项拆分、办理路线、
材料勾选、日历、整理成文字、补充通知对比、冲突提醒全部照常工作，只有开放式语义抽取会弱一些。
日历文件导出已改为命令行方式，界面上不再提供下载按钮。

这个「弱一些」我们量过，分母是人工逐条判断有值的那些条，不是全部素材。
100 条真实校园通知里，人工判断有截止日期的是 91 条、有地点的是 70 条，
剩下 9 条没写日期、30 条压根没写地点，这类通知程序给空本来就是对的。

| 口径 | 截止日期 | 地点 |
| --- | --- | --- |
| 降级路径，本地规则 | 85 / 91，约 93% | 68 / 70，约 97% |
| 接模型路径 | 88 / 91，约 97% | 68 / 70，约 97% |

一条命令就能复现这两个数字，全程不联网、不要密钥：

```bash
npm run coverage
```

它现场跑降级路径，接模型路径读 `scripts/batch-run-031.mjs` 已经产出的报告，
不重复调用模型，跑完会把哪几条没抽到、人工判的是什么一起列出来。

**换句话说：评委不需要我们的密钥，也不需要联网，就能把应用跑起来并走完整条流程。**
需要如实说明的是，走本地规则路径时字段覆盖率低于接模型的水平，
第六轮 48 条评测语料的逐条结果见 `docs/eval-report.md`。

如果配置了密钥但调用失败，超时、网络异常、返回格式非法各有独立文案，
界面会明确显示具体原因并保留用户输入的原文，不会静默假装成功。

## 二、5 分钟走一遍核心功能

1. 首次进入是欢迎页，点「进入工作台」；也可以点「体验示例」直接载入标注为「示例」的演示数据。
2. 工作台上点「新增通知」，粘贴一条通知原文，点「开始解析」。
3. 右侧结果区给出办理路线，一条通知可以拆成多个事项，每个事项有名称、时间类型、日期时间、地点、材料清单和状态。
4. 点结果里的字段，上方原文区会自动选中对应那句话，用来核对依据。原文在上、解析结果在下，是上下分区，内容多时各自滚动。
5. 材料可以逐项勾选，事项可以标记完成和撤销，刷新页面后仍然保留。
6. 点「保存到我的通知」，之后在「我的通知」「日历」「变更记录」里都能看到它。
7. 收到补充通知时，再点「新增通知」粘贴，系统会让你手选要修改的原通知，
   显示变化前后与原文依据，确认后才更新，并同步刷新办理路线、日历和提醒。

一条可以直接粘贴的示例：

```
关于2026年国家助学金评审工作安排的通知
各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室。
评审会定于11月8日晚7点在行政楼A302会议室召开，请各班班长届时到场。
```

会拆成「提交纸质申请表」和「参加评审会」两个事项，
前者是办理截止 11 月 5 日 17:00，后者是活动开始 11 月 8 日 19:00，
各自带自己的地点，不会串。「下午5点」和「晚7点」都能在原文里定位到。

**演示数据说明**：欢迎页的「体验示例」和工作台右上角的「载入示例通知」插入的是
`app/lib/sampleNotices.js` 生成的**示例数据**，界面上有「示例」来源标签和「示例数据」紫色角标，
只往前插不清空你自己保存的通知。不配密钥时走的是**本地解析模式**，来源标签显示「本地识别」。
演示素材自检命令是 `npm run demo:check`，`docs/demo-notices.md` 里有 10 条示例原文，
`docs/demo-script.md` 里有 13 步演示流程。

## 三、自检命令

本项目把「验证」当作一等公民。除 `check:key` 用于验证本机密钥配置、会发起一次模型请求外，
以下命令**全部离线运行，不依赖网络，不需要密钥**。

```bash
# 配置与规范
npm run check:key          # 检查密钥配置状态，不打印密钥内容
npm run check:prompt       # 检查归档提示词的书写规范
npm run check:regex        # 检查代码里是否有过度转义的正则
npm run test:regex-lint    # 正则写法的回归

# 抽取与融合
npm run test:extract       # 规则引擎抽取
npm run test:location      # 地点抽取
npm run test:relative      # 相对日期本地换算
npm run test:classify      # 分类值域校验
npm run test:grounding     # 反幻觉出处核对
npm run test:locate        # 原文定位
npm run test:materials-date # 材料与日期边界
npm run test:audience-materials # 面向对象与材料
npm run test:title         # 标题生成
npm run test:mode-guard    # 模式切换保护
npm run test:manual        # 手动编辑
npm run test:share         # 文字汇总
npm run test:batch         # 批量粘贴

# 事项、路线、补充通知、提醒
npm run test:items         # 事项拆分
npm run test:route         # 办理路线与日历同源
npm run test:patch         # 补充通知变更对比，26 条
npm run test:conflict      # 日程冲突与截止集中，29 条
npm run test:calendar      # 日历视图
npm run test:sample        # 示例通知

# 分轮回归（每轮改动都留一条可复跑的断言链）
npm run test:round1        # 中文数字时间、零事项兜底、材料边界
npm run test:round2        # 材料限定词与并列项、办理路线排序与日历同源
npm run test:round3        # 补充通知的识别、匹配、前后对比、落盘与负例
npm run test:round4        # 整轮实测里修掉的五个抽取缺陷
npm run test:round5        # 通知发布日期入口与相对日期换算
npm run test:round6        # 字段定位与多通知链路，53 条
npm run test:round7        # 日期时间、动作命名、时间类型、疑似重复、工作台，132 条

# 交付复核
npm run coverage           # 两条路径的字段覆盖率实测
npm run eval               # 48 条评测语料逐条比对，生成 docs/eval-report.md
npm run validate:ics       # 日历文件导出校验
npm run demo:check         # 演示素材自检
```

共 34 条校验命令，每条都直接 import 生产模块，不存在另写一份「相似实现」的情况。
其中相对日期与反幻觉两组包含故意写错的金丝雀用例，
用于证明「如果实现坏了，测试真的会报红」，而不是永远显示通过。

第六轮的整体验收记录在 `docs/acceptance-2026-11-03.md`，
48 条评测语料在 `docs/eval-cases.json`，逐条预期、实际与错误原因在 `docs/eval-report.md`。

## 六、核心设计思路

一句话概括：**用最小的模型能力解决最大的语义难题，其余全部交给确定性代码。**

模型擅长理解自然语言，不擅长算术，也不保证不编造。所以本项目做了三件事。

**1 相对日期交给本地代码算。**「下周三」「三天后」这类说法，早期交给模型换算，
实测约 1/20 概率算错，把 temperature 设为 0 也消除不了。现改为本地纯函数
`relativeDate.js` 换算，提示词要求模型原样返回相对说法、不要自己算。

**2 模型输出必须回原文溯源。**`grounding.js` 把模型返回的日期、时间、地点、材料、
面向对象回原文找依据，找不到即置空并记录原因。提示词里写「不许编造」只是要求，
代码里回查才算约束。

**3 只有确定的信息才做确定的判断。**第五轮的冲突提醒只在两项活动都有明确开始和
结束时间时才计算重叠，一项结束等于另一项开始不算撞车，只有开始时间时只提示
「结束时间待补充」，绝不假设活动一般开多久。同一天多个截止叫「截止事项集中」，
不叫冲突。

**4 不自动改官方通知。**补充通知必须用户手选原通知、看过变化前后对比、点确认才落盘，
未提及的字段保留，歧义先确认不覆盖，每次更新都留修改历史。

## 八、已知边界，诚实说明

以下尚未解决，不夸大：

- 「半个月后」「半年后」等相对说法、区间日期、周期性时间、「原定 X 推迟至 Y」的改期语义，
  本地规则尚未完全覆盖，会标待确认或留给模型处理。
- 材料提取是开放集合，中文「要带什么」的写法近乎无限，无法保证穷尽。
  第六轮 48 条评测里材料漏抽 4 件、误抽 0 件，误提防线有效但覆盖面还不够。
- 部分通知在本地规则路径下拆不出事项，界面会显示「这条通知里没有拆出具体事项。」，
  此时可以点顶部「重新解析」，或在接模型路径下重试。
- 事项名在部分写法上会回退成「参加活动」「提交材料」这类泛称。
- 多句通知里偶尔出现日期或地点串到相邻事项的情况。
- 模型路径的准确率依赖使用者自己的 Key，交付材料里无法复现，
  README 中的接模型数字来自此前已经跑完并留档的批量报告。
- 数据只存本机浏览器，没有云同步，换设备不会带过去。
- 演示视频由学生按 `docs/video-record-template-2026-11-04.md` 自行录制，技术文档 PDF 仍在准备中，仓库里先提供提纲与功能清单。

## 九、常见问题

**问：没有 DeepSeek Key 能跑吗？**
能。跳过第 3 步，全部核心功能可用，来源标签显示「本地识别」。这是无密钥演示模式。

**问：为什么解析结果和我预期的不一样？**
先点结果字段，看原文里被高亮的是哪句话。规则只能抽它认得的写法，
抽不到的字段会留空并标「待确认」，可以在界面上手动补齐。
`docs/eval-report.md` 里列了 48 种写法的实际表现。

**问：刷新之后数据还在吗？**
在，数据存在浏览器 localStorage。清理浏览器数据、换浏览器、用无痕窗口会丢失。

**问：示例数据会覆盖我自己的通知吗？**
不会，示例只往前插，且带「示例」标签，可以在筛选里单独看。

**问：模型调用失败会怎样？**
界面显示具体失败原因，原文完整保留，点「重新解析」可以重试，
不会把失败结果显示成一个看起来正常的解析结果。

**问：补充通知会不会自动改我保存的安排？**
不会，必须你手选原通知、确认对比表之后才更新，并且保留修改历史。

**问：`npm run build` 报错怎么办？**
先跑 34 条自检命令。本机曾遇到构建被安全软件的批量删除守卫打断，
与代码本身无关，把旧 `.next` 整体移走再构建即可。2026-11-04 已实测 `npm run build` 通过，
浏览器验收也跑在刚构建出来的生产产物上。

**问：怎么确认数字不是编的？**
`npm run coverage` 和 `npm run eval` 都会现场重跑并生成报告，
不联网、不读密钥，报告里连哪条没抽到都列出来。
