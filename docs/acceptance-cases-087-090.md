# 087 到 090 核查轮 开发前验收案例

同学发来一张截图，说标题没被识别。截图里的通知原文逐字如下。

```
第十五届校园歌手大赛报名通知
报名截止时间为11月10日17:00，报名表交到团委办公室。
初赛定于11月15日晚6点半在大礼堂举行，请参赛选手准时到场签到。
```

界面解析结果里「标题」显示「第十五届校园歌手大赛报名通知」，与原文第一行完全一致，
点这个值之后下方出现红字「原文里没找到这段内容，请自行核对。」。
取证结论：本地规则 `extractNotice` 返回的字段里根本没有 title，
界面标题由 `getNoticeTitle` 从 `notice.title` 或原文首行兜底显示，
而点击定位走 `fieldLocate.findSpan`，取的是 `analysis.title`，必然是空值。
所以这不是抽取失败，是「展示值」和「定位值」不同源造成的误报。

## 一、素材

- 素材 A：上面这条歌手大赛通知，同学给的，未参与过任何开发与验收。
- 素材 B：两条通知用空行分隔，用作多通知流程，未参与开发。
- 素材 C：一条含相对日期「下周三」的通知，配发布日期 2026年11月3日。
- 素材 D：一条同时有报名截止日与活动举办日、且写明结束时间的通知，用来看模型字段有没有丢。
- 素材 E：一条补充通知，写「原定11月15日的初赛调整至11月18日」，用来看历史与对比弹窗。

## 三、本轮明确不修，留作风险

全链路复查另外发现的问题，改动跨多个模块或需要重新设计语义，
本轮只记录不落地，避免为了修一处把已有功能带坏。

- 手动编辑解析字段后，事项清单与日历待办不跟着变，`noticeOps` 与 `ItemsPanel` 的数据源本就不同形。
- 补充通知改期写回的是原文写法，没有归一化与重算，跨年和中文数字日期会在日历里丢失。
- 补充通知「依据原句」的下标基准是补充通知原文，高亮目标却是当前通知原文，语义要重新定。
- 模式不匹配提醒算出来但界面没有渲染入口。
- 选中已保存通知点重新解析，若被判为补充通知后取消，选中态没有恢复。
- 示例通知编辑一次后不再归入「示例」筛选。
- 批量查重只比正文全等，没有单条模式的标题相同一级。
