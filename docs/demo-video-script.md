# 演示视频脚本，7 分 30 秒，1920×1080

配套文件 `docs/tech-doc-outline.md`。本脚本是**拍摄脚本**，不是成片。
录制参数：1920×1080、30fps、系统声音与麦克风分轨、字幕单独一层、不加速不剪辑掉失败画面。

**连贯案例**用同一条通知从头走到尾，中间不换数据：

> 关于2026年国家助学金评审工作安排的通知
> 各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室。
> 评审会定于11月8日晚7点在行政楼A302会议室召开，请各班班长届时到场。

补充通知用这一条：

> 关于助学金评审会的补充通知
> 原定11月8日的助学金评审会调整至11月9日19:00，地点改为行政楼B201会议室，其余安排不变。

这两条是 `scripts/test-items.mjs`、`scripts/test-patch.mjs` 与 `docs/demo-notices.md` 里
真实跑过的素材，不是现场编的。所有界面名称按代码里的实际文案念。

## 1:00 至 3:15 真实 AI 协作过程，135 秒

这一段是全片过程分的核心，**必须用真实素材，不许摆拍、不许补造对话**。

### 1:00 至 1:30 展示问题与提示词

画面：编辑器打开 `docs/acceptance-2026-11-03.md`，滚到「本轮发现并修掉的真实缺陷」，
停在那句「时间另行通知把普通新通知劫持进补充通知流程」。
再切到 `prompts/062-pending-false-positive.md`，停在「背景」段与「Prompt」块开头。

口播：
「这是第六轮整体验收时真抓到的一个缺陷。粘贴一条普通通知，
写的是时间另行通知、地点待定，点解析之后程序却弹出了请选择它要修改的原通知，
把一条新通知劫持进了补充通知流程。
我的做法是把现象和验收口径写成一条可以整段复制的提示词，
交给 DeepSeek 改，我不自己写代码。」

### 1:30 至 2:10 真实对话与真实失败

画面：切到**真实的 DeepSeek 对话窗口**，把 `prompts/062-pending-false-positive.md`
里的 Prompt 块整段粘进去，等真实回复，滚过它给出的改动片段。
然后切到终端，**现场重演第一版**：把归档里 062 的第一版改动贴回
`app/lib/noticePatch.js`，跑 `npm run test:patch`，
镜头停在真实输出「业务结果 24 通过 1 失败」和「FAIL 说不清的补充通知要记歧义」上，
不要剪掉这一帧。

口播：
「它给的第一版过宽了。我本机一跑，二十四条通过一条失败，
把原本就该记歧义的『评审会时间另行通知』也拦掉了。
这个失败不能改期望值糊过去，得把现象贴回同一个会话让它收窄。」

注意：这里必须用真实的对话窗口和真实的终端输出。
如果录制当天模型服务不可用，**宁可缩短这一段并如实说明，也不要用伪造的聊天截图**，
可以改用 `prompts/062` 与 `.ai-out-062.md`、`.ai-out-062b.md` 两份真实归档输出代替，
并在口播里说明这是归档的往返记录。

### 2:10 至 3:00 返修与验证

画面：把 `prompts/062` 里那段「回归挂了一条」的返修原话贴回同一对话，

口播：

二是第一句是完整通知抬头，并且都没有原定这类回指词。
真正的补充通知和单独一句另行通知都照常识别。
补了三条回归用例，二十六条全绿。
整个项目有一百零二份这样的提示词归档，三条完整迭代链写在技术文档里。」

## 3:15 至 4:35 连贯案例上，导入到保存

画面与操作，全程**同一条助学金通知**：

1. 工作台点「新增通知」，弹窗里是「单条通知」模式，粘贴上面那条原文，
   点「开始解析」。镜头给到「正在解析」转圈一秒，不要做假进度条。
2. 解析完自动切到「我的通知」，左栏是通知原文，右栏是办理路线。
   特写两张事项卡片：
   「提交纸质申请表」办理截止 11月5日 17:00、学生工作处A302办公室、材料纸质申请表；
   「参加评审会」活动开始 11月8日 19:00、行政楼A302会议室。
3. 点结果里的「学生工作处A302办公室」字段，左栏原文文本域真的选中这一段；
   再点时间字段，特写原文里对应的时间说法被选中，说明展示值 17:00 能指回原文。
4. 勾一下「纸质申请表」前面的方框，出现「已准备」反馈。
5. 点「保存到我的通知」。

口播：
「点开始解析，一条通知拆成两件事。第一件是办理截止，提交纸质申请表，
十一月五日下午五点前交到学生工作处 A 三零二；
第二件是活动开始，十一月八日晚七点在行政楼 A 三零二开评审会。
两件事各自带自己的地点，没有串。
点结果里的地点，左边原文会选中对应的话，点时间会选中下午5点，
因为程序把原文的时间说法折算成二十四小时制再反查，这就是可核对。
材料可以一条条勾，勾完有已准备反馈。然后保存到我的通知。」

注意：这一段的日期时间、地点、材料名必须与 `scripts/test-items.mjs` 案例一完全一致。
不要念成「截止 11 月 8 日」或「评审会要交材料」。

## 4:35 至 6:35 连贯案例下，补充通知到日历

画面与操作：

1. 再点「新增通知」，粘贴上面那条补充通知，点「开始解析」。
   出现选原通知的弹窗，手选刚才保存的助学金通知，点下一步。
2. 对比弹窗特写三行：变化，日期 11月8日 到 11月9日；
   不变，时间 19:00；变化，地点 行政楼A302会议室 到 行政楼B201会议室。
   每行下面有「依据原句」。镜头停两秒。
3. 点「确认更新」。特写成功提示「更新成功」「受影响事项 参加评审会」
   「提醒已按新安排重新计算」。
4. 切到「变更记录」，展示前后对比卡片与「修改历史 共 1 次」，
   展开「查看这条通知」。
5. 切到「日历」，11 月 9 日那格显示参加评审会与新地点行政楼B201会议室，
   11 月 5 日那格仍是提交纸质申请表、学生工作处A302办公室、17:00。
6. 回「我的通知」，特写第一件事项仍是原来的截止与地点，没有被改。

口播：
「过几天收到补充通知，说评审会改到十一月九日十九点，地点改到行政楼 B 二零一。
再点新增通知粘贴，系统让我手选要改的原通知，
然后给出变化前后和原文依据，没提到的字段一律保留。
确认之后，成功提示写清楚更新成功、受影响事项是参加评审会，
并且提醒已按新安排重新计算。
日历上九号变成新的评审会，五号交表完全没动，已完成状态也还在。
变更记录里留着这次修改，刷新之后也不会丢。」

注意：
- 界面文案以代码为准：「更新成功」「受影响事项」「提醒已按新安排重新计算」
  「修改历史」「查看这条通知」。
- 不要说「系统自动改了官方通知」，必须强调手选和确认两步。

## 6:35 至 7:30 收尾

画面与操作：

1. 在「我的通知」里点「标记完成」，按钮变成「撤销完成」，
   再点一次回到「标记完成」，特写 localStorage 里的状态变化。
2. 按 F5 刷新，办理状态、材料勾选、修改历史、日历都还在。
3. 终端快速跑三条命令，各停一秒：
   `npm run coverage`、`npm run eval`、`npm run demo:check`。
4. 最后一屏：技术文档提纲的「实际限制」一页，
   列出「本地规则路径下 48 条语料有 12 条拆不出事项」「材料漏抽 4 件、误抽 0 件」
   「保存失败未端到端实测」。
5. 淡出到深蓝底，白字「知办，把校园通知变成清晰行动」，
   小字「无密钥也能完整体验」。

口播：
「事项可以标记完成，也可以撤销，刷新之后都还在。
最后把覆盖率和评测跑一遍，二十七条离线校验命令全绿，不联网也不要密钥。
不好的地方我们也写进文档：本地规则路径下，四十八条评测语料里有十二条拆不出事项，
材料漏抽四件，误抽零件，保存失败这一项还没有做端到端实测。
知办，把校园通知变成清晰行动。」

注意：结尾**必须念出限制**，不能只报好数字。
