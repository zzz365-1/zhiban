开发前验收案例在 `docs/acceptance-cases-round7.md`，每条预期都先用 `tmp/final-facts.mjs`
跑生产模块取证再写，没有凭印象设锚。本文只记**实际跑出来的结果**和**确实没做的部分**。

## 一、本轮改了什么

按需求七组逐条对应，代码全部经 `scripts/ai-patch.mjs` 由对话式 AI 出成对片段，
本机逐片段校验唯一命中后落位，提示词在 `prompts/097` 到 `prompts/107`，
AI 回复待审记录在 `.ai-out-097.md` 到 `.ai-out-107b.md`，
往返线程在 `tmp/thread-round7.json` 到 `tmp/thread-round7k.json`。

### （一）统一日期和时间处理

- 根因：`app/lib/deadline.js` 的 `buildDeadlineDate` 在没有具体时刻时写死 `let hours = 17`，
  内部排序用时间戳被 `routeEvents.js` 和 `shareText.js` 当成原文时间展示。
- 现在：没有明确时刻时排序基准落在当天零点，但由新增的 `hasExplicitTime(time)` 判断原始时间字符串，
  事件 `time` 留空并带 `hasExplicitTime=false` 和 `timeNote=具体时刻未说明`。
  展示层 `ItemCard.js`、`CalendarPage.js`、`CalendarView.js`、`TodoList.js`、`ItemsPanel.js`、
  `AnalysisPanel.js`、`MultiResultPanel.js` 一律不把内部排序值印成原文时刻。
- `shareText.js` 的 `formatShareDateTime` 在没写时刻时输出「M月D日（具体时刻未说明）」。
- `todo.js` 的 `formatRemaining` 增加 `dateOnly` 参数，原文只写日期时按自然日说「剩 N 天」，
  不再说「剩 N 小时」或「不到 1 小时」。
- 同学自己补的结束时间写入 `endTimeSource: "user"`，事项卡用独立灰底小标签「自行补充 HH:mm」，
  与通知规定时间分开；`endTime` 字段仍供冲突判断使用，功能没断。

### （二）准确命名办理事项

- `noticeItems.js` 新增通用动作词表与 `deriveActionName()`，按原文实际动作起名，
  不针对样例硬编码。无法判断动作时返回「待确认办理事项」。
- 系统建议仍在「系统建议不是通知里的要求」区块，与「通知要求」分区没动。
- 现场取证：A1 得「完成本季青年大学习网上主题团课」，A2 得「核对个人学籍信息」，
  C 仍是「提交纸质申请表」「参加评审会」，同类新说法「完成缴费」「到场签到」「提交报名表」也按动作生成。

### （三）统一各页面时间类型

- 新增 `getNoticeTimeType(analysis)`，按事项数组判断整条通知主时间类型。
- 解析页对讲座类把字段标签改成「活动日期」「开始时间」，批量预览的 Row 标签改成「开始」，
  截止类通知仍显示「截止日期」「具体时间」「截止」。
- 讲座 14:30 在单条详情、批量预览、工作台、日历、文字汇总里的含义一致。
- 同一条通知里报名截止和活动开始仍各带各的时间、地点、材料，没有串台。

### （四）补强疑似重复提示

- `dedupe.js` 新增 `textSimilarity` 与 `SIMILAR_THRESHOLD = 0.75`，
  `checkDuplicate` 在 `exact` 之后加 `similar` 档，`title_same` 保留在其后，
  所以标题相同但正文不同不会被判成疑似重复。
- 新增 `checkBatchDuplicates(texts, notices)`，一次判定与已有通知、与同批次前文重复。
- `DuplicateDialog.js` 新增「疑似重复的通知已存在」档，提供查看已有／跳过／明确另存。
- `MultiResultPanel.js` 显示重复档位、可展开查看已有正文、可切换跳过本条与明确另存。
- `page.js` 的批量确认、可保存条数、保存过滤、批量保存二次查重全部接线，
  命中的条目默认跳过，明确另存才放行，不静默覆盖，不自动删除用户数据。
- 补充通知判定仍在查重之前，走原有变更流程。

### （五）整理工作台

- `WorkspaceOverview.js`：统计卡移到最前，三个区块顺序改为「即将截止 → 待办理事项 → 待确认事项」，
  外层收住行宽，两级栅格在 1280 下不挤、在 1920 下不散，提醒区在统计卡之后。
- `ScheduleAlerts.js`：多条 `needEndTime` 收成一张聚合卡，
  文案「有N项活动未提供结束时间，暂无法判断时间冲突。」，
  点「查看具体事项」才展开逐项补结束时间，展开后每项仍可独立补时间。
  清理了聚合后残留的旧展开状态。缺结束时间只影响冲突判断，标记完成、勾材料照常可用。
- 保留深蓝导航、浅色背景、白色卡片、主要按钮和大日历，没有加装饰或动画。

### （六）完整流程里抓到并修掉的两处真实缺陷

浏览器实测第一轮跑出 42 条失败，逐条分辨后确认其中两处是产品缺陷，其余是脚本选择器或欢迎页跳转问题。

1. **明确另存弹窗反复出现**。`handleDuplicateImport` 里 `setAllowDuplicate(true)` 是异步状态更新，
   紧接着调用的 `handleParse()` 仍持有 `allowDuplicate=false` 的闭包，于是又查重又弹窗，
   通知永远存不进去。`prompts/107` 让 AI 改成同步具名放行标记
   `handleParse({ forceImport: true })`，且只认 `opts.forceImport === true`，
   React 传进来的事件对象不会被误判成放行。AI 首版直接读 `opts.forceImport`，
   不传参时会抛 TypeError，回一轮 `107b` 改成读已算好的布尔变量后才落位。
2. **变更对比弹窗点「依据原句」报变量未定义**。`PatchReviewDialog.js` 在 onClick 里引用
   `onFieldClick`，但函数参数没解构出来；`page.js` 其实早就传了这个回调。
   `107` 把参数补齐，点击不再抛异常。

修完后重新构建、重启生产服务、整套浏览器流程重跑，这两处都通过。

## 三、演示提纲与录屏建议

`docs/demo-outline-2026-11-05.md` 是一份简洁正式提纲，
主线「收到通知 → 生成办理路线 → 核对原文 → 完成交表 → 收到改期通知 → 确认更新 → 日历同步且完成状态保留」，

录屏建议 1920×1080，浏览器缩放到 100% 或 125%，关闭系统通知与无关标签页。

或后期给弹窗做一次等比放大，保证评审能看清前后值。

## 四、当前环境无法执行的，如实标记

1. 浏览器验收是 Edge 无头 CDP，能驱动静态首屏和脚本内点击，不是真机，没有测移动端窄屏。
2. 没有手机日历导入、没有跨天刷新、没有云同步的实测条件。
3. 模型两遍输出不一致约 5%、单次解析耗时与花费是历史批量结论，本轮未重跑百条批量。
4. 演示视频由学生按 `docs/video-record-template-2026-11-04.md` 自行录制，仓库里没有成片。
5. 技术文档 PDF 仍在准备中。

### 给学生的最短手动检查步骤

1. `npm run dev`，浏览器打开 http://localhost:3000 ，首次点「进入工作台」。
2. 把 `docs/video-record-template-2026-11-04.md` 里第一条助学金通知粘进「新增通知」，点开始解析，保存到我的通知。
3. 在「事项清单」里勾材料、点标记完成，切到工作台看统计卡变化。
4. 再粘补充通知，手选原通知，看对比表，点确认更新，切到变更记录看历史。
5. 切到日历，点改期后的那一天，确认只剩一条新安排，回到我的通知确认交表仍是已完成。
6. 按 F5 刷新，重复第 5 步，确认状态和变更记录都还在。
7. 把窗口拉窄到 1280 宽，看统计卡、按钮、文字有没有挤出或截断。

## 五、仍未解决，别当成已修

沿用上一轮报告第五节，本轮继续没碰：

1. 手动编辑解析字段后，事项清单、日历、待办、冲突提醒不会同步重算。
2. 补充通知改期写回的是原文写法，未归一化、未重算 `deadlineDate`，跨年与中文数字日期会丢。
3. 变更对比弹窗「依据原句」下标基准与高亮目标不是同一段文本，本轮只修掉点击抛异常，选中效果仍可能落空。
4. 模式不匹配提醒计算出来了，界面没有渲染入口。
5. 判为补充通知后取消不恢复选中态。
6. 示例通知编辑后脱离筛选。
7. `_source === "ai"` 是死条件。
8. 前端没有 ICS 下载入口，日历文件生成与校验只有命令行。
9. 1920×1080 下多通知结果页右侧留白；换算说明沿用红色提示条，观感偏像报错。
10. 工作台「即将截止」和「待办理事项」是同一批未完成事项的两种口径，同一条会出现两次。
11. 评测语料里「报名从11月1日到11月5日下午5点截止」这类纯时间范围句，事项名会带出整段时间文字，偏长但仍贴原文，不是硬造的「提交材料」。

**本轮明确不做**：不新增独立提醒时间设置界面，需求一第 4 条按「把用户自行补充的时间与通知规定时间分开标注」落地；
不做复杂自动排程；不重构数据模型；不改深层相对日期与区间日期规则。
