### 6.1 生产构建

- 取证：本机安全守卫由 `CODEBUDDY_SAFE_DELETE_*` 一组环境变量注入，
  旧 `.next` 里的文件数超过批量删除阈值；同时 3000 端口的开发服务器正占着 `.next`，
  首轮连移动目录都会被拒绝。
- 做法：先停掉开发服务器，再把旧 `.next` 整体移到 `tmp/.next-prebuild-verify-*`，
  只移动不删除，项目根不再有构建目录，随后跑全新构建。
- 结果：`BUILD_EXIT=0`，Next.js 16.3.8 Turbopack，编译 3.6 秒，TypeScript 通过，
  5 个静态页生成，路由 `/`、`/_not-found`、`/api/parse`、`/welcome`，
  `BUILD_ID=ofoPWEymdCJFtkd1f0CYu`，`.next/static` 下 14 个静态文件。
- 结论：首轮的构建失败是工具守卫与文件占用造成的假性打断，与代码无关，
  和 Dec-046 记录一致。全程未提权、未关闭守卫、未删除文件、未改产品代码。

### 6.3 生产构建产物上的浏览器复验

- 用 `npm run start` 起生产服务，`http://localhost:3000/` 返回 HTTP 200。
  这一轮浏览器跑的是刚构建出来的产物，不是开发服务器实时编译，比首轮更贴近交付形态。
- 1280×720 与 1920×1080 共十个场景，脚本 `tmp/layout-shots.mjs` 挂了量化断言，
  `RECHECK_ASSERT_FAILS=0`、脚本 exit 0，截图 `111` 到 `120`。
- 量化判据以主内容区为参照：原文区宽度占主内容区九成以上，原文框高度在 40 到 200 像素之间，
  事项清单左缘与原文区对齐、宽度达原文区九成、纵向位于原文下方，页面文档高度不超过视口。
  1280 实测原文框 680×110、事项清单 624 宽且位于其下；1920 实测原文框 1320×87、事项清单 1264 宽。
- 其余场景实测：滚到底仍见事项清单与标记完成，折叠展开可用，
  二十一行长原文完整载入且原文框自身不出滚动条，上区滚到中段后标题吸顶、解析结果仍可见，
  日期控件是文本类型、占位「例如：2026年11月3日」、空态无值、弹窗原文框 118 像素，
  填入中文日期不报格式错误。
- 首轮断言出现过 3 条假失败：把视口绝对坐标当成了主内容区坐标，
  而页面左侧有固定 584 像素的导航与列表区，于是 `items.x=605`、`ta.w=680` 被误判成
  「挤在右半列」「没占整宽」。按 Dec-039 核过输入、描述、期望三样，
  确认是判据口径错而非产品缺陷，改成相对主内容区的判据后重跑 0 失败，产品代码一行未动。
