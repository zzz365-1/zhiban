# 最后一轮针对性优化：开发前验收案例

日期 2026-11-04 晚。本轮沿用现有项目，只修功能细节、整理工作台、准备演示，不扩展大型功能。

**取证方式**：所有预期都先用 `tmp/final-facts.mjs` 跑生产模块，把当前实际值记下来，再写修后预期。
取证脚本 import 的是 `extractNotice.js` `noticeItems.js` `deadline.js` `routeEvents.js` `shareText.js` `dedupe.js`，
不是另抄一份相似实现。

**取证时看到的当前实际值**（这些就是本轮要修的）：

- A1 / A2：`analysis.time = null`，但 `deadlineDate` 是 `17:00`；`routeEvents` 把 ts 转成 `time: "17:00"`；
  汇总文字出现「11月9日 17:00」「11月12日 17:00」。根因 `deadline.js` 里 `let hours = 17`。
- A1 / A2：事项名都是「提交材料」，材料数组为空，还给了「提前把要提交的内容准备好」这类建议。
- B：`analysis.deadline = 11月14日`、`time = 14:30`、`eventDate = null`；事项层 `timeType = start` 是对的，
  但 `MultiResultPanel` 写死 `<Row label="截止">`，解析页字段标签写死「截止日期」。
- C：两事项正确（提交纸质申请表 11月5日 17:00 学生工作处A302办公室；参加评审会 11月8日 19:00 行政楼A302会议室）。
- D：`deadline = 11月10日`、`time = 15:00`、`location = 行政楼B201会议室`；事项 1 条。
- F1 → `exact`，F2 → `title_same`，F3 → `title_same`。现在没有「疑似重复」这一级，标题相同就一律当成需确认。
- 工作台顺序是「需要关注提醒区 → 统计卡 → 待确认 → 即将截止 → 待办理」；
  `conflict.js` 给每个缺结束时间的事件各生成一条 `needEndTime`，会渲染成多张卡。

## 三、本轮明确不修（留作风险，别当成已解决）

沿用上一轮报告第五节，本轮继续不碰：手动编辑解析字段后事项与日历不同步、
补充通知改期未归一化且未重算 `deadlineDate`、依据原句下标基准不一致、
模式不匹配提醒是死代码、判为补充通知后取消不恢复选中态、示例通知编辑后脱离筛选、
`_source === "ai"` 死条件、前端没有 ICS 下载入口、1920 下多通知结果页右侧留白、
换算说明沿用红色提示条像报错。

**本轮新增但不做的**：不新增独立的提醒时间设置界面（需求一第 4 条按「把用户自行补充的时间
与通知规定时间分开标注」落地，不扩展成排程功能）；不做复杂自动排程；不重构数据模型。

## 四、当前环境无法执行的，如实标记并给手动步骤

浏览器用 Edge 无头 CDP，只能驱动静态首屏与脚本内点击，没有真机、没有移动端窄屏、
