## 零、录前准备（三分钟）

1. 起服务 `npm run dev`，浏览器打开 http://localhost:3000
2. **清空状态**，否则片头拍到的是带旧数据的工作台。浏览器控制台执行：

```js
localStorage.removeItem("zhiban.welcomed");
localStorage.removeItem("zhiban.notices.v1");
location.href = "/";
```

3. 全程**不配密钥也能跑通**，来源标签会标明是本地规则给的。别在演示现场改 `.env.local`，改了要重启服务。

## 一、通知素材（12 条，直接复制代码块内容）

### A 主线：一条通知带出十几个功能点

这条最重要，双日期是核心卖点。

```text
关于2026年国家助学金评审工作安排的通知
各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室，逾期不再受理。
评审会定于11月8日晚7点在行政楼A302会议室召开，请各班班长届时到场。
```

本机实测：截止 **11月5日 17:00**、活动 **11月8日 19:00**、地点 **学生工作处A302办公室**、材料 **纸质申请表**、拆成 **2 条事项**（提交纸质申请表、参加评审会），无误弹补充通知窗，有「保存到我的通知」按钮。

能拍到：双日期分开、中文数字时间、地点、材料、对象、分类、事项拆分、来源标签、保存、详情页原文与解析结果双栏、点字段跳回原文、手动改字段、标记完成、材料勾选、待办、日历、搜索筛选、整理成文字、刷新后保留。

### B 中文数字时间

```text
第十五届校园歌手大赛报名通知
报名截止时间为11月10日17:00，报名表交到团委办公室。
初赛定于11月15日晚6点半在大礼堂举行，请参赛选手准时到场签到。
```

本机实测：**18:30**（晚6点半）、11月15日、大礼堂，无误弹窗。

### C 相对日期与待确认状态

```text
关于开展宿舍安全月活动的通知
请各班于下周三下午4点前将活动计划表交至学院学工办A201。
```

本机实测两组，是这条素材最值得拍的对比镜头。

**留空发布日期**：显示「下周三 16:00 待确认」，材料活动计划表、地点学院学工办A201、无材料误抽。橙色提示只有一句「日期待确认，请补充发布日期以便换算」。

**填 2026-11-03**：显示「2026年11月11日 16:00」，橙色提示消失，待办和日历都用这个日期。

2026-11-04 起新增了「通知发布日期」输入框，在新增通知弹窗里，模式切换下面、原文框上面，选填。它不是密钥开关，跟接不接模型无关，作用是给「下周三」这种说法一个换算基准。留空就保持待确认，不许按今天偷算，这条设计没变。录的时候可以连着拍两个镜头，先留空讲宁可不瞎猜，再填日期讲给了基准就能落到日历，比只讲一个状态有说服力。

### D 没有地点：宁缺勿滥

```text
关于核对2026级本科生学籍信息的通知
请各位同学于11月12日前登录教务系统核对个人学籍信息，逾期不再受理。
```

本机实测：地点那一栏**是空的**，截止 11月12日，分类教务。

### E 行政单位名做地点

```text
2027届毕业生教材费结算通知
请各班学习委员于11月18日前将教材费汇总表交至教务处教材科A105，并携带缴费凭证。
```

本机实测：地点 **教务处教材科A105** 整串保留，材料 **教材费汇总表、缴费凭证** 两件。

### F 只有活动日没有截止日

```text
学术讲座通知
定于11月14日下午两点半在图南楼报告厅举办人工智能与城市发展专题讲座。
请感兴趣的师生届时参加。
```

本机实测：日期栏 **11月14日 14:30**（下午两点半），地点图南楼报告厅，事项「参加讲座」。这条没有截止日，只有一个举办日，按「行动日」口径填进日期栏，让它也能进待办和日历。

### G 最短的一条

```text
请全体团员于11月9日前完成本季青年大学习网上主题团课。
```

本机实测：截止 11月9日，照样拆出一条待办。

### H 紧急截止：待办倒计时（用明确日期）

```text
关于紧急报送体温监测表的通知
请各班于11月4日下午5点前将体温监测表交至学院学工办B203。
```

本机实测：截止 **11月4日 17:00**，保存后进待办，显示 **「剩 18 小时」** 倒计时（本轮实测到的原文是这个，具体小时数随录制时刻变化）。

**日期要跟着录制当天改**：上面 11月4日 是 2026-11-03 的明天。你要是隔天再录，把它改成录制当天的明天或后天，否则会显示已过期，红色提醒就拍不到了。相对写法「明天」不要用，见下面第三节第 3 条。

### I 多通知批量（三条一起粘，中间空一行）

```text
关于2026年国家助学金评审工作安排的通知
各班请于11月5日下午5点前将纸质申请表报送至学生工作处A302办公室。
评审会定于11月8日晚7点在行政楼A302会议室召开。

第十五届校园歌手大赛报名通知
报名截止时间为11月10日17:00，报名表交到团委办公室。
初赛定于11月15日晚6点半在大礼堂举行。

学术讲座通知
定于11月14日下午两点半在图南楼报告厅举办人工智能与城市发展专题讲座。
```

本机实测：弹切分确认，显示 **「识别到 3 条通知」**、有「去掉」和 **「解析这 3 条」** 按钮。

### J1 原通知（补充通知演示的前半段，必须先保存）

```text
关于举办2026年校园心理情景剧大赛的通知
请各学院于11月20日17:00前将报名表报送至团委办公室。
决赛定于11月28日晚7点在大礼堂举行，请参赛队伍准时到场。
```

### J2 补充通知（后半段，接在 J1 之后）

```text
关于校园心理情景剧大赛的补充通知
原定11月28日晚7点的决赛调整至12月1日下午2点，地点改为大学生活动中心报告厅，其余安排不变。
```

浏览器实测：J1 保存成功后粘 J2，会弹 **「请选择它要修改的原通知」**，列出含「校园心理情景剧大赛」和「个事项」的原通知选项，且不误报重复。

### L 纯告知：不该拆就不拆

```text
我校王芳老师荣获2026年度校级教学能手称号，特此通报。
```

本机实测：**0 条事项**，走零事项空态（这一条只有模块级实测，界面空态文案见既有验收记录）。用来讲宁缺勿滥的边界。

## 二、按什么顺序录（照着做就能拍全）

| 步 | 操作 | 拍到的功能 | 一句话口播 |
|---|---|---|---|
| 1 | 欢迎页，点「进入工作台」 | 欢迎页、两种入口、空状态 | 从一个干净的空白开始 |
| 2 | 点「新增通知」，粘 **A**，点「开始解析」 | 双日期、时间、地点、材料、对象、分类、2 条事项、来源标签 | 一条通知里两个日期，一个要赶一个要到场，现在分开管 |
| 3 | 点「保存到我的通知」 | 保存、已保存状态 | 存下来之后才进待办和日历 |
| 4 | 点这条通知进详情 | 原文与解析结果双栏、点字段跳回原文 | 每个值都能点回原文看出处 |
| 5 | 鼠标移到地点那行点铅笔，改内容回车 | 字段手动修正，标签变「手动修正」 | 抽不准的允许改，改完标明是谁给的 |
| 6 | 点「标记完成」，勾材料，试「无需办理」再「取消无需办理」 | 事项状态、材料勾选 | 办到哪一步自己记 |
| 7 | 切「待办」「工作台」 | 需要关注三项统计、待办列表 | 三天内到期的才来打扰你 |
| 8 | 按 H 里的说明把日期改成录制当天的明天，解析并保存 | 倒计时「剩 18 小时」、待办只收三天内到期的 | 快到期的会自己冒出来 |
| 9 | 切「日历」，切上个月下个月，点某一天 | 月视图、选一天看当天事项 | 按日期落进格子 |
| 10 | 顶栏「搜索通知」输关键字，点分类下拉 | 关键字搜索、分类筛选 | 通知多了能找能筛 |
| 11 | 点「整理成文字」 | 整理成一段可直接发班群的文字、复制 | 给同学看的版本不用贴原文 |
| 12 | 按 **F5** 刷新 | 刷新后通知与状态都还在 | 数据存浏览器本地，不传服务器 |
| 13 | 依次粘 **B C D E F G**，每条只看解析结果；粘 **C** 时留空解析一次，再填上发布日期重新解析一次 | 中文数字时间、待确认与具体日期的对比、无地点留空、行政单位名、行动日、最短通知 | 各种写法都照顾到了，拿不准的宁可留空，给了基准才换算 |
| 14 | 切「多通知」模式，粘 **I**，点「解析」 | 切分确认「识别到 3 条通知」、去掉、解析这 3 条 | 班群一次转发好几条就整段粘 |
| 15 | 粘 **J1** 解析并保存 | 原通知 | 先有一条原通知 |
| 16 | 粘 **J2** 点解析 | 补充通知识别、关联原通知弹窗 | 收到补充通知，先问它改的是哪条 |
| 17 | 弹窗里点含「校园心理情景剧大赛」「个事项」的选项，点「下一步」 | 手选原通知与事项 | 认错了可以自己挑 |
| 18 | 对比弹窗看「变化前 / 变化后 / 依据原句」，点「保持原样」看效果，再「确认更新」 | 前后对比、依据原句、保持原样、确认更新 | 改了什么一眼看清，还能逐项决定 |
| 19 | 切「变更记录」，点开修改历史 | 变更记录、修改历史、查看当时的补充通知原文 | 每次改动都留痕 |
| 20 | 粘 **L** 解析 | 0 事项、不硬造 | 纯通报就不给你造一条假待办 |
| 21 | 收尾点一句：全程没配密钥 | 降级路径，来源标签标明结果由本地规则给出 | 不用申请密钥，评委也能复现 |

**不用每条都保存**。第 13 步那几条只解析看结果即可，存太多容易触发「与已有通知重复」弹窗，反而打断录制。

## 三、六个别踩的坑（都会现场翻车）

1. **别把「提前」写回素材**。变更词表把「提前」当改期词（本意是「时间提前至…」），素材里凡是「提前半小时到场」都会被判成补充通知，**列表非空时会误弹关联窗**。上面 B、F、J1 已换成「准时到场」「届时参加」，照抄即可，别自己加回去。
2. **补充通知必须先有原通知**。页面判定条件是 `isPatch && 已有通知数 > 0`，列表空的时候粘 J2 不会弹关联窗，会走普通解析。所以第 15 步一定在第 16 步之前，且 J1 要真的保存成功。
3. **发布日期留空时**，所有相对日期都显示「待确认」，不会换算成具体日期，会进「待确认事项」区，没有倒计时提醒。2026-11-04 起可以在新增通知弹窗里填「通知发布日期」，填了就换算成具体日期，这与密钥无关。C 用来拍这个对比，H 想拍倒计时仍要用明确日期。别再讲成「只有接模型才会换算」，那是旧口径。
4. **演示前一定清空列表**，不然左列一堆旧数据，老师看不清重点，还可能触发查重弹窗。
5. **别用带身份证号、学号、真实姓名的通知**，界面不脱敏。
6. **别临时改密钥、别改代码**，改了要重启服务，容易当场翻车。

## 五、这份材料的取证方式（区分模块实测与界面实测）

- **12 条通知逐条跑生产模块** `extractNotice` / `buildItems` / `buildNoticePatch`，确认字段、事项数、补充通知识别结果。D、E、F、G、L 只有这一层实测，文档里写的结果来自模块输出，**没有替它们做浏览器界面实测**。

- **2026-11-04 追加实测**：发布日期留空与填 2026-11-03 两组浏览器对照、保存刷新后详情仍显示具体日期、明确日期通知填基准不受影响、多通知三条共用同一基准，以及 1280×720 与 1920×1080 两张截图。详见 `docs/self-check-2026-11-04.md`。
