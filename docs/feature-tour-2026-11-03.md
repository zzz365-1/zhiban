# 全功能导览（给老师看的版本）交付说明

生成日期 2026-11-03 晚。这一份和 `docs/demo-video-script.md` 不是同一个东西：

| | 本份 | 比赛演示视频脚本 |
| --- | --- | --- |
| 给谁看 | 老师，快速了解产品有哪些功能 | 评委，看开发过程与 AI 协同 |
| 重点 | 界面功能全覆盖 | 真实提示词、真实对话、真实失败与返修 |
| 形式 | 已产出的可播放文件 | 拍摄脚本，尚未录成片 |
| 时长 | 69.7 秒 | 计划 7 分 30 秒 |

本份**不是真人出镜录屏，也没有口播**，是真实界面截图逐屏播放加字幕的自动导览。
比赛清单里要求的「不少于 2 分钟人与 AI 协同画面」不在这个文件里，那一项目前仍未完成。

## 三、已覆盖的功能分组

**入口与导航**：欢迎页、进入工作台、体验示例、四个视图（工作台、我的通知、日历、变更记录）、
需要关注三项统计、返回欢迎页。

**通知录入**：新增通知、单条模式、多通知模式、空行分隔、切分确认、
去掉认错的分块、返回修改、开始解析、保存到我的通知。

**解析结果**：事项拆分、办理截止与活动开始、时间地点材料对象分类、来源标签
（本地识别、规则兜底）、原文与解析结果双栏、点字段跳回原文、系统建议与通知要求的区分。

**事项操作**：标记完成、撤销完成、无需办理、材料勾选已准备、
事项手动编辑入口、结束时间待补充提示。

**查找与输出**：关键字搜索、分类下拉筛选（教务、活动、行政、后勤、其他、示例）、
整理成文字与复制到剪贴板、载入示例通知。

**日历**：月视图、切换月份、回到本月、选一天看当天事项、空态说明。

**补充通知**：识别为补充通知、手选原通知与事项、变更前后对比、
依据原句、保持原样、确认更新、成功提示、提醒重算、变更记录、修改历史、
查看当时的补充通知原文。

**异常与持久化**：本地存储写入失败的红色提示条与再试一次、
模型不可用与网络异常的失败原因区分、回退本地规则结果、重新解析入口、
刷新后通知与状态保留。

## 四、没有单独出镜的功能（如实列出，不编造画面）

- 重复通知检测弹窗（标题相同、正文相同、标题相同正文不同三种情况）
- 多通知「无法可靠分割」的分支画面
- 事项手动编辑弹窗的完整操作过程
- 时间冲突、截止事项集中、结束时间待补充这三类提醒的独立画面
- 日历 ICS 导出：**界面入口已移除**，只保留命令行 `npm run validate:ics`
- 模型路径的真实调用（需要使用者自己的密钥，本导览全程无密钥）
- 第五轮冲突提醒：按安排跳过验收，代码保留但本轮没有实测

这些功能在代码和文档里都有，本导览没有替它们摆拍或补造画面。
片尾那一屏已把这一点念明。

## 五、制作与验证方法（可复现）

1. `node tmp/tour-shots.mjs`：一次浏览器会话按使用顺序拍 17 张，逐屏自检。
   其中 6 张因脚本状态未复位没达到目标，**已删除，没有混进导览**。
2. `node tmp/tour-shots2.mjs`：基于第三轮已验证成功的补充通知流程补拍 7 张，
   8 个场景自检全部达到目标。刷新会清空浏览器 JS 全局环境，重注入辅助函数后复核通过。
3. `node tmp/build-tour.mjs`：把 21 张达标截图内嵌成单文件 HTML，加片头片尾共 23 屏。
4. `node tmp/export-tour-video.mjs`：浏览器 `canvas.captureStream` 加 `MediaRecorder`
   导出 webm，不依赖 ffmpeg。能力探测通过，录制返回 2.30 MB。
5. `node tmp/verify-tour-video.mjs`：重新打开视频，读元数据并跳到第 30 秒截帧。
   实测 `duration 69.66 秒`、`1280×720`、`readyState 4`，
   验证帧里顶部标题、页码、界面截图、功能标题与说明文字完整清晰，无重叠截断。

`tmp/` 下的脚本不进仓库，是本机验收工具。导览的截图、HTML、视频与本文档进仓库。

## 六、给老师看时的两句说明

第一，全程**不配密钥、不联网**也能跑完整条流程，来源标签写「本地识别」，
这是刻意设计的降级路径。画面里的通知都是示例或测试语料，没有真实姓名、手机号、学号。

第二，这不是最终参赛视频。参赛视频要求 5 到 8 分钟且含不少于 2 分钟的人与 AI 协同画面，
脚本在 `docs/demo-video-script.md`，成片目前仍未录制。
