# 新对话开场白（每次开新对话，先粘这段给 AI）

> 背景：2026-11-02 发生一次严重事故。给新对话的 AI 发了一个"历史对话分享链接"让它自己熟悉，
> 它从链接里挑了**项目第一天**的需求（不接 AI、只用本地规则），然后给了"完整实现"，
> 用户照着粘贴后，`app/page.js` 从 321 行被砍到 58 行，004 到 021 的全部功能一次性消失。
> 根因是 AI 不知道项目已经演进到哪一步，把"重做"当成了"继续"。
> 本文件就是防止这件事再次发生。

---

## 使用方式

开新对话后，**第一件事**把下面整段粘给 AI，然后再粘当轮的具体需求。
不要只发分享链接让它自己猜进度。

## 开场白原文（整段复制）

我在做一个校园通知助手的网页项目，用 Next.js 写的，放在 D 盘 zhiban 这个目录里。
用户粘贴一条校园通知进来，程序自动把截止日期、时间、地点、材料、面向对象这些字段抽出来，
做紧急度分级，还能导出日历文件和复制待办文字。

这个项目已经做到很后面了，不是刚开始。到现在为止已经完成了这些：
本地规则抽取引擎、日历文件导出、数据持久化和紧急度分级、接入大模型做语义抽取、
抽取准确性多轮收敛、日历与待办视图、手动修正字段、复制摘要、批量粘贴多条、
面向对象与材料抽取、统一粘贴入口、空态引导、相对日期本地换算、数量型相对日期、
分类值域校验与失败原因上屏、反幻觉出处核对。

有六条规矩请你一定遵守，这些是之前踩过坑才定下来的。

第一，不要重写已经存在的文件，也不要给出从零开始的完整实现。
我需要的是在现有代码上做局部改动。如果你觉得必须大改，先告诉我原因，别直接动手。
之前有一次你给了我一份完整实现，我把 page.js 整个替换掉，结果项目里已经做完的十几个功能
一下子全没了，从三百二十一行变成五十八行，我花了很大力气才恢复回来。

第二，不要删掉任何现有功能。哪怕你觉得某个功能写得不好，也不要擅自去掉，先跟我说。

第三，这个项目没有配置路径别名。写代码的时候不要用 @ 开头那种路径，
一律用相对路径，比如 ./lib/某某.js 这种写法。之前就是因为用了 @ 开头的路径，
程序直接报找不到模块，网页打不开。

第四，抽取通知字段的那个模块叫 extractNotice.js，放在 app 目录下 lib 目录里，
不要另外新建一个名字差不多的模块。之前新建过一个叫 extract.js 的，
结果两份代码判断逻辑不一样，反而更乱，后来删掉了。

第五，改动不要分散。回复我的时候不要把这个文件整个重新输出一遍，
只要告诉我改动落在哪几行，把改之前和改之后的那几行分别写出来，我自己去替换。

第六，写正则的时候一律用字符类，不要出现反斜杠加数字那种写法。
另外测试代码要直接引用真正的模块，不要自己另外抄一份相似的来判断。

再说明一下，我是新开的一个对话，之前聊过什么你这边看不到了，
所以你只能根据我这次发给你的信息来判断，不要假设你还记得之前说过什么。
如果我给的信息不够，你直接问我，我去补。

## 为什么这样写

| 这条防什么 | 对应事故 |
|---|---|
| 强调项目已做到很后面 | AI 误判成第一天的需求，从零重做 |
| 明确禁止完整实现 | page.js 321 行 → 58 行 |
| 明确禁止删功能 | 十余个组件被解除引用 |
| 明确没有路径别名 | `@/lib/extract` 导致 Module not found |
| 明确抽取模块真名 | 新建 extract.js 与 extractNotice.js 不同源 |
| 只输出改动片段 | 输出过长撑爆对话、且易误改别处 |

## 配套动作（本机侧）

用户把 AI 返回的改动粘回来之后，**先不要急着应用**，让本机侧先做：

1. `git status -sb` —— 看改了几个文件，是否出现了预期外的新文件
2. `git diff --numstat` —— 看删了多少行。**删行数异常大就是回退信号**
3. 确认无误再应用，应用后跑全量回归

判据：单次改动如果**删除行数超过新增行数两倍以上**，基本可判定为回退，先问再动。
