## 三、决策记录

### Dec-001 选题定为「知办 — 校园通知行动助手」
**理由**：对比 10 个候选方向后判断，本选题纯 Web 实现、无硬件依赖、无需私有数据，在"过程可复现性"这一最高权重项上最容易拿满分；同时通知解析任务天然适合展示结构化意图控制，可兼顾"方法创新性"。方向 1（多 Agent 看板）、方向 7/9（具身智能仿真）均存在复现失败风险显著更高的问题。

### Dec-002 产品定位为"从知到办的闭环"，明确拒绝"又一个 AI 摘要"
**理由**：评分表中明文写着"拒绝毫无实用价值的玩具项目"。"粘贴通知→AI 总结"没有任何说服力。差异点必须落在通知落地为行动的那一步。

### Dec-003 数据源策略：做"汇聚中枢"而非"爬虫"
**理由**：校园通知散落于教务系统、学院官网、QQ 群、公众号，绝大多数需登录态 Cookie，且普遍有反爬。若核心流程依赖真实抓取，评委复现时登录不上创作者账号，演示直接崩塌。改为：以粘贴文本 / 截图 OCR / 邮件 / ICS / CSV / 标准 JSON 为主输入，学校抓取降级为可插拔 Adapter 插件，仓库附脱敏种子数据。

### Dec-004 技术栈：Next.js 16.3 App Router + TypeScript + Tailwind + shadcn/ui + Zustand + SQLite(Prisma)
**理由**：前后端一体的单仓库形态，评委 `npm i && npm run dev` 一条命令即可启动，端口固定，把复现失败概率压到最低。SQLite 以单文件形式随仓库运行，零外部依赖。

**2026-10-30 修正（重要）**：初版方案写的是 Next.js 14，经核实已严重过时。当前事实为
- Next.js 最新稳定版 **16.3.0**（2026-08-03 发布），App Router；Turbopack 为默认打包器
- **Next.js 15 官方支持已于 2026 年 10 月终止**，14 更早已停止维护
- 若沿用 14 参赛，在技术文档与答辩环节会被直接判定为过时方案，属于可被一眼看穿的硬伤
- Node.js 当前 LTS 为 **v26.13.0**，满足 Next.js 16 的运行要求

调整后技术栈：**Next.js 16.3 + App Router + TypeScript + Tailwind + shadcn/ui + Zustand + SQLite(Prisma)**。

**已规避的严重事故**：用户执行 `git add .` 时，316 MB 的录屏视频被一并暂存。已通过 `git rm --cached -r deliverables/recordings` 移出索引，并将 `deliverables/recordings/` 追加写入 `.gitignore`。若当时未拦截，仓库体积将超 300 MB，**直接摧毁"评委 clone 后十分钟复现"这一 25% 权重项**。

**更深一层的坑（本次技术要点）**：`git rm --cached` 之后，`.git` 目录实际仍达 **295 MB**——因为 Git 的对象存储是引用可达性驱动的，`rm --cached` 只摘掉索引指针，那个 316 MB 的 blob 仍以悬空对象形式躺在 `.git/objects` 里。最终靠以下命令真正回收：

```bash
git reflog expire --expire=now --all
git gc --prune=now
```

执行后 `.git` 降至 **114 KB**。验证 `git rev-list --objects --all` 无任何大于 10 MB 的 blob，仓库彻底干净。

**教训沉淀**：`git rm --cached` 能让文件"不进下一次提交"，但**不会自动回收已被 add 过的大对象**。凡涉及误 add 大文件，必须在 commit 后补一次 gc，否则隐性膨胀会被带到后续所有克隆里。

**Git 身份配置**：首次 commit 因未配置 user.name / user.email 被 Git 拒绝（`fatal: unable to auto-detect email address`），属预期内的一次性配置动作。

## 六之二、003 规则引擎：转义缺陷的两轮拉锯

**交付**：`prompts/003-rule-engine.md` → DeepSeek 产出 `app/lib/extractNotice.js`（8.5 KB），并在 `AnalysisPanel.js` 落了五字段栏位（截止日期 / 具体时间 / 地点 / 需提交材料 / 面向对象）。

**Prompt 设计意图**（写入 003 归档文件）：
- 「你觉得我想得对吗」→ 让提问者主动提出架构主张（确定性任务用规则、模糊语义留待模型），体现减法的意图控制；
- 「抽不到就留空，不要瞎编」→ 划出产品红线，AI 完整执行（`value.length === 0 ? "未识别"` 已落地）；
- 「最后帮我准备五条测试通知」→ 为技术文档取得可量化准确率数据的起点。

**缺陷一（首版）**：AI 把正则写成四个反斜杠 `\\\\d`。JS 中此写法表示「匹配两个字面反斜杠加 d」，导致日期 / 时间 / 地点三组规则全部静默失效，仅 `materials` 字段因采用「字符串数组 + `new RegExp`」构造而幸存。
→ 诊断方法：独立 Node 复现 + 对照组实验（四反斜杠 false / 单反斜杠 true，抓到 `2026年11月15日`）。
→ **「偏偏一个字段好使」是本次最关键的排查线索**，两组写法差异直接指向转义层。

**缺陷二（首轮修正失败）**：追问后 AI 由四个反斜杠改为两个（ `\\d` ），**仍不正确**。首版准确率 1/5，修正后仍为 1/5。
→ 教训：**LLM 在转义层具有系统性的过度转义倾向，且一次修正不保证到位。** 后续凡涉正则生成，须在 Prompt 层主动指定书写形式，并要求其自附验证脚本。

**缺陷三（已本地定位，暂未反馈）**：`extractAudience` 中 `全体[\u4e00-\u9fa5]{1,8}?(?:同学)` 量词下限为 1，导致「全体同学」（中间零汉字）无法匹配。留待评测体会一并反馈，避免单轮 Prompt 目标分散。

**本地预验证结论（重要）**：将全文件双反斜杠替换为单反斜杠后，五条测试通知的日期 / 时间 / 地点抽取**全部正确**，输出如 `2026年11月15日 / 17:00 / 学生资助管理中心A301办公室`。
→ 证明修复路径唯一且确定，第三轮追问具备一击收敛的条件。

**003b 追问策略**（`prompts/003b-escape-fix.md`）：给出双反斜杠这一具体线索但保留不确定语气；引用「materials 字段从没出错」这一**它自身代码中的证据**，推导改用 `new RegExp` 写法以一次性绕开转义陷阱；同时索要命令行验证脚本。
→ 最后一项是本轮最有价值的增量：把「改一次→刷浏览器→看结果」收敛为「改一次→跑脚本→秒看结果」，并天然沉淀为后续量化准确率的评测工具。

**缺陷四（二次修正再次失败，同根）**：追问后 AI 采纳了「改用字符串数组 + `new RegExp`」的建议，架构层确实换了容器，但**把原先给正则字面量准备的四反斜杠原封不动搬进字符串，未重新审视转义层级**。全文件共 **77 处四反斜杠**。

- 字符串中 `"\\\\d"` → JS 解析成 `\\d` → 正则收到「匹配字面反斜杠 + d」→ 错
- 应写 `"\\d"` → 解析成 `\d` → 正则收到「匹配数字」→ 对

**方法论沉淀（Dec-013）**：LLM 在转义层存在**系统性过度转义倾向**，且该错误具有**跨容器移植性**——更换写法时它搬运了旧的转义习惯而未重新校准。因此凡涉正则、`\n`、`\t` 等元字符的生成任务，必须在 Prompt 层主动指定书写形式，并要求其自附可运行验证脚本，不可以为之──改一次就对。

**好消息：它提供的 `scripts/test-extract.mjs` 极有价值。** 该文件把「改一次 → 刷浏览器 → 看结果」收敛为「改一次 → 跑脚本 → 秒看结果」，并支持命令行传任意文本。此脚本后续将升级为抽取准确率的评测载体，是 20% 方法创新性得分点的关键产出。

**本地预验证（四换二后，五样例全通）**：

| 样例 | deadline | time | location | audience |
|---|---|---|---|---|
| 1 标准型 | 2026年11月15日 | 17:00 | 学生资助管理中心A301办公室 | 各学院 |
| 2 斜杠日期 | 11/20 | — | 体育馆一楼大厅 | — |
| 3 相对时间 | 本周五 | — | 各班级教室 | 全体学生 |
| 4 连写日期时间 | 2026-12-10 | 17:00 | 行政楼205室 | — |
| 5 模糊日期 | 10月底 | — | 图书馆三楼会议室 | — |

日期 5/5、地点 5/5；时间与对象为空的样例属原文确无该信息，返回 null 为正确行为。

**003c 收敛策略**（`prompts/003c-escape-final.md`）：给出四换二的精确推算并请其确认；**提出用字符类 `[0-9]` 替代 `\d`、字符类替代 `\s`，使整个文件彻底不含反斜杠，从根源消灭此类缺陷**；并顺带反馈测试脚本同源缺陷（`console.log` 中 `\\n` 导致输出字面 `\n` 而非换行）。

最后一项反馈具有独立价值：该现象只有真正运行过脚本才可能观察到，是人机协同真实性的强力佐证。

**数据留档**：规则引擎首版准确率 1/5（20%）。三轮修正后本地预验证已达 **5/5（100%）**。此曲线为技术文档「方法创新性」章节核心硬证据。

**003c 收敛成功（21:39）**：AI 采纳字符类方案，改用 `[0-9]` / `[ ]` / `[一-龥]` 替代 `\d` / `\s` / `\u4e00-\u9fa5`。`node scripts/test-extract.mjs` 五条样例**全部通过**，145 分钟的三轮拉锯至此收敛。
