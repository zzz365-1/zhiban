## 三、决策记录

### Dec-001 选题定为「知办 — 校园通知行动助手」
**理由**：对比 10 个候选方向后判断，本选题纯 Web 实现、无硬件依赖、无需私有数据，在"过程可复现性"这一最高权重项上最容易拿满分；同时通知解析任务天然适合展示结构化意图控制，可兼顾"方法创新性"。方向 1（多 Agent 看板）、方向 7/9（具身智能仿真）均存在复现失败风险显著更高的问题。

### Dec-002 产品定位为"从知到办的闭环"，明确拒绝"又一个 AI 摘要"
**理由**：评分表中明文写着"拒绝毫无实用价值的玩具项目"。"粘贴通知→AI 总结"没有任何说服力。差异点必须落在通知落地为行动的那一步。

### Dec-003 数据源策略：做"汇聚中枢"而非"爬虫"
**理由**：校园通知散落于教务系统、学院官网、QQ 群、公众号，绝大多数需登录态 Cookie，且普遍有反爬。若核心流程依赖真实抓取，评委复现时登录不上创作者账号，演示直接崩塌。改为：以粘贴文本 / 截图 OCR / 邮件 / ICS / CSV / 标准 JSON 为主输入，学校抓取降级为可插拔 Adapter 插件，仓库附脱敏种子数据。

### Dec-004 技术栈：Next.js 16.3 App Router + TypeScript + Tailwind + shadcn/ui + Zustand + SQLite(Prisma)
**理由**：前后端一体的单仓库形态，评委 `npm i && npm run dev` 一条命令即可启动，端口固定，把复现失败概率压到最低。SQLite 以单文件形式随仓库运行，零外部依赖。

**2026-10-30 修正（重要）**：初版方案写的是 Next.js 14，经核实已严重过时。当前事实为
- Next.js 最新稳定版 **16.3.0**（2026-08-03 发布），App Router；Turbopack 为默认打包器
- **Next.js 15 官方支持已于 2026 年 10 月终止**，14 更早已停止维护
- 若沿用 14 参赛，在技术文档与答辩环节会被直接判定为过时方案，属于可被一眼看穿的硬伤
- Node.js 当前 LTS 为 **v26.13.0**，满足 Next.js 16 的运行要求

调整后技术栈：**Next.js 16.3 + App Router + TypeScript + Tailwind + shadcn/ui + Zustand + SQLite(Prisma)**。
待落定：TypeScript 7（原生端口）尚属新产物，为稳妥起见建议暂用 TypeScript 5.x 稳定版，交由 DeepSeek 生成时确认兼容后再决定是否升级。

**已规避的严重事故**：用户执行 `git add .` 时，316 MB 的录屏视频被一并暂存。已通过 `git rm --cached -r deliverables/recordings` 移出索引，并将 `deliverables/recordings/` 追加写入 `.gitignore`。若当时未拦截，仓库体积将超 300 MB，**直接摧毁"评委 clone 后十分钟复现"这一 25% 权重项**。

**更深一层的坑（本次技术要点）**：`git rm --cached` 之后，`.git` 目录实际仍达 **295 MB**——因为 Git 的对象存储是引用可达性驱动的，`rm --cached` 只摘掉索引指针，那个 316 MB 的 blob 仍以悬空对象形式躺在 `.git/objects` 里。最终靠以下命令真正回收：

```bash
git reflog expire --expire=now --all
git gc --prune=now
```

执行后 `.git` 降至 **114 KB**。验证 `git rev-list --objects --all` 无任何大于 10 MB 的 blob，仓库彻底干净。

**教训沉淀**：`git rm --cached` 能让文件"不进下一次提交"，但**不会自动回收已被 add 过的大对象**。凡涉及误 add 大文件，必须在 commit 后补一次 gc，否则隐性膨胀会被带到后续所有克隆里。

**Git 身份配置**：首次 commit 因未配置 user.name / user.email 被 Git 拒绝（`fatal: unable to auto-detect email address`），属预期内的一次性配置动作。
