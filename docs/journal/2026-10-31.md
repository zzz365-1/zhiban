## 二、今日主线：004 —— ICS 日历导出

### 为什么是这一步

003 解决了「看清通知」，但**看清不等于执行**。同学看完截止日期，仍需手动打开日历添加，这一步的流失率恰恰是「通知被遗忘」的真正成因。

004 把结构化字段转换成**可被手机日历直接消费的实体行动**，这是区分「又一个 AI 摘要」和「真正有用的工具」的分界线，直接对应评分表中 25% 的「解题有效性与实用价值」。

选 ICS 而非自研提醒系统：零后端、零账号、零成本，双击即入系统日历，演示效果直观，评委一定能复现。

### ICS 格式的三个硬约束（架构师掌握）

1. **换行必须是 CRLF**，仅用 `\n` 会导致部分日历客户端解析错乱或静默失败。此为最经典坑，AI 极易写错。
2. **单行不得超过 75 字节**，超长需按 RFC 5545 折行。
3. **时区须显式声明**，否则会出现「导入后偏移 8 小时」。

本轮让 AI 自行解决这三点，但**强制要求其提供不依赖手机导入的本地校验手段**。

### 交付物

`prompts/004-ics-export.md` —— 含产品定位说明、技术要点、Prompt 正文、五个设计点、验收标准。

### Prompt 的五个设计点

1. **开门见山给产品动机**：不是「我要加个按钮」，而是描述真实流失场景。这是 25% 解题有效性的核心论述。
2. **时区要求**：真实痛点，AI 极易忽略。
3. **空值时按钮行为**：主动考虑边界状态，体现产品设计意识，实现方式交还 AI。
4. **主动预警格式陷阱**：「我听说换行有讲究，昨天那个反斜杠折腾了三轮，我有点怕再来一次」——把昨日教训转化为今日风险预判。**这条整条 Prompt 最值钱**，证明提问者在积累方法论。
5. **索要本地校验手段**：流程从「跑起来看浏览器」升级为「命令先验」。

### 发现缺陷：escapeICSText 过度转义

本机抽出原函数实测：

```
输入 : 材料：申请表,复印件
输出 : 材料：申请表\\,复印件      ← 两个反斜杠，RFC 5545 只需一个
```

这是转义类缺陷在本项目的**第四次出现**（前三次为 `extractNotice.js` 的正则反斜杠）。
同一模型在同一类问题上连续四次失手，本身即是技术文档中「AI 可靠性观察」最扎实的一条素材。

反向印证：换行符改用**字符码构造**后躲过了该缺陷，说明「用字符类/字符码替代反斜杠元字符」
是能系统性消灭此类问题的有效对策。此经验已写入 `prompts/004b-ics-escape-fix.md` 并对 AI 明确要求。

### 同时标记的合规缺口

RFC 5545 规定单行不超过 75 字节，中文一字占 3 字节，通知标题稍长即超限。
当前生成器未做折行，校验脚本也未检查行宽。两项均已在 004b Prompt 中要求补齐。

### 缺陷 A（阻断级）

| 输入 | 原版 | 字符类修正版 |

| 2026年11月15日 | null | Nov 15 2026 17:00 |
| 11月15日 | null | Nov 15 2026 17:00 |
| 2026-11-15 | null | Nov 15 2026 17:00 |
| 2026/11/15 | null | Nov 15 2026 17:00 |
| 11/20 | null | Nov 20 2026 |
| 2026-12-10 | null | Dec 10 2026 17:00 |

### 缺陷 B（中）

`escapeICSText` 输出双倍转义，实测「申请表,复印件」导出为逗号前两个反斜杠，标准为单个。
验证可行方案：`String.fromCharCode(92)` 拼出反斜杠，彻底不用反斜杠字面量。

### 缺陷 C（中，已实测量化）

RFC 5545 单行上限 75 octets。以真实标题「关于开展2026年秋季学期国家助学金申请材料报送工作的通知」
计算，SUMMARY 行达 **87 字节**，已超限。中文一字 3 字节，标题超过约 22 字即必然越界。
生成端未折行，校验端亦未检查行宽。
