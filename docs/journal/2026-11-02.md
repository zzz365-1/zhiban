## 七、019g 完成与验收（2026-11-02 晚，新对话重做）

### 交付与改动

新对话的 AI 先要了 `relativeDate.js` 全文才动手，没有直接给完整实现，
说明开场白里的防回退约束生效。改动三处，全部落在 `app/lib/relativeDate.js`：

1. 函数开头 `const s` 改 `let s`，加截止后缀预处理：结尾的之前、以前、先摘掉；
   若摘掉后还以时段词（凌晨到晚上）结尾，再摘掉时段词
2. 新增 `isQuantityRelativePhrase`，摘后缀后若是纯数量型短语则直接返回 null
3. 在过 X 天段之后补半个月、半年、一季度三档解析

规模 `+54 / -1`，是新增不是删除，符合预期，无回退迹象。

### 验收结果

- AI 自带的测试脚本（30 条，含两个故意写错的用例）全绿
- 现有 `test:relative` 140 条回归
- 全量 13 条离线命令 exit=0
- 端到端：`下周三之前` → 抽取下周三 → 换算 2026年11月11日；
  `本周五中午前` → 2026年11月6日；`三天前` → 保持 null 交模型

### 验收中发现的两个问题

**一、现有一条用例的期望值过时，不是代码 bug。**

回归时出现 `[122/140] FAIL 「半个月后」= null`。
反查 `scripts/test-relative-dates.mjs` 第 223 行，该用例写在 019 收官时，
当时半个月后未本地化，`expected: null` 是在**记录已知边界**。
现在功能实现，边界消失，期望值自然对不上。
基准日 `NOW_SUNDAY = 2026-11-01`，加 15 天应为 2026年11月16日，语义核实无误。
已改为正向断言并加注释说明改动理由，不是把期望值改成实际值了事。
这是 Dec-039 的又一次生效：失败用例必须核输入、描述、期望三样。

**二、`isQuantityRelativePhrase` 当前是行为等价的冗余防御。**

注入让它永远返回 false 之后，**所有测试依然全绿**。
原因是摘掉后缀后剩下的三天本来就无法解析（返回 null），
提前 return null 与否结果完全相同。
它防的是未来若出现能解析裸数量短语的规则，但**当前没有任何用例能证明它起作用**。

对照 Dec-024，这条安全网不满足"能证明会响"的标准。
结论是保留但**如实记录其冗余性质**，不把它当成已验证的防护写进任何对外材料。
同轮另外两处注入（后缀识别失效、时段词摘除失效）均正确报错，
证明那两处逻辑确实被测试真实覆盖。
