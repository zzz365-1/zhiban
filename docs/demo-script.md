# 给老师演示的流程（约 10 分钟）

素材在 `docs/demo-notices.md`，直接从那里复制粘贴。
下面写的每个结果都是本机跑过的真实结果，不是预期值。

## 零、演示前的三分钟准备

1. 起服务 `npm run dev`，浏览器打开 http://localhost:3000
2. 把界面清空。左侧列表里每条右上角有个删除按钮，把旧的都点掉。
   或者直接在浏览器控制台执行 `localStorage.clear()` 再刷新，更省事。
   **这一步不能省**：列表里存的是解析当时的结果快照，代码后来加了字段，
   老数据不会自己补上。不清空就会看到一条没有活动日期的旧通知。
3. 清空后点空状态里的"载入示例通知"，第一条示例现在会带活动日期；
   或者直接从 `docs/demo-notices.md` 复制素材粘贴解析。
4. **别在演示现场改密钥**。要证明无密钥也能跑，用 `npm run coverage` 那条命令，
   零网络零密钥，跑完直接给出覆盖率数字。

## 一、开场半分钟：说清问题

> 校园通知的毛病是，要你几点前交什么、在哪儿交，全埋在一段话里。
> 我们做的事就是把它拆出来，变成能直接进日历的一条待办。

## 二、第一条：助学金（核心卖点，两个日期）

粘贴素材一，点解析。

界面会给出：

| 字段 | 值 |
|---|---|
| 截止日期 | 11月5日 |
| 具体时间 | 17:00 |
| 活动日期 | 11月8日 |
| 活动时间 | 19:00 |
| 地点 | 学生工作处A302办公室 |
| 需提交材料 | 申请表 |
| 面向对象 | 各班 |
| 分类 | 行政 |
| 来源 | 本地识别 |

要说的三句话：

> 这条通知里有两个日期，一个是你要赶的截止日，一个是评审会举办日。
> 以前这类通知只有一个日期字段，举办日要么被当成截止日抢走，要么干脆没人管。
> 现在两个分开，各带各的时间，左边来源写着本地识别，说明这条没花钱调模型。

## 三、第二条：歌手大赛（再看一次双日期）

粘贴素材二。截止 11月10日 17:00，初赛 11月15日 18:30，地点团委办公室。

> 晚6点半这种说法也能认，给出的是 18:30。

## 四、第三条：下周三（相对日期本地换算）

粘贴素材三。截止 **2026年11月11日** 16:00，地点本班自习教室。

> 原文写的是下周三，程序自己按今天的日期算成了十一月十一日。
> 这一步是本地算的，不调模型，所以不花钱也不联网。

## 五、第四条：这条没有地点（宁缺勿滥）

粘贴素材四。地点那一栏是空的。

> 这条通知压根没写地点，程序给空是对的。
> 我们的原则是宁可留空让人手动补，也不编一个像答案的假地点。

## 六、第五条：手动修正（点一下就能改）

粘贴素材五。地点给出学生宿舍。

演示改字段：鼠标移到地点那一行，右边出现铅笔图标，点一下，
把内容改成「各寝室」，回车。来源标签会变成"手动修正"。

> 抽取不可能百分百，所以每个字段都能改，改完标记成手动修正，
> 以后一眼能看出这个值是谁给的。

## 七、第六条：行政单位名（地点补全）

粘贴素材六。地点给出 **教务处教材科A105**，材料给出汇总表和缴费凭证。

> 教务处教材科这种单位名以前切不准，只剩教务处，人跑过去还得再问科室在哪。
> 现在整串保留，还带上 A105。

## 八、第七条：只有活动没有截止

粘贴素材七。截止日期显示 11月14日，活动那两行不出现。

> 这条没有要赶的截止，只有一个讲座的举办日。
> 程序把它当成行动日填进截止，这样它才会进待办和日历，不会漏掉。

## 九、第八条：最短的一条

粘贴素材八。截止 11月9日，对象全体团员，还有一句摘要。

> 摘要和分类是模型给的，来源标签会变成 AI 辅助。

## 十、第九条：保存后看待办

粘贴素材九（明天下午 5 点截止），点保存。

切到顶栏"待办"。这条会自己出现，标着"剩 1 天"，红色。

> 待办只放三天内到期的，按时间排，超过三天的不来打扰你。

## 十一、多通知批量

切到"多通知"模式，把素材十整段粘进去，点**解析**。

会先弹出一个确认框：识别到 3 条，每条显示标题和开头一句，
认错的可以点"去掉"。点"解析这 3 条"。

解析结果出现在**右下那块面板**里（和单条通知同一个位置），
一条一块，能上下滑动。按钮变成"保存 3 条到我的通知"。

> 班群里一次转发好几条通知的时候用这个，不用一条一条贴。
> 提示类的东西都做成弹窗，不占输入框的地方，所以输入框是撑满的。

**顺带演示一次切不出来的情况**：把两条通知中间的换行删掉，让它们连成一段，
再点解析。会弹窗提示"没认出这是多条通知"，并说明要用空行或标题分隔，
还能选择"当作一条通知解析"。以前这种情况是闷声不响的。

## 十二、日历和分享

切"日历"，能看到保存过的通知按日期落在格子里。
右上角"分享"点开，是整理好的一段文字，可以直接复制到班群。

> 分享这段是给同学看的，只挑最近要截止的，附上时间和地点。

## 十三、无密钥也能跑（收尾）

在终端跑：

```bash
npm run coverage
```

零网络零密钥，跑完给出降级路径下的覆盖率，还会列出哪几条没抽到、
人工判的是什么。

> 没配密钥的时候，模型换成本地规则，全流程照样跑通，
> 来源标签会显示本地识别。评委不用申请密钥就能复现。

## 老师可能追问的四件事

**为什么不用更大的模型或者做微调。**
我们的思路是用最小的模型能力解决最大的语义难题，其余交给确定性代码。
日期地点这类能算的都本地算，模型只补本地搞不定的那部分，
所以单次解析成本大概四分钱，还快。

**模型会不会编。**
每个模型返回的值都要回原文核对出处，找不到的直接丢掉，
界面上不会显示一个原文里没有的值。

**现在还做不到什么。**
改期语义（原定某日推迟到某日）、区间日期（某日至某日）、
没覆盖的相对说法（半个月后），这三种本地抽不准，
一部分靠模型补，剩下的要手动改。这个我们写在技术文档里，不藏着。

**数据存哪。**
存在浏览器本地，没有后端，不传任何服务器。

## 演示时别做的事

- 别临时改 `.env.local`，改了要重启服务，容易当场翻车。
- 别用真实通知里带身份证号或学号的内容，界面不脱敏。
- 演示前一定清空列表，不然左列一堆旧数据，老师看不清重点。
