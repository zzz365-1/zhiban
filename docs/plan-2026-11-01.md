## 一、三块抽取能力的真实状态（不笼统说"完善"）

| 能力 | 当前性质 | 失效模式 | 结论 |
|---|---|---|---|
| 相对日期换算（已覆盖说法） | 018 后是**确定性代码** | 不会算错，只会认不出 | 可以放心用 |
| 相对日期换算（未覆盖说法） | 又落回**模型算术** | 概率性算错 | **要补，优先级最高** |
| 时间含义区分（选哪个日期） | 完全靠模型语义 | 没有专门测试 | 缺验证，是最大盲区 |
| 材料提取 | 规则与模型混合 | 开放式，遇新说法就漏 | 不敢打包票 |

### 1.1 相对日期：018 已让它发生性质变化

`app/lib/relativeDate.js`，132 行纯函数，零网络零密钥。已覆盖：今天/明天/后天/大后天、下周X/本周X/这周X、本月底末初/下月底末初、本月X日/下月X日。43 条用例、十连绿、移走密钥仍全绿、跨月跨年闰年与月末溢出都验过。

**性质变化的意义**：以前是"模型算术"有概率错，现在是"代码算术"，覆盖范围内错了必是代码 bug。

**但有一个未收口的边界**：数量型说法没覆盖。当前 `今天/明天/后天/大后天` 是四个枚举，`(下|本|这)?(周|星期)X` 要求整串精确匹配。所以「三天后」「两周内」「下周三之前」「本周五中午前」本地算不出来，安全返回 null 后**回落给模型又重新开始做算术**——018 之前的风险在这类说法上原样保留。

这是最讽刺的一点：018 的原则是"模型不承担算术"，但在数量型说法上它还在算。

### 1.2 时间含义区分：能用，但没验证过边界

靠 `parsePrompt.js` 的四级优先级让模型做语义选择题。已验证：多日期取截止那个、活动类回退取活动日期、初稿与答辩并存取前者。

**没建过用例的**：时间区间（11月5日至10日开放借阅）、周期时间（每周三下午例会）、隐性截止（逾期不再受理但无明写日期）。

### 1.2.2 日期展示形态：同一个日期会因原文写法不同而不一致（2026-11-01 实测发现）

**统一解析函数早已存在，缺的不是解析能力，是没接到主链路。**

`app/lib/deadline.js` 的 `parseUserDateInput` 已支持 2026.11.20 / 2026/11/20 / 2026-11-20 /
2026年11月20日 / 11月20日，并归一成一种写法，非法值返回 null，本机已逐条验过。

但它**只被手工修改那条路用到**（结果面板与相应的自检脚本），主抽取链路没走它。后果实测可复现：

| 原文写法 | 界面拿到的值 |
|---|---|
| 请于2026.11.20前把体检表交到校医院三楼 | 2026.11.20 |
| 请于2026/11/20前把体检表交到校医院三楼 | 2026/11/20 |
| 请于2026年11月20日前把体检表交到校医院三楼 | 2026年11月20日 |

三条语义完全一样，界面却显示成三种样子。相对说法那一路因为有本地换算，统一成了第三种。

**这不是抽取错，是展示口径没收口。** 补的时候关键是接在主链路上，而不是再造一个新函数，
否则两边标准会各走各的，这正是上一轮不同组件各自维护一份规则栽过的跟头。
排 021 之后处理，因为它动的是主链路，须排在盲测之前。

### 1.3 材料提取：三者里最不敢打包票的

013e 用穷举变体封住七种触发词说法，自测 24/0。但它是**开放集合**，中文说"要带什么"的方式是无限的。013 连修五轮，每轮都以为收工了结果下轮冒出新变体（Dec-034）。

**更根本的问题：我们所有测试的期望值都是自己写的。** Dec-031 已经证明过一次这件事有多危险——013c 的用例 8 把「身份证复印件」的期望写成「身份证,身份证,复印件」，同一件东西拆成两截写了两遍，而我们当时把它当正确标准用。

"全绿"只证明我们想到的情况通过了，不证明完善。

## 二、界面布局：改上下结构（方案二）

### 2.1 问题根因是一个，不是两个

当前 `260px | 1fr | 280px`。1920 宽屏下中间约 1380px 只放一个输入框，下面大片空白；右栏 280px 要塞八个字段，其中 materials 是数组、summary 是一整句话。

**中间空白与右栏拥挤是同一个原因：宽度分配失衡。** 右栏不够不是内容多，是给得太少。

### 2.2 方案二的形态

上半部：输入区（保持现有能力，宽度合理收缩）
下半部：结果区，**两列栅格排布字段**，材料一格独占一列或横向铺开

### 2.3 一个必须警惕的陷阱

**不能把 280px 那根竖条原样搬到下面。** 如果下方结果区还是单列堆叠，宽度的收益等于没兑现，只是把拥挤从右边挪到了下面。要做就做彻底。

### 2.4 一个超出预期的收益

项目的核心卖点是"抽取结果可信、可核对"。上下结构让**原文在上、结果在下同屏对照**，这条对照关系比左右结构宽得多，演示时一个画面就能讲完故事。

### 2.5 已知冲突

**015 的空态会和上下结构打架。** 空态现在占满中间 `flex-1`，结果区在下方时，有空态就没位置了。约定解法：空态只占上半部分，或直接折叠结果区。这条要写进 Prompt，否则 DeepSeek 大概率会漏。

## 三、老师的技术表述建议：五条全部采纳

| 条 | 建议 | 性质 | 证据现状 |
|---|---|---|---|
| 1 | temperature 0 不能说"保证可复现" | 改表述 + 补实测 | 今天已有铁证 |
| 2 | json_object 需补值域校验 | **需改代码**（小） | category 值域确实没校验 |
| 3 | 反幻觉不能只靠提示词，要能测 | 补测试 | 缺专门用例 |
| 4 | 失败必须用户可感知并留痕 | **需改代码**（小） | 已查实是真缺陷 |
| 5 | 要能指出依据哪一句 | 补功能（016） | 待做 |

### 3.1 第 4 条指向一个真实缺陷（已查实）

`parseOne` 的 catch 确实返回了 `{analysis, error}`，但 `page.js` 的 `handleParse` 写成：

```js
const result = await parseOne(text);
setAnalysis(result.analysis);   // error 被丢弃了
```

**error 字段从头到尾没被用过**。后果三层：
1. 超时、网络错误、Key 缺失、JSON 非法、返回空内容——五种失败界面上长得一模一样
2. 实际是超时，界面却写「模型未接入，已退回本地」，因为 `rule_fallback` 一个状态兜了所有失败
3. 提示是 11px 小标签，容易被忽略

合起来就是：**解析实际失败了，用户以为成功了**，然后拿着本地规则抽出的残缺结果去办事。

这是 Dec-020 的另一半——我们一直说"AI 产出必须有界面出口"，但**错误状态也是一种产出，它也必须有出口**，否则等于没发生。

### 3.2 第 1 条我们有铁证

今天的事：提示词里明写了「不要把星期日当作新一周的开始」，模型照样违反，约 1/20 概率算错。这发生在 temperature=0 **之下**——API 的确定性和理论上的贪心解码不是一回事。

改成"低随机性配置 + 记录参数 + 测试稳定性"之后反而更强：**018 那个十连绿就是稳定性实测**。从"嘴上承诺一致"变成"我们跑了十次，结果一致"，这是质变。

### 3.3 第 2 条是真实缺口

`response_format: json_object` 只保证语法合法，不保证 schema 正确（要 schema 保证得上 `json_schema` + strict）。我们现在做了类型规范化但没做值域校验。最明显的是 `category`：提示词限定五个取值，**代码压根没检查**，模型返回"体育比赛"也会原样展示。

补的时候记着 Dec-024：**加校验的同时必须加"注入非法 category 必须拒绝"的用例。**

### 3.4 总体判断

这五条采纳了对我们是**加分不是减分**。

原来那版写法像在吹牛：确定性、防幻觉、永不失败。改完之后变成：我们压低了随机性并记录参数、我们注入测试用例验证它会不会瞎编、失败可感知且留痕。

**前者是声称，后者是证据。** 这是 Dec-024 从代码层延伸到表述层：不承诺做不到的事，只对验证过的部分负责。

## 四、盲测：必须做，且现在做

### 4.1 做法

找 20 条真实通知（学校教务网、辅导员群、学院公众号，**不要用我们自编的**），先人工标一遍答案，再跑程序对比。

**顺序不能反**：先看程序输出就会被它带着走。这是 Dec-031 的直接应用。

### 4.2 为什么现在做

- 全是"自己出题自己考"，天然有偏差
- 评委最可能做的就是**当场粘贴一条我们没见过的通知**
- 现在还有时间修，等到录演示视频那天发现就来不及了
- 盲测结果本身就是答辩素材：能讲"我们用 20 条真实通知盲测，准确率多少、哪几类还在出错"，比讲"我们写了 43 条测试全过了"有分量得多

### 4.3 排期约束

**必须排在抽取逻辑改动全部完成之后**，否则测了又改、改了又测，白做。
