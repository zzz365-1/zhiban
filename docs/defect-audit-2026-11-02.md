## 一、两条 P0（静默错误，必须修）

### P0-1 落款剔除误杀正常日期（024 引入的回归）

**这是本次最严重的发现，而且是我们自己上一轮修出来的。**

实测（全部走生产模块）：

| 输入 | 实际 deadline | 应该 |
|---|---|---|
| 11月5日前交 | 空 | 11月5日 |
| 12月31日前交 | 空 | 12月31日 |
| 截止日期为12月31日 | 空 | 12月31日 |
| 截止时间为11月20日 | 空 | 11月20日 |
| 11月20日截止 | 空 | 11月20日 |
| 材料报送截止到11月20日 | 空 | 11月20日 |
| 请于12月31日前将表交到教务处 | 空 | 12月31日 |
| 请于11月30日前将表交到教务处 | 空 | 11月30日 |

对照能抽出来的：

| 输入 | 实际 |
|---|---|
| 请于11月5日前交 | 11月5日 |
| 请于11月5日前将材料交至行政楼A301 | 11月5日 |
| 请于12月31日前将材料交至行政楼A301 | 12月31日 |

**根因**（`extractNotice.js` 第 139 到 176 行的 `isSignatureDate`）：
它把"日期所在行除了日期只剩单位名或者空"当作落款特征，而代码里
`beforeOnLine === ""` 与 `afterOnLine === ""` 两种情况都被直接算作"像落款"。
于是三种正常写法被误杀：

1. **日期在行首**（前面没字）：`11月5日前交`
2. **日期在行尾**（后面没字）：`截止日期为12月31日`、`11月20日截止`
3. **日期后面那段以单位名收尾**（处、部、办公室、学院…）：`请于12月31日前将表交到教务处`
   —— 注意同一句换成"交至行政楼A301"就能抽出来，因为 A301 不在单位名特征里

**为什么盲测没抓到**：024 之后盲测 20 条里 13 条走了模型兜底，模型把日期补回来了。
本地错了但被模型盖住，界面上看不出来。**无密钥时没有模型兜底，这些日期直接是空的**——
而"无密钥也能完整体验"正是 README 的第一卖点，也是 25% 复现分的支点。

### P0-2 周期时间被换算成一个具体日期

| 输入 | 实际 | 应该 |
|---|---|---|
| 每周三下午三点在行政楼会议室召开例会 | 2026年11月4日 | 空（这是周期，不是某一天） |

流程是：本地抽到"周三" → `resolveRelativeDate` 换算成 11 月 4 日 → 界面显示一个确定日期。
用户看到的是"11月4日截止"，而原文说的是每周三。**每周、下午三点全部丢失，且不报错。**

同类未建模：每两周、每逢单周、每月第一个周一。

## 二、P1（错但影响可控，或一致性问题）

### P1-1 时间区间只取一端，且取哪一端不一致

| 输入 | 实际 | 说明 |
|---|---|---|
| 图书馆将于11月5日至10日闭馆整理 | 11月5日 | 取了起点 |
| 12月1日至2027年1月10日接受报名 | 2027年1月10日 | 取了终点 |

同一个语义（区间），两次取了不同的一端。**区间本身没有建模**，现在是碰运气。

### P1-2 相对日期本地抽不出来，018/019 的投资在主链路没兑现

实测 `extractNotice` 对这些说法全部返回空：
三天后、两周之内、下周三之前、半个月后、半年后、一季度后、大后天、本月底前、12月31日前交（见 P0-1）

`relativeDate.js` 那 220 条用例测的是"**如果**拿到这个短语能不能换算"，
但主链路里这些短语根本没被抽成 deadline。设计上依赖模型先把相对说法原样返回，
本地再换算——所以 018 的"模型不做算术"只在我们接了密钥时成立。

**无密钥用户遇到"三天后截止"，日期字段是空的。**

### P1-3 批量拆分不认编号分隔

| 输入 | 拆出条数 | 应该 |
|---|---|---|
| 空行分隔的两条 | 2 | 2 |
| `1. … 2. …` 编号分隔 | 1 | 2 |
| 无分隔 | 1 | 1 |

群里转发的通知常带编号或"通知一/通知二"，这条路径目前拆不开。

## 七、这次审计本身的两条结论

1. **P0-1 是 024 自己引入的。** 我们加防线时只验了"落款不再被抽"，没验"正常日期没被误杀"。
   Dec-034 说过收敛要**穷举变体 + 防误杀双向验**，这一轮只做了单向。
2. **盲测的 85% 到 95% 是被模型兜底撑住的。** 一旦评委无密钥运行，
   本地规则的真实水平就是这次审计的结果，而不是盲测那个数字。
   这件事必须写进技术文档，不能含糊。
