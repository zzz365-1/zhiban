# 2026-11-04 发布日期入口 自检记录

## 需求

界面上加一个可选的「通知发布日期」输入。原文里出现「下周三」「明天」这类相对说法时，
填上发布日期就能换算成具体日期。留空时保持原来的「待确认」行为，不许按今天偷偷换算。

## 起因

11-04 同学拿截图问，截止日期那一格显示「下周三」，橙色提示写着
「日期待确认，请补充发布日期以便换算」，但界面上根本没有能填发布日期的地方。

本机取证：密钥是配好的，`check:key` 当次真实调通了模型，`/api/parse` 返回 200。
问题不在模型，在页面解析时 `parseOne(text)` 与 `buildItems(text)` 都没传 `publishedAt`，
换算函数拿不到基准。对照实测同一条通知，只差一个参数，
无基准是「下周三 / pending」，有基准是「2026年11月11日 / ok」。

## 验收案例与预期（开发前定死，不参考程序输出）

| 编号 | 输入与操作 | 预期结果 |
|---|---|---|

| R2 | 同一条通知，发布日期填 2026年11月3日 | 截止日期显示 2026年11月11日，事项日期同值，状态正常，不再有待确认 |

| R5 | 多通知模式粘三条，其中一条含「下周三」，填了发布日期 | 三条都用同一个基准，含相对说法那条换算成具体日期，另两条不变，不串台 |

- 图书馆新系统已于11月1日上线运行，欢迎使用。
- 关于2026年寒假放假安排的通知，放假时间为1月20日至2月25日。

## 硬约束

第一，留空时不许拿今天日期去算，这是刻意设计，不能因为加了入口就顺手改掉。
第二，明确日期的通知填不填都一样。
第三，只影响相对日期换算这一件事，抽取、事项、补充通知、日历、去重都不许动。
第四，代码由对话式 AI 产出，本机实跑验证后再落地。

## 防线实证

新增 `npm run test:round5`，46 条断言，含动态断言、页面接线静态断言与两条金丝雀。
八处接线逐处注入坏实现，全部精确报红。

| 注入项 | 报红条数 |
|---|---|
| A 单条解析丢基准 | 2 |
| B 单条事项丢基准 | 1 |
| C 多通知逐条丢基准 | 2 |
| D 单条保存不存发布日期 | 1 |
| E 状态默认成今天 | 1 |
| F 弹窗日期框被改成文本框 | 1 |
| G 迁移补事项丢基准 | 3 |
| H 模型换算提示开关被撤销 | 1 |

注入后与干净副本逐字节比对一致。

第一次注入时 D 一次命中 6 处，把别处的基准也一起改坏了，不算精确报红。
把断言收紧成两条保存语句的精确计数、注入锚点改成单条保存那一处之后，
D 变成命中 1 处报红 1 条，才真正证明那条断言承重。

## 顺带修掉的一处误导文案

1280 留空截图里，截止日期明明显示「下周三」，下面却还挂着
「原文为相对日期，这里是模型按今天日期换算的结果，仅供参考」。
值根本没换算，这句会让看的人以为程序偷偷按今天算过。
收紧开关后留空只剩「日期待确认，请补充发布日期以便换算」一句，
重拍截图与浏览器断言都确认误导文案消失。

## AI 迭代记录（真实往返，五条链）

075 加发布日期入口，AI 把基准当成位置参数直接传字符串，本机核对签名是对象参数，那样功能完全不生效。
076 讲清签名后改成对象参数，字段名统一 publishedAt，并撤回它顺手加在多通知分支的范围外补事项代码。
077 收紧误导提示开关，方向对但猜了一个库里不存在的函数名，导入路径也指错。
078 喂了真实导出名之后，把条件写反成判真才亮，留空时错误提示照样亮。
079 把方向改回取反判断显示值，但导入路径又写回另一个文件。

同一处反复修不好，按本机已核验的事实取用。
导入语句用 078 给过的那条，补进已有的同一文件导入。
开关条件用 079 给的那条。两段代码都出自 AI 输出，本机只做核对与落位。
五条链每一轮都抓到一个具体错误，没有编造往返。
